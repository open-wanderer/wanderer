## Verdict

broken. The `gaps_found` status is driven entirely by *verification coverage*, not by defects:
one phase was never verified at all, and another's verification explicitly asks to be re-run
against a change that landed after it.

integration bugs were found by manual use *after* Phase 32's verification passed

here at least once already.

## Cross-Phase Integration

**8/8 seams wired. 0 orphaned. 0 missing.**

The highest-risk seam was Phase 32 → Phase 31: Phase 32 removed `bbox` from the `regions`
collection, and the Flutter parser drops entries missing it. Verified safe with direct evidence:

- `RegionRepository.refreshCatalogAndFetchHierarchy` (`app/lib/provider/region/region_provider.dart:162-165`)
  is the **only** call site touching `/regions` anywhere in `app/lib`, and it always passes
  `enabled=true`. Disabled leaves never reach the client, so the bbox-omission path is unreachable.
- `parseRegionCatalog` wraps each element's `fromJson` in try/catch and skips per-element
  (lines 42-47) — a malformed entry is dropped, not a crash.
- `trail_coverage_util.dart` operates on persisted `RegionEntity` snapshots, all of which carry a
  real bbox because only enabled, resolved leaves are ever fetched.

Also confirmed: no stale `region_polygons` references anywhere; `path` is used consistently as the
natural join key across `regions`, `region_archives`, and `region_geometry`, enforced by a
model-level hook that covers internal writes as well as API traffic.

## E2E Flow

Admin enables a region → geometry cached → archive built → API reports it → app lists it →
download succeeds. **Traced through all six links; no break found.**

## Recommendation

Neither gap is a defect, and both are cheap to close relative to the risk they carry:

1. **Phase 31 on-device pass** — the phase asked for it, the server contract underneath it
   changed, and static tracing (however good) is what already missed three bugs in this
   milestone. Highest value per unit of effort.
2. **Phase 29 retroactive verification** — `/gsd-validate-phase 29` or a written VERIFICATION.md.
   The wiring is correct today; what's missing is anything that would catch it breaking. The
   `region_id` → `path` rename already broke this exact area once, silently.

Proceeding to close is defensible — nothing is broken — provided both are recorded as known gaps
rather than quietly dropped.
