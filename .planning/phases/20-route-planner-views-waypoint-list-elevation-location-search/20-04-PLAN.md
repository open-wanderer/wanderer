    Each row (`ValueKey(anchor.id)`): a single-line `ListTile` (default 56px height, 16px horizontal padding) with leading = a 24px circular badge (accent-primary fill `Color(0xff242734)` light / `Color(0xff3E435B)` dark, white 12px/600 number = `index + 1`, D-02 renumber-by-index), title = `'Anchor ${index + 1}'`, subtitle = `'${anchor.lat.toStringAsFixed(5)}, ${anchor.lon.toStringAsFixed(5)}'` in `Colors.grey[600]`, and trailing = an `IconButton(FontAwesomeIcons.trash, size: 14, color: Colors.red.shade400, visualDensity: VisualDensity.compact)` whose `onPressed` calls `ref.read(routeAnchorsProvider(travelProfile).notifier).deleteAnchor(anchor.id)` — immediate, no confirmation dialog, no snackbar-undo (D-06). The delete button is never disabled (D-07 — deleting to zero is valid; the parent screen un-mounts the sheet at 0 anchors).

    `_onReorder(oldIndex, newIndex)`: apply the canonical `if (newIndex > oldIndex) newIndex -= 1` shift, mutate a copy of `_orderedIds` (removeAt/insert), `setState(() { _orderedIds = reordered; })`, then call `ref.read(routeAnchorsProvider(travelProfile).notifier).reorderAnchors(_orderedIds)`, then `setState(() => _reordering = false)`. Because `reorderAnchors` is a synchronous in-memory mutation (no network, cannot throw), no revert-on-error/error-toast path is required — the guard exists only to prevent a mid-drag reseed; do not fabricate an async failure branch.

    No empty-tab state is needed: the sheet (and this tab) is only mounted when `anchors.isNotEmpty` (D-03, enforced by the parent screen in Plan 05).
