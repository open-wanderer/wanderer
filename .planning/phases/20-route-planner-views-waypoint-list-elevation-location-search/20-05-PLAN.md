<objective>
Assemble Phase 20's user-facing surface: the tabbed `DraggableScrollableSheet`
(PLANUI-01, D-02/D-03) hosting the Route Anchors tab (Plan 04) and the Elevation
tab (Plan 03), and the Route Planner screen integration — a magnifying-glass
search control (D-04) that opens the location search (Plan 02) and pans the map
to the result at zoom 13 (D-14/D-15), plus restructuring the screen body to host
the sheet conditionally on `anchors.isNotEmpty` (D-03).

This is Wave 3 — it wires together the components built in Waves 1-2. The
sheet/tab composition is the phase's hardest problem: the single sheet
`scrollController` must attach to only ONE tab to avoid the documented
`"ScrollController attached to multiple scroll views"` crash (RESEARCH.md
Pattern 1, flutter/flutter#55388).

Purpose: Make the list, elevation, and search capabilities reachable on the
planner screen.
Output: A new `RouteAnchorSheet`; `route_planner_screen.dart` gains the search
button, the sheet host, and the camera hand-off.
</objective>

  <action>
    Create `RouteAnchorSheet` as a `ConsumerStatefulWidget` with `required String travelProfile`. Hold an owned `final DraggableScrollableController _sheetController = DraggableScrollableController()` (dispose it in `dispose`).

    Build a `DraggableScrollableSheet(controller: _sheetController, initialChildSize: 0.14, minChildSize: 0.14, maxChildSize: 0.6, snap: true, snapSizes: const [0.14, 0.6], builder: (context, scrollController) {...})`. `minChildSize` equals the peek size — the sheet never fully dismisses (D-03: peek is the floor, not zero). Do NOT add a `NotificationListener` drag-to-dismiss/`onClose` path.

    Inside the builder, wrap the content in the `waypoint_sheet.dart` chrome container (rounded-top-16, `theme.canvasColor`, the exact boxShadow), then a `DefaultTabController(length: 2)` wrapping a `Column` with three parts:
    1. A handle-bar `Row` (drag grabber, no close button) wrapped in a `GestureDetector` whose `onVerticalDragUpdate` computes `(_sheetController.size - details.delta.dy / MediaQuery.sizeOf(context).height).clamp(0.14, 0.6)` and calls `_sheetController.jumpTo(target)` (guard on `_sheetController.isAttached`). This is the ONLY expand/collapse driver — expand/collapse is decoupled from the scrollController (Pattern 1).
    2. A `TabBar` with two tabs: `Tab(icon: FaIcon(FontAwesomeIcons.listOl), text: 'Route Anchors')` and `Tab(icon: FaIcon(FontAwesomeIcons.mountain), text: 'Elevation')`, accent-colored indicator/selected label.
    3. `Expanded(child: TabBarView(children: [RouteAnchorListTab(travelProfile: travelProfile, scrollController: scrollController), ElevationTab(travelProfile: travelProfile)]))`.

    CRITICAL (Pitfall 1): pass the builder's `scrollController` ONLY into `RouteAnchorListTab`. `ElevationTab` gets NO shared controller. Passing the same `scrollController` into both `TabBarView` children throws `"ScrollController attached to multiple scroll views"` at runtime because `TabBarView` keeps both children built simultaneously.

    Sizing fractions are Claude's Discretion starting points (tune against `WaypointSheet`'s 0.35/0.0/0.7 if peek/expand feel wrong on-device); the peek must show at least the handle bar + TabBar without clipping.
  </action>
