# Phase 20 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** This phase is Flutter mobile (`app/lib/`), not the SvelteKit web app. `shadcn` and the web `DESIGN.md`/"The Terrain Log" palette (Polar Night, flat-by-doctrine elevation) documented in `CLAUDE.md`'s Design Context are a **web-only** artifact set — no `DESIGN.md`/`PRODUCT.md` file exists in this repo for the Flutter app. This contract inherits directly from `19-UI-SPEC.md` (Phase 19, same screen — `route_planner_screen.dart`) and the Flutter app's own shipped design system (`app/lib/theme/`), extended with the reusable patterns this phase's decisions (20-CONTEXT.md) explicitly name: `waypoint_sheet.dart` (sheet chrome), `settings_categories_screen.dart` (reorderable list), `elevation_profile.dart` (chart), `global_search_screen.dart` (search-screen shell). Do not import web CSS tokens or shadcn primitives into this phase.

## Spacing Scale

Declared values (must be multiples of 4), inherited verbatim from `19-UI-SPEC.md` and extended with this phase's sheet/list/row tokens:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps; gap between anchor-list row's coordinate icon and text |
| sm | 8px | Padding around each top-right control-button pill; gap between the Search and Auto-routing pills in the `Column` (D-04) |
| md | 16px | Sheet content horizontal padding; app bar/search-field horizontal padding; anchor-list row horizontal padding |
| lg | 24px | Control-button pill corner radius (unchanged from Phase 19); sheet top corner radius (`BorderRadius.vertical(top: Radius.circular(16))` is `waypoint_sheet.dart`'s existing value — see exception below) |
| xl | 32px | Not used this phase's new elements (reserved — matches Phase 19's route-anchor map marker, unchanged) |
| 2xl | 48px | Tab bar height (Material default `TabBar` height); minimum touch target reference for app bar/search-field icon buttons |
| 3xl | 64px | Not used this phase |

Exceptions (reused, load-bearing existing constants — do not round):
- **16px sheet corner radius** — not a multiple of 8 relative to the lg=24 token, but the *exact, existing* `waypoint_sheet.dart` constant (`BorderRadius.vertical(top: Radius.circular(16))`). The new tabbed sheet reuses this radius verbatim for visual consistency with the app's one other `DraggableScrollableSheet`.
- **56px anchor-list row height** — Flutter's standard single-line `ListTile` height (not a spacing-scale multiple of 4 in the strict sense, but the platform-default row height already used by every list in the app, e.g. `_LocationTile`, `_TrailTile`). Do not force a custom row height.
- **14px delete-icon size** — matches the existing `FontAwesomeIcons.trash` convention in `waypoint_card.dart` (`size: 14`, `visualDensity: VisualDensity.compact`). Reused verbatim for the anchor-list row's delete button (D-05).
- **18px control-icon size** — the search pill icon matches the existing 18px `FaIcon` size used by the auto-routing toggle pill and app-bar undo/redo icons (Phase 19 precedent), for visual consistency across the top-right controls column.

## Sheet & Tab Contract (phase-specific — D-02/D-03)

Single `DraggableScrollableSheet` replacing the two-separate-views idea from the original PRD wording. Chrome reuses `waypoint_sheet.dart`'s container pattern (rounded top-16px corners, `theme.canvasColor`, `boxShadow: black 15% alpha / blur 10 / offset (0,-2)`) with two structural differences:

- **No full-dismiss.** `minChildSize` equals the peek `initialChildSize` (not `0.0` as in `WaypointSheet`) — the sheet always shows at least the handle bar + `TabBar`. There is no `onClose`/drag-to-dismiss callback.
- **Visibility gate (D-03):** the sheet widget is not built at all (not merely collapsed) when `state.anchors.isEmpty`. It mounts the first time an anchor is appended and stays mounted for the rest of the session, matching D-07's "delete freely to zero" — at zero anchors after a delete, the sheet un-mounts again rather than sitting empty.
- **Sizing (Claude's Discretion, default proposed):** `initialChildSize: 0.14` (peek — handle bar + 48px `TabBar`, roughly 90-110px on a typical phone), `minChildSize: 0.14` (same as peek, sheet cannot collapse further), `maxChildSize: 0.6` (leaves the map's top-right controls and app bar reachable when expanded), `snap: true`, `snapSizes: [0.14, 0.6]`. Starting point only — tune against `WaypointSheet`'s existing `0.35`/`0.0`/`0.7` values if peek/expand feel wrong on-device.
- **Structure:** `DefaultTabController(length: 2)` wraps a `Column` inside the sheet's `builder`: handle bar row (unchanged from `WaypointSheet`, minus the close `IconButton` — this sheet has no close action) → `TabBar` (two tabs, Label typography, Accent-colored indicator) → `Expanded(child: TabBarView(children: [_RouteAnchorListTab, _ElevationTab]))`. `TabBarView`'s children are NOT lazy-unmounted by default in Flutter — but D-11's "only fetch height while the Elevation tab is visible" still requires the Elevation tab to gate its own fetch on `TabController.index`/`animation` listening, not on the widget merely existing in the tree.
- **Tab icons:** "Route Anchors" tab uses `FontAwesomeIcons.listOl` (a numbered list, distinct from the auto-routing pill's `FontAwesomeIcons.route` to avoid icon reuse/ambiguity between two different controls). "Elevation" tab uses `FontAwesomeIcons.mountain` (matches the icon `elevation_profile.dart`'s own stat row already uses for elevation gain, for visual continuity).

## Route Anchor List Tab Contract (phase-specific — WAYP-04/05, D-05..D-08)

- **List widget:** `ReorderableListView.builder` inside the sheet's scrollable area, following `settings_categories_screen.dart`'s established pattern verbatim: a local `_orderedIds` working-copy list seeded from `state.anchors`, `_reordering` guard held through the full optimistic-reorder round trip, canonical `if (newIndex > oldIndex) newIndex -= 1` index-shift, revert-to-snapshot + error toast on failure. `buildDefaultDragHandles: true` (default) — no explicit drag-handle icon; long-press anywhere on the row starts the drag.
- **Row layout** (single-line `ListTile`, 56px default height, 16px horizontal padding):
  - **Leading:** a 24px circular badge — Accent-primary fill, white 1-based ascending number (Label typography, white), no border/shadow (smaller, flatter sibling of the 32px map marker; the map marker itself is unchanged by this phase).
  - **Title:** `Anchor {n}` (n = 1-based list position, always derived from index — same renumbering rule as the map marker, D-02 carried over from Phase 19).
  - **Subtitle:** `{lat.toStringAsFixed(5)}, {lon.toStringAsFixed(5)}` (Body 14px, `Colors.grey[600]`) — matches `waypoint_sheet.dart`'s coordinate-display convention exactly.
  - **Trailing:** a single `IconButton` (`FontAwesomeIcons.trash`, size 14, `Colors.red.shade400`, `visualDensity: VisualDensity.compact`) — tapping calls `deleteAnchor(id)` immediately, no confirmation dialog, no snackbar-undo action (D-06 — app-bar Undo is the sole safety net).
  - **Divider:** default `Divider` between rows (theme default), not a custom one.
- **No minimum-anchor guard (D-07):** the delete icon is never disabled; deleting down to zero anchors is valid and simply triggers the sheet's visibility gate (above) to un-mount it.
- **Empty-tab state:** cannot occur — the sheet (and therefore this tab) is only ever mounted when `anchors.isNotEmpty` (D-03). No empty-state widget is needed for this tab.

## Elevation Tab Contract (phase-specific — PLANUI-02, D-09..D-13)

- **Widget:** `ElevationProfile` (`app/lib/components/trail/elevation_profile.dart`), adapted per D-12 — its `trail` parameter becomes optional (`Trail?`). When `trail` is null: use `gpx.getTotals()` directly for the stats-header row (duration/distance/elevation-gain/elevation-loss icons, unchanged `_buildStatText` styling) and skip the `waypoints.map(...)` icon-overlay block in `_buildChart` entirely (no route-anchor markers on the chart, per D-12 — route anchors are not waypoints and must not appear as icon pins on the elevation curve).
- **Data source:** the derived `plannedGpxProvider` (D-10) supplies the `Gpx`; elevation (`ele`) values are populated only while this tab is the active `TabBarView` page (D-11) — gate the `/valhalla/height` fetch on `TabController` visibility, not on `plannedGpxProvider` alone re-emitting. Further route edits while the tab stays open re-debounce the height fetch at ~500ms (same debounce idiom as `global_search_provider.dart`'s query debounce).
- **Empty state (D-13, <2 anchors):** reuse `ElevationProfile`'s existing `_EmptyState` widget/pattern exactly (200px height, `colorScheme.secondaryContainer` background, 16px corner radius, centered `Icons.terrain` 48px + Body-14px caption) — but override its copy for this phase's context (see Copywriting Contract below). Do not call `/valhalla/height` at all with fewer than 2 anchors.
- **Chart height:** use `ElevationProfile`'s default `chartHeight: 150` unless the expanded sheet's available height requires trimming — do not hardcode a new value without checking against `maxChildSize: 0.6`'s available vertical space first.

## Location Search Screen Contract (phase-specific — PLANUI-03, D-14/D-15)

Mirrors `global_search_screen.dart`'s shell exactly, minus the category-chip row and every non-location result branch.

- **Navigation:** `context.push` (full-screen push, not a route replace) — mirrors `GlobalSearchScreen`'s own navigation pattern. On result selection: `context.pop(result)` back to `RoutePlannerScreen` (never `context.go('/map')` — the planner is a distinct, already-open route, D-14).
- **App bar:** identical `TextField`-as-title pattern — `autofocus: true`, `OutlineInputBorder(borderRadius: circular(56))`, `colorScheme.outline`/`colorScheme.onSurface` border states, Body 16px input text (see Typography exception above), trailing clear (`Icons.close`) button when non-empty. Hint text is location-specific (see Copywriting Contract) — do not reuse the existing `search_for_trails_places` l10n string verbatim, since this screen explicitly does not search trails/lists/accounts.
- **No category-chip row.** `_CategoryChips` and its `GlobalSearchCategory` selector are dropped entirely — this screen has exactly one implicit category (locations).
- **Results list:** reuses `_LocationTile`'s exact visual structure (40x40 orange-tinted rounded-8 leading container, `FontAwesomeIcons.locationDot` 18px orange icon, title + optional single-line description subtitle) verbatim — but its `onTap` changes from `context.go('/map', extra: {...})` to `context.pop(result)`, letting the caller (`RoutePlannerScreen`) own the camera animation.
- **Empty-query state:** centered `Icons.search` 64px (`Colors.grey.shade300`) + Body copy, same visual pattern as `GlobalSearchScreen`'s existing empty-query state, new copy (below).
- **No-results state:** reuse the existing SVG empty-state asset pattern (`assets/svgs/empty_state_search_{brightness}.svg`) + `No results for "{query}"` Body copy, unchanged from `GlobalSearchScreen`.
- **On the planner side:** `RoutePlannerScreen` awaits the pushed route's popped value; if non-null, calls `_mapController.animateCamera(center: Geographic(lat: result.lat, lon: result.lon), zoom: 13, nativeDuration: ...)` — zoom 13 fixed (D-15), never "keep current zoom." Use the existing `Duration(milliseconds: 1)`-for-instant / longer-for-animated convention already established in the codebase (16-03 checkpoint lesson) — an animated camera move here (not instant) is appropriate since this is a deliberate user-initiated jump, not a state restore.

## Map Control Button Contract (phase-specific — D-04)

- **Search button** joins the existing top-right `controls` `Column` (`route_planner_screen.dart`'s `Positioned` at `top: 128, right: 0`) **above** the auto-routing toggle (D-04: Search → Auto-routing, top to bottom). Identical pill styling to the existing auto-routing pill: `Padding(all: 8.0)` wrapping a `Container` (`theme.canvasColor` background, `BorderRadius.circular(24)`) containing an `IconButton` (`visualDensity: compact`).
- **Icon:** `FontAwesomeIcons.magnifyingGlass`, size 18, Accent-primary tint always (this is a stateless navigation action, not a toggle — unlike auto-routing's ON/OFF tint, the search icon never dims).
- **Tooltip:** `'Search location'`.
- **onPressed:** pushes the Location Search Screen (above) and awaits its popped result.
- This slot remains shared/extensible — do not assume Search + Auto-routing are the column's only two children if a future phase adds a third.
