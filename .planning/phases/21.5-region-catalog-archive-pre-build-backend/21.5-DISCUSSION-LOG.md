## Archive Build Mechanism

| Option | Description | Selected |
|--------|-------------|----------|
| Direct extract from region bbox | `pmtiles extract --bbox=<region bbox> --maxzoom=14` straight against Protomaps, one archive per region | ✓ |
| Extract per-cell then merge/join files | Reuse per-cell cache, then merge cell files — requires new merge logic that doesn't exist | |
| You decide | Let planning pick based on what pmtiles CLI supports | |

**User's choice:** Direct extract from region bbox
**Notes:** Simplest, no merge logic needed. Same reasoning applied to DEM (direct extract against `mapterhornSource`, maxzoom 12), for symmetry.

| Option | Description | Selected |
|--------|-------------|----------|
| Yes, separate directory | New `pb_data/region_archives/{region_id}/` dir, independent of per-cell cache | ✓ |
| Reuse pmtiles_cache directory | Store region archives inside existing cache dir with a naming convention | |

**User's choice:** Separate directory
**Notes:** Keeps region archives independently servable/cleanable without touching the per-cell cache used by existing map endpoints.

## Cron Cadence & Staleness Detection

| Option | Description | Selected |
|--------|-------------|----------|
| Daily | Matches Protomaps' own daily-dated source cadence | ✓ |
| Weekly | Lower load, but regions lag up to a week behind new builds | |
| You decide | Let planning pick a default cadence | |

**User's choice:** Daily
**Notes:** Configurable via its own env var following the `POCKETBASE_CRON_SYNC_SCHEDULE` pattern.

| Option | Description | Selected |
|--------|-------------|----------|
| Protomaps date-stamp changed since last build | Store YYYYMMDD from last build, compare each tick — cheap string comparison | ✓ |
| Content hash of extracted archive | Hash the extracted file, compare to last hash — requires re-extracting to compute | |

**User's choice:** Protomaps date-stamp changed since last build

| Option | Description | Selected |
|--------|-------------|----------|
| DEM rebuilds unconditionally alongside vector rebuild | Whenever vector rebuilds, DEM rebuilds too — simplest given Mapterhorn has no date signal | |
| DEM never auto-rebuilds after first build | DEM treated as effectively static; only rebuilt on config entry change | ✓ |

**User's choice:** DEM never auto-rebuilds after first build
**Notes:** Mapterhorn source has no date-stamped URL to compare against, unlike Protomaps.
