# Phase 21.5 Plan 02: Region Archive Builder — Vector + DEM Pre-Build Engine Summary

**`BuildAll(app)` cron entrypoint pre-builds one mosaicked vector PMTiles archive (Protomaps, z14) and one DEM archive (Mapterhorn, z12) per configured region, with atomic-rename availability, date-gated vector rebuilds, build-once DEM, and a region-id in-flight guard — a parallel, independent build path that never touches the existing per-cell `generator.go`.**

## Accomplishments

- `regions.ValidProtomapsDateAndURL()` exposes the bare `YYYYMMDD` Protomaps daily-build date alongside its URL — a self-contained duplicate of `generator.go`'s date-resolution logic (no import of the `tiles` package), closing RESEARCH.md's Pitfall 4 gap
- `needsVectorRebuild` / `bboxChanged` are pure, fully unit-tested comparison helpers backing D-10 (vector staleness) and D-11 (DEM build-once) respectively
- `regions.BuildAll(app)` loops the configured region catalog sequentially, pre-building a vector archive (temp path + `os.Rename` atomic promote, so an already-`ready` region stays fully servable through the entire rebuild window — D-08) and, best-effort, a DEM archive that never blocks or fails the vector result
- A region-id-keyed in-flight guard (mirroring `generator.go`'s cell-keyed guard) prevents two overlapping build passes for the same region from racing to write the same files
- A distinct `regionExtractTimeout` (default 30 minutes, overridable via `REGION_ARCHIVE_EXTRACT_TIMEOUT`) replaces the per-cell generator's 5-minute timeout, sized for region-scale (not 0.5° grid cell) extracts
