## Routing decision (recorded — read before implementing)

D-06 locks the literal path `GET /api/v1/regions` and cites "the existing `/api/v1/...` convention" plus `map_cells_id.go` as the structural pattern. RESEARCH.md Pitfall 3 flags a real conflict: `/api/v1/...` is the **SvelteKit** web-layer namespace, NOT the Go backend's — every custom Go route in `db/main.go` registers **unprefixed** (`/map/cells`, `/activitypub/actor`, …), and this phase explicitly excludes SvelteKit changes.

**Resolution (locked for this phase, no re-ask — this is a yolo-mode run):** Register the literal path `/api/v1/regions` **directly in the Go router** in `db/main.go`, matching D-06's exact string, with **no SvelteKit proxy**. PocketBase's `RouterGroup.GET` treats the path as a plain string, so this works with zero special handling. This is a deliberate deviation from every other unprefixed custom Go route — it is intentional and recorded here so it is not "fixed" later by mistake.

**Downstream note for Phase 22:** no SvelteKit proxy exists yet for this endpoint. The route is reachable by hitting the `db` container directly (e.g. `http://db:8090/api/v1/regions`). If Phase 22's Flutter/web clients require same-origin/CORS-safe access through the SvelteKit server, adding a proxy (mirroring `web/src/routes/api/v1/map/cells/[cellKey]/+server.ts`) is a Phase 22 task, not this phase's.
</assumptions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated client → GET /api/v1/regions | catalog listing + archive bytes must require a logged-in user (D-07) |
| client-supplied `{id}` URL path param → filesystem path | the download routes' `{id}` is fully untrusted (comes from the request URL), unlike the admin config id |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21.5-07 | Elevation of Privilege / Broken Access Control | GET /api/v1/regions + /{id}/download(-dem) | mitigate | `apis.RequireAuth()` bound at the route-group level in main.go rejects unauthenticated requests for the listing AND both file-download routes — the file bytes are protected identically to the listing (Security Domain: an auth-gated listing with public file bytes would defeat D-07); explicitly does NOT copy map_cells_id.go's unauthenticated download precedent |
| T-21.5-01 | Tampering | `{id}` path param → RegionArchivePath/RegionDemPath | mitigate | Download handlers call `regions.IsValidRegionID(id)` (the same allow-list regex) and reject with 400 before any `filepath.Join`; `e.FileFS(os.DirFS(RegionCacheDir), ...)` further confines serving to the region cache directory root |
| T-21.5-08 | Information Disclosure | `error_message` surfaced in catalog `error` field | accept | The error text is build-tooling output (e.g. "pmtiles extract failed: context deadline exceeded"); it is exposed only to authenticated users and reveals no secrets or user data — surfacing it lets the client show "unavailable" per D-08. Low risk, accepted. |
| T-21.5-SC | Tampering | package installs | accept | No npm/pip/cargo/Go packages installed this phase (all deps already vendored); no supply-chain surface added |
