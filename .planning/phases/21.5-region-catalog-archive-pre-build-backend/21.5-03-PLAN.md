## Routing decision (recorded — read before implementing; SUPERSEDES an earlier resolution)

D-06 locks the literal path `GET /api/v1/regions` and cites "the existing `/api/v1/...` convention" plus `map_cells_id.go` as the structural pattern. RESEARCH.md Pitfall 3 flags a real conflict: `/api/v1/...` is the **SvelteKit** web-layer namespace, NOT the Go backend's — every custom Go route in `db/main.go` registers **unprefixed** (`/map/cells`, `/activitypub/actor`, …).

**An earlier draft of this plan resolved this by registering `/api/v1/regions` directly on the Go router with NO SvelteKit proxy, reasoning that PocketBase's port is reachable and no proxy was strictly required. This was verified against the actual deployment configs and found incorrect — corrected below.**

**Verified fact (read `docker-compose.yml` vs `docker/docker-compose.prod.yml`/`docker/docker-compose.dev.yml` `db` service blocks to confirm before implementing):** only the top-level `docker-compose.yml` (simple/local-convenience compose) publishes the `db` service's port (`"8090:8090"`) to the host. `docker/docker-compose.prod.yml` and `docker/docker-compose.dev.yml` — the compose files actually used for real deployments — do **not** publish any port for `db`; it is reachable only from other containers on the `wanderer` docker network (e.g. `web`, via the internal hostname `db`). Additionally, `PUBLIC_POCKETBASE_URL` is set to `http://db:8090` in all three compose files — an internal-only docker DNS name that a browser outside the docker network cannot resolve, confirming the browser never talks to PocketBase/the Go backend directly in a real deployment; every client request goes through the `web` (SvelteKit) container, the only service with a publicly reachable port. This matches the existing pattern of `web/src/routes/api/v1/*/+server.ts` server routes proxying to backend services (e.g. `web/src/routes/api/v1/valhalla/route/+server.ts` proxying to Valhalla).

**Resolution (corrected):** Two layers, same public path:
1. Keep the Go route registered at the literal path `/api/v1/regions` in `db/main.go` per D-06's string (Task 2, unchanged) — this is now understood as an **internal-only** contract, reachable at `http://db:8090/api/v1/regions` from inside the docker network only.
2. Add a SvelteKit proxy at `web/src/routes/api/v1/regions/+server.ts` (+ `[id]/download/+server.ts`, `[id]/download-dem/+server.ts`) that forwards to that internal route using `event.locals.pb` (already populated with the request's authenticated PocketBase session by `hooks.server.ts`), so the SAME public path `/api/v1/regions` is what external clients (browser, Flutter app pointed at the instance's public origin) actually call — this is Task 4 below.

**Downstream note for Phase 22:** Phase 22's Flutter client should call `{instance_origin}/api/v1/regions` (the SvelteKit-proxied path on the app's own public origin) — NOT the Go backend directly. No further proxy work is needed from Phase 22 for this endpoint.
</assumptions>
