<objective>
Build the region-archive engine: a `BuildAll(app)` cron entrypoint that, per configured region, pre-builds one mosaicked vector PMTiles archive (Protomaps, z14) and one DEM archive (Mapterhorn, z12) ahead of any user request, persisting build state to the `region_archives` collection. This is a parallel, independent build path alongside the existing per-cell `generator.go` — it does not modify or merge with it (D-01/D-02).

Purpose: The three availability/staleness guarantees this phase adds on top of the per-cell precedent live here — (1) a `ready` region stays servable through a background rebuild via temp-file + atomic rename (D-08), (2) vector rebuilds are gated on a cheap Protomaps-date string comparison (D-10), (3) DEM builds once and only rebuilds on a config bbox change (D-11). Copying generator.go verbatim would violate all three; this plan adapts the pattern deliberately.

Output: `db/services/regions/staleness.go` (+ tests) and `db/services/regions/builder.go`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin config bbox → `pmtiles extract` subprocess argument | bbox floats are interpolated into a shell-exec argument via `exec.CommandContext` |
| cron scheduler → shared archive files | overlapping build passes could contend for the same region's output files |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21.5-02 | Tampering | bbox → `--bbox=` exec arg in buildVector/buildDem | mitigate | bbox is `[4]float64` formatted with `fmt.Sprintf("%f,%f,%f,%f", ...)` — never raw config text concatenated into the arg; Plan 01's ValidateRegion already range-checked the floats before they reach the builder |
| T-21.5-03 | Denial of Service | unbounded / hung `pmtiles extract` subprocesses | mitigate | Each extract is bounded by `context.WithTimeout(regionExtractTimeout)`; on timeout the subprocess is killed and the region marked `error` (never wedges the cron); a stuck subprocess cannot pin the region's in-flight entry indefinitely |
| T-21.5-04 | Denial of Service | many-region config spawning parallel extracts | mitigate | BuildAll iterates regions **sequentially** (subprocess concurrency bounded to 1) and the region-id in-flight guard prevents a slow prior pass overlapping the next scheduled tick for the same region (Pitfall 5) |
| T-21.5-06 | Availability (Info integrity) | in-place overwrite serving a truncated archive mid-rebuild | mitigate | Temp-path extract + `os.Rename` atomic promote (Pitfall 1); status/size/date fields update only after a successful rename, so a `ready` region always serves a complete file |
</threat_model>
