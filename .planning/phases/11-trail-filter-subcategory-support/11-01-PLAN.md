<objective>
Add a `subcategory` selection field to the `TrailFilter` freezed model and rewrite the category clause in `toFilterText()` so it emits a combined `(category_id IN [...] OR subcategory_id IN [...])` group using IDs — replacing the current name-based `category IN ['<name>']` clause that targets a Meilisearch attribute the redesigned index no longer makes filterable.

Purpose: This is the data foundation for the whole phase (FILTER-01, FILTER-03). Both UI surfaces (Plans 03, 04) read `TrailFilter.subcategory` and call `copyWith(subcategory: ...)`. It also fixes a latent bug: the existing `category IN ['<name>']` clause filters against a non-filterable attribute on the redesigned index (RESEARCH Pitfall 1), so category filtering is currently broken in Flutter.

Output: `TrailFilter` with a `subcategory` list, a corrected `toFilterText()`, a default-filter update, and a unit test asserting the emitted filter string for category-only, subcategory-only, and combined selections.
</objective>
