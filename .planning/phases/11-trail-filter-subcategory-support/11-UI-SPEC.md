# Phase 11 — UI Design Contract

> Visual and interaction contract for the Trail Filter Subcategory Support phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Platform:** Flutter (Material 3), not web. shadcn/Radix do not apply. This phase extends two existing filter surfaces — `TrailFilterScreen` and the quick filter bottom sheet — and the shared `WandererFilterChip`. The contract below records the *already-established* app design system (so the executor matches it exactly) plus the new visual elements this phase introduces (chip icons, subcategory badge overlay, the conditional "Subcategories" section).

## Design System

| Property | Value |

## Spacing Scale

The codebase already uses an 8-point scale via hardcoded `SizedBox`/`EdgeInsets`. This phase MUST reuse the exact values already present in the filter surfaces — do not invent new spacing.

| Token | Value | Usage (observed in repo) |
|-------|-------|--------------------------|
| xs | 4px | `Wrap.runSpacing` between chip rows (`wanderer_filter_chip.dart`) |
| sm | 8px | `Wrap.spacing` between chips; gap between a section label and its chips (`SizedBox(height: 8)`, `trail_filter_screen.dart`) |
| md | 12px | Bottom-sheet label→chips gap (`SizedBox(height: 12)`, `trail_quick_filter_bar.dart`) |
| md | 16px | Vertical gap between filter sections (`SizedBox(height: 16)`); bottom-sheet horizontal/top padding (`EdgeInsets.fromLTRB(16, 16, 16, 32)`) |
| lg | 24px | Filter screen body horizontal padding (`EdgeInsets.symmetric(horizontal: 24.0)`) |
| xl | 32px | Bottom-sheet bottom padding (the trailing `32` in `fromLTRB(16, 16, 16, 32)`) |

**Phase-specific spacing rules:**
- The new **Subcategories section** uses the SAME rhythm as the existing Category section: `Text(label)` → `SizedBox(height: 8)` → chips → `SizedBox(height: 16)` before the next section.
- Inside the bottom sheet, the Subcategories section uses `SizedBox(height: 12)` between label and chips (matches the existing sheet rhythm).

Exceptions:
- **Badge overlay offset (new, D-09):** badge `FaIcon` positioned `right: -2, bottom: -2` inside a `Stack(clipBehavior: Clip.none)`. The `-2` offsets are intentional sub-grid values required to seat the 10px badge against the 16px primary icon; they are decorative overlay coordinates, NOT layout spacing, so they are exempt from the 4px grid. Verify on-device for clipping (Pitfall 5).

## Typography

Driven entirely by the Material 3 `TextTheme` (IBMPlexSans). This phase introduces no new text styles — it reuses the styles already applied to the Category section so the Subcategory section is visually identical.

| Role | Style token | Weight | Usage in this phase |
|------|-------------|--------|---------------------|
| Section label | `TextTheme.of(context).labelLarge` | 500 (Material default medium) | "Categories" and the new "Subcategories" section headers in `TrailFilterScreen` |
| Sheet section title | `Theme.of(context).textTheme.titleMedium` | 500 | "Categories" / "Subcategories" headers inside the quick-filter bottom sheet |
| Chip label (unselected) | `FilterChip` label | `FontWeight.normal` (400) | Category/subcategory chip text when not selected (`wanderer_filter_chip.dart`) |
| Chip label (selected) | `FilterChip` label | `FontWeight.w600` (600) | Category/subcategory chip text when selected — the existing selected-state weight bump |

**Weights in play: exactly two** — regular (400) for unselected chips, semibold (600) for selected chips. Section labels inherit the theme's medium (500) and MUST NOT be overridden.

**Hard rule (FILTER-04):** Chip labels MUST use the locale-resolved display name, NOT the raw `name`:
- Category chips: `c.displayName(Localizations.localeOf(context))` (replaces current `labelBuilder: (c) => c.name`).
- Subcategory chips: `s.displayName(Localizations.localeOf(context))`.

## Color

This phase adds zero new colors. All chip, surface, and icon colors come from the existing `ColorScheme` in `app/lib/theme/colors.dart` (already mapped from the web's Tailwind variables). Both light and dark brightness are already handled by `AppTheme.createTheme(brightness)`.

| Role | Token (light / dark) | Usage |
|------|----------------------|-------|
| Dominant (60%) surface | `surface` — `#FFFFFF` / `#12141C` | Filter screen body + bottom-sheet background |
| Secondary (30%) | `surfaceContainerHighest` (chip background) / `secondary` `#E5E7EB` / `#2D3241` | Unselected chip fill, sheet structure |
| Accent (10%) | `primaryContainer` fill + `onPrimaryContainer` text/checkmark | SELECTED chip state only (background, checkmark, label) |
| Border | `outline` (unselected) / `outlineVariant` (selected) | Chip `StadiumBorder` side |
| Destructive | not used | No destructive actions in this phase |

**Accent reserved for:** the *selected* state of category and subcategory `FilterChip`s only — `selectedColor: colorScheme.primaryContainer`, `checkmarkColor: colorScheme.onPrimaryContainer`, and the selected label color. Nothing else in this phase consumes the accent. (This is the existing `WandererFilterChip` behavior; the executor MUST NOT change chip colors.)

**Chip icon (avatar) color:** the new `avatarBuilder` icons (`FaIcon`/`Icons.category`) render at their intrinsic glyph color and inherit `IconTheme` from the chip context. Do NOT hardcode an icon color — let the chip's foreground color drive it so selected/unselected contrast stays correct in both themes.

## Copywriting Contract

This phase is a filter refinement — there is no primary submit CTA and no destructive action. The copy surface area is: one new section label, the empty/hidden states, and the existing reset affordance.

| Element | Copy |
|---------|------|
| New section label (filter screen + sheet) | **"Subcategories"** — add l10n key `subcategories` to `app_en.arb` and all ~13 locale ARBs, then run l10n codegen. Reference via `l10n.subcategories`. (Pitfall 4 — no such key exists yet.) |
| Existing section label (reuse) | "Categories" — existing `l10n.categories` key, unchanged |
| Subcategories empty/hidden state | **Render nothing.** The entire Subcategories section is omitted (collapsed via `AnimatedSize` to `SizedBox.shrink()`) when no category is selected OR when no visible subcategory exists for the selected categories. No "no subcategories" placeholder text — silence is the correct empty state here (matches how the Category section behaves when categories haven't loaded). |
| Hidden categories/subcategories (FILTER-06/07) | Omitted silently from chip options — no "hidden" badge, no explanatory copy. A category/subcategory with `visible: false` simply does not appear as a chip. |
| Reset affordance (existing, reuse) | The `filterCircleXmark` IconButton in the app bar already resets the whole filter (`resetFilter()`). No new copy. Resetting also clears `subcategory` once the field is added to the default filter. |
| Error / load-failure state | No new error UI. `subcategoryProvider` is cache-first/synchronous (returns `List`, never throws to the widget); `categoryProvider` and the preference providers are `AsyncValue` consumed via `.value ?? []`, degrading to "no chips" on failure rather than showing an error. Do NOT add error banners for filter chips. |

**Destructive actions:** none in this phase. (Reset is non-destructive — it clears in-memory filter selections, not user data.)

**Copy tone:** single-word section label, sentence-case, matching the existing "Categories"/"Tags"/"Author" labels. No punctuation, no helper text.

## Interaction Contract (phase-specific UI behavior)

These are the load-bearing interaction rules the executor must implement. They derive from CONTEXT.md decisions D-03..D-14.

| Interaction | Contract |
|-------------|----------|
| Subcategories section reveal | Wrapped in `AnimatedSize(duration: 200ms, alignment: Alignment.topCenter)`. Visible only when `filter.category.isNotEmpty` AND at least one visible subcategory exists; otherwise `SizedBox.shrink()`. Smooth expand on category select, smooth collapse when all categories deselected. (D-03, D-04, D-12) |
| Subcategory chip scoping | Show only subcategories whose `.category` matches a currently-selected category id (`selectedCategoryIds.contains(s.category)`). (D-05) |
| Visibility filtering | Omit any category where its `CategoryPreference.visible == false`, and any subcategory where its `SubcategoryPreference.visible == false`. A missing preference record (null) means visible. (D-06, FILTER-06, FILTER-07) |
| Category chip avatar | `FaIcon` from `category.icon` via `fontAwesomeIconsMap` (strip `fa-` prefix), 16px. Fallback `Icon(Icons.category, size: 16)` when the icon name is absent from the map. (D-08) |
| Subcategory chip avatar | `Stack(clipBehavior: Clip.none)` — primary `FaIcon` 16px (from `subcategory.icon`, falling back to the parent category's icon when empty) + optional badge `FaIcon` 10px positioned `right: -2, bottom: -2`. Badge omitted when `subcategory.badgeIcon` is null/empty. (D-09) |
| Chip extension | `WandererFilterChip<T>` gains optional `Widget? Function(T item)? avatarBuilder`. Existing call sites (passing nothing) are unaffected — render no avatar. Category/subcategory call sites pass the builder. (D-07) |
| Quick filter bar | No second chip added. The existing Category chip opens ONE bottom sheet containing both a Categories section and (below it) a Subcategories section using the same `AnimatedSize` pattern. The chip's active highlight uses `filter.category.isNotEmpty || filter.subcategory.isNotEmpty`. Sheet keeps `initialChildSize: 0.5`, `maxChildSize: 0.9`. (D-11, D-12, D-13, D-14) |
| Consistency | TrailFilterScreen and the bottom sheet MUST present subcategories identically — same section label, same `AnimatedSize`, same chip + avatar rendering. |
