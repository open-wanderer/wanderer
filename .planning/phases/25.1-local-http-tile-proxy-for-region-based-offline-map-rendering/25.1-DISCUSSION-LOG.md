## Scope: Both Map Screens or Navigation-Only

| Option | Description | Selected |
|--------|-------------|----------|
| Unify both screens on the proxy | Both TrailMap and navigation_screen serve tiles through the same static XYZ proxy source; deletes the _sourceFromJson/_layerFromJson duplication entirely | ✓ |
| navigation_screen only | Leave TrailMap's working add-only reconcile untouched, only replace the broken navigation_screen path | |

**User's choice:** Unify both screens on the proxy
**Notes:** TrailMap's current mechanism actually passed all Phase 25 UAT tests, but keeping one rendering mechanism app-wide was preferred over leaving two different approaches (one legacy-but-working, one newly replaced) side by side.

## Region Overlap Resolution

| Option | Description | Selected |
|--------|-------------|----------|
| Smallest bbox wins | The more specific/local region takes precedence over a larger one covering the same spot | ✓ |
| Most recently downloaded wins | Whichever region finished downloading last serves the tile | |
| You decide | No strong preference | |

**User's choice:** Smallest bbox wins
**Notes:** Matches the expectation that a small regional download should be authoritative over a broader one covering the same area.

| Option | Description | Selected |
|--------|-------------|----------|
| Most recently downloaded wins the tie | Falls back to recency only when bbox size is genuinely equal | ✓ |
