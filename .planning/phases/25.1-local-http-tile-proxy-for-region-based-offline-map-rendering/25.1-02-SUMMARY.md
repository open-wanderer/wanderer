# Phase 25.1 Plan 02: Local HTTP Tile Proxy Core Summary

**Loopback-only `dart:io HttpServer` serving vector/DEM map tiles from region `.pmtiles` archives via a per-request smallest-bbox winner resolver, paired with a static-XYZ offline style rewriter that replaces per-cell `pmtiles://` source duplication with one fixed proxy URL template.**

- **Completed:** 2026-07-23T15:45:45Z
- **Tasks:** 3
- **Files modified:** 9 (5 created, 4 modified)

## Accomplishments
- Pure, unit-tested `tileToBounds` (Web-Mercator z/x/y → lon/lat bbox) and `resolveRegionForTile` (per-tile smallest-bbox-then-most-recent winner resolution, PROXY-02/D-02/D-03) — both testable without a live ObjectBox store
- A loopback-only, ephemeral-port `TileProxyServer` that routes `/vector/{z}/{x}/{y}.pbf` and `/dem/{z}/{x}/{y}.png`, explicitly bounds-checks z/x/y before constructing a `ZXY` (never trusting the package's release-stripped `assert`), resolves the archive path only from DB-derived `localFilePath` (never from the request), and caches open `PmTilesArchive` handles in a bounded LRU
- `tileProxyBaseUrlProvider`, a `keepAlive` Riverpod provider mirroring `objectbox_store_provider.dart`'s exact "overridden in main.dart" shape
- `rewriteStyleForProxy`, emitting exactly one vector and one DEM static XYZ source template pointed at the loopback proxy — no per-region `__cellN` source/layer duplication, since the proxy resolves per-tile coverage server-side
