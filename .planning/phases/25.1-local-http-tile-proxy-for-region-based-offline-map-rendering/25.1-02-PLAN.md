<objective>
Build the client-local tile-proxy core: the pure per-tile region-resolution logic (PROXY-02), the loopback `HttpServer` that serves tiles from region `.pmtiles` archives, its `keepAlive` base-URL provider, and the style-rewrite helper that points an offline style's tiled sources at the static loopback XYZ template (PROXY-01). This is the machinery the Plan 03 on-device spike exercises and the Plan 04 screen rewiring consumes. No new packages: `dart:io HttpServer` is Dart SDK; `maplibre` 0.3.5 and `pmtiles` 1.2.0 are already pinned with the exact APIs used here (`VectorSource.tiles`/`RasterDemSource.tiles`, `PmTilesArchive.tile`/`ZXY.toTileId`/`Tile.bytes`/`TileTypeMime.mimeType`).

Purpose: Replaces hand-rolled Dart source/layer diffing with MapLibre Native's own viewport tracking against a single static source — the mechanism that structurally eliminates the reentrancy bug class (no reconcile call, no race). The `resolveRegionForTile` winner-picking rule is net-new (nothing today picks a winner among overlapping regions; `splitRegionTilePaths` returns paths for all of them).

Output: `xyz_tile_bounds.dart` (new), `resolveRegionForTile` added to `tile_repository_manager.dart`, `tile_proxy_server.dart` (new), `tile_proxy_provider.dart` (new + codegen), and `rewriteStyleForProxy` added to `offline_style_rewriter.dart` — each with unit tests where it is pure logic. The legacy `rewriteStyleForOffline(cellPaths:...)` cell-duplication path is left intact for now (its deletion belongs to Phase 27 legacy cleanup, matching this milestone's "delete the old path last" discipline); the only remaining `cellPaths` caller after this milestone is the throwaway Phase-25 RENDER-03 harness.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MapLibre Native (in-process) → loopback HttpServer | HTTP GETs cross into the proxy handler; `z/x/y` path segments are the only client-influenced input. |
| Other apps on the device → loopback interface | The loopback interface is shared across all apps on a mobile OS; anything bound there is reachable by co-resident apps. |
| Proxy handler → local `.pmtiles` files | The handler reads on-disk archives; the path must never derive from request input. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25.1-03 | Information Disclosure | HttpServer bind scope | mitigate | Bind `InternetAddress.loopbackIPv4` only (never `anyIPv4`/`0.0.0.0`) so the server is unreachable from the LAN/hotspot — verified by negative grep for `anyIPv4`/`0.0.0.0`. Served data is public map tiles (low value), but loopback-only binding removes the exposure entirely. |
| T-25.1-04 | Information Disclosure | Port predictability | mitigate | Use an OS-assigned ephemeral port (`bind(..., 0)`), not a fixed well-known port, so a co-resident app cannot pre-target a guessable port. |
| T-25.1-05 | Tampering / DoS | z/x/y request parsing | mitigate | Explicit range validation (`z` 0..26, `x/y` in `[0, 2^z)`) in the handler BEFORE constructing `ZXY` — `ZXY`'s own `assert` is stripped in release builds (RESEARCH Anti-Pattern / Security V5). Malformed input → HTTP 400, never undefined behavior. |
| T-25.1-06 | Tampering (path traversal) | archive path resolution | mitigate | The `.pmtiles` path is read only from `DownloadedTilePackageEntity.localFilePath` (DB-derived, validated at write time by `region_file_path.dart`'s `assertValidRegionId`), never assembled from request path segments — structurally eliminates traversal. |
| T-25.1-07 | Denial of Service | open PmTilesArchive handles | mitigate | Bounded LRU archive-handle cache (small fixed N) rather than an unbounded per-lifetime map; evicts entries whose backing file no longer exists. |

Supply-chain gate (T-{phase}-SC): N/A — zero new packages (`dart:io` SDK + already-pinned `maplibre`/`pmtiles`; RESEARCH Package Legitimacy Audit: not applicable).
