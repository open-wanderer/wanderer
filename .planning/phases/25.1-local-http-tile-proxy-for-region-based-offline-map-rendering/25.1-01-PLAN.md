<objective>
Add the two platform-manifest network exceptions that let MapLibre Native's on-device tile-fetch layer (OkHttp on Android, NSURLSession on iOS) reach the in-app loopback tile proxy over cleartext `http://127.0.0.1:<port>`. Both platforms block non-TLS HTTP by default; without these exceptions the Phase 25.1 proxy — and the PROXY-03 on-device spike that validates it (Plan 03) — fail for a reason that has nothing to do with the actual airplane-mode question the spike exists to answer.

Purpose: These are a hard prerequisite for the spike (Plan 03) and the real rewiring (Plan 04). RESEARCH.md Pitfall 1 (Android) is HIGH confidence (official policy + confirmed absence of any current exception + confirmed OkHttp dependency chain in `maplibre_android`); Pitfall 2 (iOS ATS) is MEDIUM (mixed community evidence) so both documented exception mechanisms are added proactively — a loopback-only exception is zero-cost and carries no App Review risk.

Output: A new Android `network_security_config.xml` scoped to `127.0.0.1`, the `android:networkSecurityConfig` attribute wiring it into `AndroidManifest.xml`, and an `NSAppTransportSecurity` loopback exception in `Info.plist`. No Dart, no packages, no behavior change to any existing surface.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MapLibre Native tile fetch → in-app loopback proxy | An in-process HTTP GET to `127.0.0.1` crossing the OS network-policy layer; these manifest changes decide whether that crossing is permitted and how narrowly. |
| Other apps / LAN hosts → device HTTP policy | A too-broad cleartext exception would also unblock cleartext to arbitrary non-loopback hosts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25.1-01 | Information Disclosure / Elevation | Android/iOS cleartext policy scope | mitigate | Scope the exception to `127.0.0.1` (Android `<domain>`) and `127.0.0.1`/`localhost` (iOS `NSExceptionDomains`) ONLY. Explicitly forbid `android:usesCleartextTraffic`, `<base-config>`, and iOS `NSAllowsArbitraryLoads` — verified by negative greps in both tasks. A blanket allowance would let any plaintext HTTP host through, widening the app's network attack surface for no benefit. |
| T-25.1-02 | Information Disclosure (privacy prompt) | iOS Local Network permission | accept | `NSLocalNetworkUsageDescription` is deliberately NOT added — loopback traffic never reaches the LAN, so the iOS 14+ Local Network prompt does not apply (RESEARCH Pitfall 3). No user-facing permission is requested. |
