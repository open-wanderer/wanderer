<objective>
Settle PROXY-03 — the phase's risk gate — with an on-device spike, mirroring Phase 25's RENDER-03 precedent (`region_render_spike_harness.dart` + a blocking `checkpoint:decision`). RESEARCH.md establishes that the core airplane-mode question (does MapLibre Native reliably load loopback-HTTP tile sources while the OS reports no connectivity?) cannot be resolved by source reading — the HTTP fetch lives in MapLibre Native's C++/JNI/Swift core (OkHttp on Android, NSURLSession on iOS), outside the Dart surface. A human must run the real proxy on real hardware in airplane mode before the phase commits to rewiring the production screens.

Purpose: If the spike fails, D-04 forbids pre-scripting a fallback — the executor stops and reassesses with the user (the patch-the-reconcile option remains known but is NOT chosen here). This plan therefore ends in a blocking decision, not an implementation branch.

Output: `app/test/services/tile_proxy_spike_harness.dart` (a `flutter run -t` entry point, NOT a unit test, kept off the shipped app under `test/`), plus a blocking `checkpoint:decision` recording the human's on-device findings and the proceed/stop decision.
</objective>
