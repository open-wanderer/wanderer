## Tests

### 1. TrailMap offline render on the real production screen
expected: Basemap (and hillshade) renders offline exactly as it did through the harness in 25.1-03-SUMMARY.md, confirming main.dart's TileProxyServer startup + TrailMap's rewired _composeStyle work end-to-end on real hardware.
result: pass
reported: "Confirmed on-device (Android): basemap tiles + hillshade (dem served -> 200), street-name glyphs, and sprite icons all render offline through the loopback proxy on TrailMap. Fixed in commit 9e164aab."
severity: major
resolution: "Root cause was NOT the proxy/style wiring (all correct). MapLibre Native suppresses every online-file-source HTTP request when its ConnectivityReceiver reports no network (airplane mode) — including requests to http://127.0.0.1 — so it never issued a tile request (no proxy hit, no error), while still rendering ungated file:// glyphs and inline-GeoJSON track. Fix: MainActivity calls MapLibre.setConnected(true). Two secondary bugs also fixed: the offline render path still depended on the network via mapStyleJson/glyphSpriteCache (now network-free offline providers), and the sprite cache omitted @2x.json (missing icons on hi-dpi)."

## Known limitation (iOS)

The MapLibre.setConnected(true) fix is Android-only. The maplibre_ios FFI
package exposes no setConnected/NetworkStatus hook, so iOS has the same
airplane-mode connectivity gate and offline tiles will not render there until
the package is forked to expose the override (upstream's own recommendation).
Tracked in deferred-items.md. iOS was not part of this phase's on-device UAT
(verified on Android/Pixel-class hardware).
