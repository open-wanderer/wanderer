# Phase 25.1 Plan 04: Wire TrailMap and navigation_screen Onto the Loopback Tile Proxy Summary

**Both `TrailMap` and `navigation_screen` now compose their offline style through one static loopback-proxy XYZ source (`rewriteStyleForProxy`), with the entire incremental `addSource`/`removeSource` region-reconcile machinery — and the `MapEventCameraIdle` trigger that raced it — deleted from both files, closing Phase 25's UAT Test 4 gap structurally.**

## Accomplishments

- `main.dart` starts the `TileProxyServer` immediately after `openStore` and overrides `tileProxyBaseUrlProvider` with its resolved base URL, alongside the existing `objectBoxProvider`/`cookieJarProvider` overrides — the proxy is bound before any screen's first `_composeStyle` call.
- `TrailMap._composeStyle` now bakes the single static proxy source via `rewriteStyleForProxy`; the entire `_addedSourceIds`/`_addedLayerIds`/`_seedRegionTracking`/`_sourceFromJson`/`_layerFromJson`/`_addRegionComposition` incremental-reconcile machinery and its `regionListNotifierProvider` listen are deleted. `_swapStyle` is unchanged structurally.
- `navigation_screen._composeStyle` drops its `viewportBounds` parameter entirely (the proxy resolves coverage per-tile server-side, so no live viewport query is needed) and bakes the same static proxy source. The mirror-image `_reconcileRegionComposition`/`_sourceFromJson`/`_layerFromJson`/`_seedRegionTracking`/tracking-set machinery is deleted, along with the `MapEventCameraIdle` trigger diagnosed as the Phase 25 UAT Test 4 reentrancy race and the `regionListNotifierProvider` listener that drove the old reconcile.
- Both screens now serve region tiles through exactly one mechanism app-wide — the `_sourceFromJson`/`_layerFromJson` duplication between the two files that D-01 targeted is gone.

## Decisions Made

- **Deleted (not kept) the mid-session-download refresh listener in `navigation_screen`.** The plan's task text posed a strict either/or gated on `25.1-03-SUMMARY.md`'s test case (d) finding: delete the `regionListNotifierProvider` listener entirely if tiles appear "WITHOUT a remount", or keep a minimal fixed-source refresh if they do not. The recorded spike verdict was PASS with the literal phrase "no screen remount required" — satisfying the plan's own criterion for outright deletion. This also matches the underlying mechanism: the proxy re-queries `RegionEntity` rows fresh on every HTTP request (no server-side caching of the region list), so once the camera reaches a newly-covered tile, MapLibre's native fetch simply succeeds — no Dart-side signal is structurally required.
- **TrailMap's widened coverage scope accepted as-is.** Per RESEARCH Pitfall 6 and the plan's explicit instruction, no banner/toast/empty-state was added for the (harmless, camera-fixed) scope widening from "trail's own bounds" to "any downloaded region the camera renders."
