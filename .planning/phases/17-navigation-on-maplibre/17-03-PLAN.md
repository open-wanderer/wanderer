  <how-to-verify>
Run the app on a PHYSICAL Android device (not the simulator — GPS + platform-view
gesture routing differ). Build/install with `cd app && flutter run --release` (or a
debug run if faster to iterate), open a trail's detail map, and tap Navigate. Then
verify each item and record PASS/FAIL:

1. NAV-01 render: the route line, directional arrows, waypoints/start-finish pins,
   and a native location puck all appear; with follow on, the camera stays centered
   on the puck as you (or a mock route) move. Confirm the puck is the native
   pulse/accuracy puck (D-04 accepted visual), not the old 18px blue dot.

2. NAV-02 drag-break precision (the highest-risk item):
   (a) drag the map with ONE finger → follow breaks, the recenter button becomes
       enabled (surface background, not grey);
   (b) pinch-zoom with TWO fingers → follow must NOT break (camera zooms, puck keeps
       tracking, recenter stays disabled);
   (c) two-finger rotate → follow must NOT break.
   If (b) or (c) breaks follow, the pointer-count heuristic is not observing pointer
   events through the platform view — that is a FAIL to feed back to 17-01 Task 2.

3. NAV-02 recenter + D-03: with heading-up ON, drag to break follow, then tap
   recenter → the camera re-engages follow AND stays in heading-up (does not snap to
   north). Repeat the pan-then-recenter cycle a few times — it must remain heading-up.

4. NAV-03 compass toggle (D-01/D-02): the compass is always visible (does not hide at
   north). Tap it once → map rotates to follow GPS heading (heading-up). Tap again →
   map animates back to north over ~400ms (not instant, no crash). Confirm the compass
   needle rotates with the map bearing.

5. NAV-04 offline (reuse the existing v1.1 offline-navigation test procedure): download
   a trail, enable airplane mode (leave device GPS/location ON), start navigation.
   Confirm: (a) maneuver banner still advances as position updates (ObjectBox cache,
   unregressed); (b) the offline indicator (`Icons.cloud_off`) shows in the banner;
   (c) the basemap renders (place labels + tiles) from local `.pmtiles` with no network;
   (d) the native puck still renders and follows in airplane mode (RESEARCH Open
   Question 2 — confirm the OS did not silently degrade to a network-only provider).

6. Theme-swap survival (Pitfall 4): while navigating, toggle the app light/dark theme.
   Confirm the map style swaps live AND the location puck, trail track, and breadcrumb
   all survive the swap (they must be re-armed on `onStyleLoaded`). A vanished puck or
   dropped track after the toggle is a FAIL.

7. No-crash sanity: exit navigation via the X (confirm dialog), re-enter, and confirm no
   leaked GPS subscription or duplicate puck.
  </how-to-verify>
