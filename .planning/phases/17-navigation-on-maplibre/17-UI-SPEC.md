# Phase 17 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** This is the Flutter mobile app (`app/lib/`), not the SvelteKit web frontend. There is no shadcn/Tailwind/CSS surface here — the design system is Flutter Material 3 (`ThemeData`) plus the native `maplibre` 0.3.5 package's own widgets. Template sections below are filled in Flutter vocabulary (widget properties, `Theme.of(context)` tokens, `IconButton.styleFrom`) per this agent's Flutter-project mandate, not CSS.

**Scope note:** Per ROADMAP.md/CONTEXT.md, this phase changes the **map rendering layer only** — the route line, breadcrumb, waypoint markers, maneuver banner, and stats sheet keep their existing content and layout unchanged (v1.0/v1.1 behavior, unregressed). The visual contract below therefore has two kinds of entries: (a) **carried forward unchanged** — documented here so the executor doesn't accidentally "improve" them during the file rewrite, and (b) **genuinely new** — the location puck and the compass icon, which change appearance because their implementation moves to native `maplibre` widgets with no custom-styling API. Item (b) includes one gap CONTEXT.md's locked decisions left open (the compass icon's visual, as opposed to its toggle *behavior*, which D-01 locked) — resolved below by aligning to Phase 16's already-shipped `map_screen.dart` precedent rather than inventing a third treatment.

## Spacing Scale

Declared values (Flutter, multiples of 4px — matches existing `navigation_screen.dart` usage):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label internal gaps (banner icon padding) |
| sm | 8px | Compact control spacing — **compass-to-recenter gap in the control column (see below)** |
| md | 16px | Default padding (banner horizontal padding, button row horizontal padding, stats sheet horizontal padding) |
| lg | 24px | Banner outer horizontal padding (`SafeArea` → `Padding(24, 8, 24, 0)`) |
| — | 12px | Banner vertical padding, stats-sheet stat-row bottom padding (existing exception, already in codebase — not a new token) |

Exceptions:
- **Compass/recenter gap changes from 4px → 8px (sm).** The current custom `MapCompass` (`app/lib/components/map/map_compass.dart`) renders inside a ~48×48px `IconButton` with zero internal padding. The native `ml.MapCompass` (default `radius: 22`, default `padding: EdgeInsets.all(10)`) occupies a larger ~64×64px footprint. Keeping the previous 4px `SizedBox` gap between it and the recenter `IconButton` below would visually crowd the two controls given the compass's larger footprint — bump the gap to 8px (`sm`). This is the one spacing change this phase makes; every other spacing value in `navigation_screen.dart` is unchanged.
- Material minimum touch target: `IconButton`/`FloatingActionButton.small` default to a 48×48px minimum tap area regardless of visible icon size — unchanged, matches existing recenter/exit/elevation-toggle buttons.
- The control column's screen position is unchanged: `Positioned(top: 128, right: 8)` wrapping a `Column(mainAxisSize: MainAxisSize.min)` containing `[compass, SizedBox(height: 8), recenter button]`.

## Widget Contract — Map Controls (new/changed this phase)

This section is the executor's concrete implementation reference for the two controls whose visuals change in this phase. Every property below is prescriptive, not exploratory.

### Location Puck (CORE-07, D-04)

Replace the custom 18px blue-dot `WidgetLayer` marker (the one still used by `WandererMap`/`map_screen.dart` elsewhere, **unaffected by this phase**) with maplibre's native puck, called from `onStyleLoaded` (re-armed on every style reload — see Pitfall 3/4 in 17-RESEARCH.md):

```dart
await controller.enableLocation(
  bearingRenderMode: ml.BearingRenderMode.gps, // GPS heading, not compass sensor (D-04)
  pulseFade: true,
  accuracyAnimation: true,
  pulse: true,
  compassAnimation: true,
);
```

- **Visual acceptance:** the puck's color, ring, and accuracy-pulse circle come entirely from the native platform component (Android `LocationComponent` / iOS `MLNMapView`) with **no color/size override API**. Do not attempt to tint or resize it to match the app's `#3549BB`/blue-dot language — this is D-04's explicit, accepted departure, not an oversight to fix.
- `trackLocation`/`trackBearing` drive follow + heading-up (see Interaction Contract below) — not a separate visual concern, but do not gate the puck's *rendering* on follow state; the puck always shows the device's live position regardless of whether the camera is following it.

### Compass Control (CORE-05, D-01, D-02)

Replace the app-local `MapCompass` widget (`app/lib/components/map/map_compass.dart` — "N" label with orange up-caret / default-color down-caret inside a zero-padding `IconButton`, themed `canvasColor` background) with maplibre's native `ml.MapCompass`.

**Resolved gap:** CONTEXT.md locked the toggle *behavior* (D-01) and *visibility* (D-02) but left the icon's *visual appearance* undiscussed — flagged by ROADMAP/CONTEXT as an accepted-by-omission native default. This UI-SPEC resolves it explicitly: **use the native default unstyled**, matching the precedent Phase 16 already shipped on `map_screen.dart` (`ml.MapCompass(hideIfRotatedNorth: true)`, no `child` override, no color override). Do not restyle it to FontAwesome/app icon language — introducing a third distinct compass treatment across the app's three map screens (trail detail, map screen, navigation) is explicitly the outcome to avoid per this phase's brief.

```dart
ml.MapCompass(
  hideIfRotatedNorth: false,   // D-02: always visible during nav (contrast with map_screen's true)
  rotateNorthOnPressed: false, // prevent double-handling — onPressed fully takes over (see Pattern 3, 17-RESEARCH.md)
  onPressed: () {
    setState(() => _headingUp = !_headingUp);
    controller?.trackLocation(
      trackLocation: _followEnabled,
      trackBearing: _headingUp ? ml.BearingTrackMode.gps : ml.BearingTrackMode.none,
    );
    if (!_headingUp) {
      controller?.animateCamera(bearing: 0, nativeDuration: const Duration(milliseconds: 400));
    }
  },
)
```

- **Native default visual (accepted, not themed):** ~44px circle (`radius: 22`, default) + 10px padding on all sides ≈ 64×64px total footprint. `Colors.white60` fill, `Colors.black` 3px outline, `Colors.red` compass needle, painted via the package's own `CustomPaint`. This is **not** theme-aware (identical in light and dark mode) — a known, pre-existing characteristic of this same widget already shipped on `map_screen.dart` in Phase 16; not a new regression introduced here and not in scope to fix.
- Position: `Positioned(top: 128, right: 8)` — unchanged from today's layout. Sits above the recenter `IconButton` in a `Column(mainAxisSize: MainAxisSize.min)` with an 8px gap (see Spacing Scale exception above).
- Rotation angle is driven by `camera.bearing` automatically (native widget internals) — no manual `Transform.rotate` wiring needed, unlike the deleted custom widget.

### Recenter Control (NAV-02, D-03) — unchanged visual, changed wiring only

No visual change. Keep exactly as today:

```dart
IconButton(
  onPressed: _followEnabled ? null : _onRecenter,
  icon: const FaIcon(FontAwesomeIcons.locationCrosshairs),
  style: IconButton.styleFrom(
    backgroundColor: Theme.of(context).colorScheme.surface,
    disabledBackgroundColor: Theme.of(context).colorScheme.surface,
    disabledForegroundColor: Colors.grey,
  ),
)
```

Only `_onRecenter`'s *implementation* changes (native `trackLocation` call restoring prior `_headingUp` state per D-03, instead of pushing to the old `_recenterTrigger` stream) — the icon, colors, sizing, and enabled/disabled visual states are identical to today.

## Interaction Contract — Follow / Heading-Up / Drag-Break (NAV-01, NAV-02, NAV-03)

Not a template section, included because this phase's core requirements are interaction-state contracts, not new visual elements — the executor and checker both need this state table to verify NAV-02/NAV-03 without re-deriving it from RESEARCH.md.

| State | Trigger | Resulting control wiring | Visual result |
|-------|---------|---------------------------|----------------|
| Follow + north-up (default) | Screen opens | `trackLocation(trackLocation: true, trackBearing: none)` | Camera stays centered on puck; map bearing fixed at 0°; recenter button disabled (grey) |
| Follow + heading-up | Tap compass while north-up | `trackLocation(trackLocation: true, trackBearing: gps)` | Camera rotates to match device heading as it changes; compass needle rotates opposite to camera per its own internal `Transform.rotate` |
| Follow broken by drag | Single-finger pan starts (`MapEventStartMoveCamera` + pointer-count == 1, see RESEARCH.md Pattern 2) | `trackLocation(trackLocation: false)` | Puck and camera decouple; recenter button becomes enabled (surface bg, normal foreground) — no other visual change |
| Follow broken, heading-up still "on" | Same as above, while `_headingUp == true` | `_headingUp` flag is **not** reset (D-03) | Compass icon state (native, reads live `camera.bearing`) shows whatever bearing the user left the map at — not reset to north |
| Recenter tapped | Tap recenter button (only enabled when follow is broken) | `trackLocation(trackLocation: true, trackBearing: _headingUp ? gps : none)` (D-03 — restores prior heading-up state, does not force north) | Camera snaps/animates back to puck, resuming whatever bearing mode was active before the drag; recenter button disables again |
| Heading-up turned off via compass tap | Tap compass while heading-up | `trackLocation(trackBearing: none)` + explicit `animateCamera(bearing: 0, nativeDuration: 400ms)` (D-01 — native `rotateNorthOnPressed` is disabled, so this reset must be explicit) | Map animates back to north-up over ~400ms |
| Pinch-zoom or two-finger rotate | Multi-finger gesture (pointer count > 1) | **No** `trackLocation` call — follow must NOT break | Camera zooms/rotates under the gesture; puck tracking and heading-up mode remain exactly as they were |

**Animation durations:** short, native, non-zero — 400ms for the compass north-reset (matches Phase 16's `map_screen.dart` cluster-tap-zoom precedent); `Duration.zero` is banned app-wide for `animateCamera`/`fitBounds` (crashes the Android native binding — Phase 16-03 checkpoint lesson, cited in RESEARCH.md).

**checkpoint:human-verify:** The pointer-count heuristic distinguishing single-finger drag from multi-finger pinch/rotate (no native API distinguishes these — see RESEARCH.md Open Question 1) must be confirmed on a physical device: (a) one-finger pan breaks follow, (b) two-finger pinch-zoom does NOT break follow, (c) two-finger rotate does NOT break follow. This is a functional/interaction check, not a purely visual one, but it gates whether NAV-02's visual contract (recenter button enable/disable) fires correctly.
