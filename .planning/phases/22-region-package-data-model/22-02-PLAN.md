<objective>
Build the fetch-and-upsert function for Phase 21.5's region catalog: `RegionRepository.refreshCatalog()` GETs `/api/v1/regions`, parses the bare JSON array into `RegionCatalogEntry` values, and upserts them into ObjectBox by business id — preserving each region's local download status and package links. Expose it as a plain, construction-only Riverpod provider seam.

Purpose: Give Phase 23 (download engine) and Phase 24 (Settings UI) a callable that keeps the catalog in sync without the destructive `removeAll()+putMany()` merge used elsewhere in the app — that pattern would sever `ToOne` package links and destroy local download status on every refresh (D-01). This phase only makes the function exist and be callable; it is not wired to any call site or screen lifecycle yet (D-02).

Output: `app/lib/provider/region/region_repository.dart` (+ generated provider) and unit tests for the network, parse, and orphan-detection logic.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote backend -> Dio client | `GET /api/v1/regions` crosses the network from this instance's backend into the app; response body is untrusted input |
| fetched catalog -> ObjectBox | parsed entries are written to local persistence; a failed/partial fetch must not corrupt or wipe existing local state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-05 | Tampering | `parseRegionCatalog` on a malformed/hostile array | mitigate | Non-`List` payloads throw `RegionCatalogException`; individual malformed elements are caught and skipped per-element (and `applyCatalogEntry`'s bbox-length guard rejects a truncated bbox), so one bad entry cannot crash the parse or corrupt the upsert |
| T-22-06 | Denial of service | `refreshCatalog` clobbering local state on a bad fetch | mitigate | fetch+parse fully complete before any store write; on offline/401/500 `fetchRegionCatalog` throws `RegionCatalogException` before `upsertCatalog` runs, so existing rows/download status are left untouched (D-03); orphan handling flips a flag, never deletes rows or files (D-08) |
| T-22-07 | Spoofing / Info disclosure | transport auth + no secret persistence | accept | The fetch reuses the app's existing cookie-authenticated `apiProvider` Dio over the operator's HTTPS base URL (platform default TLS/cert validation, no `badCertificateCallback` override introduced); no token/cookie is written into ObjectBox — auth stays in the existing cookie jar |
| T-22-SC | Tampering | dependencies | accept | Zero new packages — `dio`, `objectbox`, `riverpod_annotation`, `build_runner` already pinned in `app/pubspec.yaml`; no install step, so no supply-chain checkpoint applies |
</threat_model>
