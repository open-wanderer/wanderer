## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public internet → GET /activitypub/instance | Unauthenticated peers/tools fetch the actor document; response must contain only public data |
| Server process → activitypub_actors table | `InitInstanceActor` writes the RSA private key (encrypted) at startup |
| Env (ORIGIN, POCKETBASE_ENCRYPTION_KEY) → process | Configuration crossing into the binary; missing/wrong values must fail safe |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `InstanceActorGet` response | mitigate | Response is built from an explicit `map[string]any` containing only public fields (`public_key`, never `private_key`). The `private_key` column is `hidden` in PocketBase schema and is never read into the response map. Acceptance criterion greps that the handler builds a map and does not reference `private_key`. |
| T-01-02 | Tampering | Keypair regeneration on restart | mitigate | `InitInstanceActor` performs an IRI existence check (`FindFirstRecordByData`) and returns immediately if the actor exists — never overwrites the stored key. Covered by `TestInitInstanceActorIsIdempotent` (automated) AND the live-restart checkpoint (Task 3 step 4). Listed as a hard blocker in STATE.md. |
| T-01-03 | Spoofing | Instance actor IRI collision / duplicate actor | mitigate | The `iri` column carries a unique index (`idx_rpT7QJwWTm`); the migration does not alter it. One-record-per-IRI is enforced at the DB level. Idempotency check prevents the process from creating a second record. |
| T-01-04 | Information Disclosure | RSA private key at rest | mitigate | Private key is encrypted with `security.Encrypt(privBytes, POCKETBASE_ENCRYPTION_KEY)` (AES-GCM) before storage — identical to the existing user-actor pattern. `verifySettings` in `main.go` fatals if the key is not exactly 32 bytes. No new key-handling code is introduced. |
| T-01-05 | Elevation of Privilege | GET handler bypassing collection access rules | accept | The handler intentionally uses `app.FindFirstRecordByData` (server-side, bypasses collection viewRule) so the userless instance actor is fetchable. This exposes only public actor fields by design (AP actors are public discovery documents). No sensitive data is reachable through this path. |
| T-01-06 | Denial of Service | Unauthenticated GET endpoint flooding | accept | The endpoint is a single indexed DB read returning a small static document; it is no more exposed than the existing `/activitypub/actor` routes. Rate-limiting is an infrastructure concern out of scope for v1 (matches existing AP endpoints). |
| T-01-SC | Tampering | npm/pip/cargo installs | n/a (mitigated by design) | No packages are installed in this phase — all code uses dependencies already present in `db/go.mod` (verified in RESEARCH §"No New Packages"). No package-legitimacy checkpoint required. |
</threat_model>
