# Phase 2 — UI Design Contract

> Visual and interaction contract for the Flutter NavigationScreen. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Platform:** Flutter + Material 3 (mobile). shadcn / web design-system tooling is **not applicable** — this is a native Flutter screen that reuses the app's existing `AppTheme` (`app/lib/theme/theme.dart`) and `AppColors` (`app/lib/theme/colors.dart`). All tokens below are extracted from the existing codebase, not newly invented. Reuse existing widgets (`MapCompass`, `TrailLayer`, `CurrentLocationLayer`, `AnimatedMapController`) rather than rebuilding.

## Spacing Scale

Declared values (Material 8-point family; values used across `map_screen.dart` and entry screens):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text inline gaps, button corner radius (theme `ElevatedButton` radius = 4) |
| sm | 8px | Compact gaps (icon ↔ label `SizedBox(width: 8)`, chip spacing, banner inner row gap) |
| md | 16px | Default content padding (banner horizontal padding, floating-control inset from screen edge) |
| lg | 24px | Screen-edge padding for top maneuver banner and bottom floating CTA (matches `MapScreen` `horizontal: 24`) |
| xl | 32px | Reserved — large vertical breaks if needed |

Exceptions:
- **Floating map controls (compass, recenter, exit):** circular `IconButton` targets at **48px** diameter minimum (Material touch-target floor) even though 48 is not on the 4-step list below 48. This is the standard Flutter accessibility minimum and is allowed.
- **Top control offset:** the maneuver banner and top-right compass sit inside `SafeArea`; the compass column in `MapScreen` uses `top: 124` to clear the search bar — NavigationScreen has no search bar, so place the compass/exit row directly under `SafeArea` top inset with `md (16px)` inset.

## Typography

All roles map to Material 3 `TextTheme` slots so they inherit IBMPlexSans automatically. Sizes are the Material 3 defaults the app already relies on (`Theme.of(context).textTheme.*`).

| Role | Size | Weight | Line Height | Material slot / usage |
|------|------|--------|-------------|------------------------|
| Maneuver instruction (primary) | 20px | 600 (SemiBold) | 1.3 | `titleLarge` — the current Valhalla instruction text in the top banner (NAV-04) |
| Maneuver distance / sub-label | 14px | 400 (Regular) | 1.4 | `bodyMedium` — "in 120 m" distance-to-next-turn line under the instruction |
| Completion banner heading | 20px | 600 (SemiBold) | 1.3 | `titleLarge` — "You've arrived!" (D-14) |
| Button / control label | 16px | 600 (SemiBold) | 1.2 | `labelLarge` — "Navigate" CTA label and recenter label |

Weights are restricted to **2**: Regular (400) and SemiBold (600). The IBMPlexSans Bold (700) face exists in the bundle but is NOT used on this screen — heading emphasis is carried by SemiBold to match the rest of the app's screen chrome.

## Color

Derived from `AppColors` / `ColorScheme`. The navigation screen is a **map-dominant** screen: the live map fills 100% of the viewport, so the "60% dominant surface" is the map itself. Chrome (banner, controls) is layered on top as opaque cards.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | the live map raster/vector tiles | Full-screen background — `FlutterMap` fills the viewport |
| Secondary (30%) | `colorScheme.surface` — light `#FFFFFF` / dark `#12141C` | Maneuver banner background, floating control button backgrounds (`canvasColor`), completion banner |
| Accent (10%) | `colorScheme.primary` — `#242734` (both themes) | Primary "Navigate" CTA fill, recenter button active state, GPS marker accent, maneuver-banner leading turn icon |
| Breadcrumb trace | crimson red `#DC2626` | The session breadcrumb polyline showing the user's actual traveled path (NAV-08 / D-18, D-20) |
| Trail polyline | `#3549BB` (TrailLayer default `routeColor`) | The planned trail route — kept visually dominant over the breadcrumb |

Accent reserved for:
- The "Navigate" primary CTA on the two entry screens (filled primary, full-width — D-01/D-02/D-03)
- The recenter button when auto-follow is paused (D-09)
- The leading maneuver/turn icon inside the instruction banner
- The GPS direction marker tint (via `CurrentLocationLayer` default, which uses primary)

Accent is NOT applied to: the compass toggle, the exit/close button, or the maneuver text itself (those use `onSurface` on a `surface` card).

**Color contract for the two map polylines (must hold together):**
- Trail polyline: `#3549BB`, strokeWidth **5.0**, white border 2px (existing `TrailLayer` default — unchanged).
- Breadcrumb trace: `#DC2626` (crimson), strokeWidth **3.5** (thinner than trail so trail stays dominant — D-20), drawn in a `PolylineLayer` **above** `TrailLayer` so the traveled path reads on top.

## Copywriting Contract

All user-facing strings route through `AppLocalizations` (`app/lib/i18n/`) — the values below are the canonical English source strings the planner must add as i18n keys.

| Element | Copy |
|---------|------|
| Primary CTA | **Navigate** (with `FontAwesomeIcons.locationArrow` / navigation icon, leading) |
| CTA loading state | CTA label hidden; `CircularProgressIndicator` (strokeWidth 2) shown in the icon slot; button stays disabled while in flight (D-06) |
| Maneuver banner (active) | `{instruction}` from `NavigateManeuver.instruction`, with a secondary line `in {distance}` formatted via the app's existing distance formatter (km/m, locale-aware) |
| Completion banner heading | **You've arrived** |
| Completion banner body | **You've reached the end of the trail.** (display-only; navigation, map, and GPS stay active — D-14; no save-as-summit-log option — D-15) |
| Error state (API failure) | Toast, `ToastType.error`, icon `FontAwesomeIcons.triangleExclamation`: **Couldn't start navigation. Check your connection and try again.** (D-07 — stay on detail screen) |
| Empty / no-route guard | If the route shape or maneuver list is empty, show the same error toast and do not transition; NavigationScreen is never entered without a `NavigateResponse`. No in-screen empty state is needed because entry is gated on a successful API response (D-05). |

Notes:
- There is **no destructive action** in this phase. Exiting navigation is non-destructive (the session breadcrumb is in-memory and intentionally discarded — D-19), so **no confirmation dialog** is required for exit. The exit/close control returns directly to the originating screen (NAV-07).
- Maneuver instruction text comes verbatim from Valhalla via the Phase 1 contract — do NOT rewrite or re-template it client-side.

## Interaction Contract (Flutter-specific, for executor)

| Control | Placement | Visual | Behavior |
|---------|-----------|--------|----------|
| Maneuver banner | Top, inside `SafeArea`, `lg (24px)` horizontal inset | `surface` card, radius 16, elevation 4, black26 shadow; leading turn icon (accent) + `titleLarge` instruction + `bodyMedium` distance | Shows `maneuvers[currentManeuverIndex]`; auto-advances when GPS within ~30m of next `begin_shape_index` (D-12) |
| Orientation toggle (compass) | Top-right, under `SafeArea`, `md (16px)` inset | Reuse `MapCompass` widget, `canvasColor` background `IconButton` | Cycles north-up ↔ heading-up; in heading-up the map rotates to device bearing (D-11) |
| Exit / close | Top-left, under `SafeArea`, `md (16px)` inset | Circular `IconButton`, `canvasColor` bg, `FontAwesomeIcons.xmark`, 48px target, `onSurface` icon | Pops route, returns to originating screen (NAV-07); no confirmation |
| Recenter | Bottom-right (or bottom-center), `md (16px)` inset, **only visible when auto-follow paused** | Circular `FilledButton`/`IconButton`, **accent** primary fill, `FontAwesomeIcons.locationCrosshairs`, white icon, elevation 4 | Resumes auto-follow and animates camera to GPS (D-09); reuse `MapScreen` recenter pattern. Appear/disappear with a scale transition like `MapScreen`'s `_mapButtonScale` |
| Breadcrumb layer | On-map | Crimson `#DC2626` polyline, strokeWidth 3.5, above `TrailLayer` | Renders in-memory `List<LatLng>` appended from the location stream (D-18) |
| GPS dot | On-map | `CurrentLocationLayer` defaults | Same stream feeds maneuver advancement + breadcrumb (D-13) |

Layering order (bottom → top): map tiles → `TrailLayer` (trail polyline + start/end markers) → breadcrumb `PolylineLayer` → `CurrentLocationLayer` (GPS dot) → `MapCompass` → floating controls (exit, recenter) → maneuver/completion banner.

Entry-screen CTA layout:
- `TrailDetailScreen`: fixed full-width `ElevatedButton.icon` pinned at the bottom, **in front of** scrollable content (D-01) — use a `Stack` / `bottomNavigationBar`-style overlay so it floats above the `TrailPanel` scroll view.
- `TrailDetailMapScreen`: large full-width `ElevatedButton.icon` floating over the elevation profile when open (D-02). Same fill/style as D-01.
- Both buttons inherit the theme `ElevatedButton` style (primary fill `#242734`, white foreground, radius 4).
