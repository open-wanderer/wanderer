Build the data foundation for the navigation screen: a Dart `NavigateResponse` freezed model mirroring the Phase-1 API contract, and the `@riverpod` `Navigation` notifier that owns the live navigation state (current maneuver index + breadcrumb trace) and the per-position advancement logic.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Valhalla response → Flutter notifier | `begin_shape_index` and `shape` come from an upstream routing service via the Phase-1 endpoint; indices are not guaranteed in-range or monotonic |
| GPS sensor → notifier | Device position stream feeds per-position advancement; positions are untrusted device input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Denial of Service | `Navigation.onPosition` indexing `shape[beginShapeIndex]` | mitigate | Clamp `beginShapeIndex` to `shape.length - 1` and guard `next >= maneuvers.length` before indexing (Pitfall 3) — prevents RangeError crash on malformed/last-maneuver indices |
| T-02-02 | Tampering | maneuver advancement index | mitigate | Forward-only advancement (never decrement); a spoofed/jittery position near an earlier point cannot rewind navigation state |
| T-02-03 | Information disclosure | breadcrumb `List<LatLng>` | accept | Breadcrumb is in-memory only, never persisted or transmitted (D-19); discarded when the provider family entry is disposed on screen exit |
</threat_model>
