<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| committed regions_seed.json → migration (runs on every startup) | in-repo artifact, semi-trusted; a malformed or oversized seed must fail the migration cleanly, never brick a boot mid-insert |
| migration → SQLite regions table | write boundary; bulk insert must be transactional and idempotent across repeated runs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-06 | Denial of Service | migration bulk insert on boot | mitigate | Wrap the two-pass insert in `app.RunInTransaction` so a mid-loop failure rolls back (no half-seeded catalog); set `polygon` `JSONField` `MaxSize: 8 << 20` so large coastlines don't trip the 1MB default partway through (Pitfall 1) |
| T-28-07 | Tampering | repeated `migrate down` + `up` | mitigate | `CountRecords("regions") > 0` idempotency guard makes a second up() a no-op, preventing duplicate inserts / unique-index failures (Pitfall 5) |
| T-28-08 | Tampering | malformed/oversized seed JSON | mitigate | `os.ReadFile` + `json.Unmarshal` errors are wrapped with `%w` and returned from up() → the migration fails loudly at startup with context, rather than inserting corrupt or partial rows |
| T-28-SC | Tampering | dependency surface | accept | RESEARCH Package Legitimacy Audit: no new packages; PocketBase SDK + stdlib only |
</threat_model>
