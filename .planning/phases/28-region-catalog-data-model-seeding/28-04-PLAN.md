<objective>
Close the sole failing truth from 28-VERIFICATION.md (#10/10): the committed `db/migrations/initial_data/regions_seed.json` is 730,548,521 bytes — ~7x GitHub's 100 MB hard per-file push limit, with no Git LFS configured. As committed it can never reach the project's real git remote; the moment the (local-only, 12-commits-ahead) branch is pushed, GitHub rejects it, every real `git clone` lacks the file, and the Phase 28-03 migration's seed read fails on fresh boot — the exact opposite of SEED-02's "zero admin action" promise.

Remediation (already validated by ad-hoc measurement this session, not to be re-litigated): gzip-compress the seed. Compact JSON alone is ~216 MB (still over the limit); gzip -6 of that compact encoding is ~57 MB — comfortably under 100 MB, no data loss, full coordinate precision, no Git LFS, no CI change, no new dependency (`compress/gzip` is Go stdlib).

Purpose: Make the seed a distributable git artifact so SEED-02 holds for every checkout, not just the local working tree, without regressing CATALOG-01/02/03 or SEED-01.
Output: A gzip-compressed compact `regions_seed.json.gz` (<100 MB) committed in place of the 730 MB file; `seed_regions.go` writing that format; the migration decompressing it; a full `migrate up` re-proving the identical 1306-row catalog.
</objective>
