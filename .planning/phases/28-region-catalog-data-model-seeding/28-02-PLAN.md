<objective>
Build `db/commands/seed_regions.go` — the maintainer-run Cobra command that fetches CoMaps' `hierarchy.txt` and every leaf `.poly` file fresh from Codeberg (`comaps/comaps`) at a pinned commit (D-01), converts them with the plan 28-01 parsers (`ParseHierarchy`, `ParsePoly`), and writes a flattened JSON seed array to `db/migrations/initial_data/regions_seed.json` (SEED-01). Wire it into `db/main.go`'s `setupCommands`, then run it to generate and commit the seed file that plan 28-03's migration bulk-inserts.

Purpose: Turn the two pure parsers from plan 28-01 into an end-to-end fetch-transform-write pipeline and produce the single committed artifact (the JSON seed) that makes SEED-02's "fresh instance boots with a populated catalog" possible. Only the tool's JSON output is committed — never the raw upstream files (D-01).
Output: `SeedRegions` command + `SeedRow` struct + a committed `regions_seed.json`, and one new registration line in `db/main.go`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator CLI flags (--commit / --out / --limit) → seed tool | operator-supplied; a maintainer-run dev-time CLI, not a served endpoint reachable by untrusted input |
| Codeberg HTTP responses → parsers | untrusted upstream bytes fetched over HTTP; the plan-28-01 parsers plus the fetch guards are the validation layer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-03 | Tampering (SSRF-shaped) | seed_regions.go URL construction | mitigate | Validate `--commit` against `^[0-9a-f]{7,40}$` before interpolating it into the fetch URL (RESEARCH Security Domain); `url.PathEscape` the `comaps_id` in the `.poly` URL — the value never reaches a filesystem path, so no allow-list regex is needed |
| T-28-04 | Denial of Service | seed_regions.go HTTP body reads | mitigate | Wrap every response body in `io.LimitReader` (8MB hierarchy.txt, 32MB per `.poly`); propagate plan-28-01 parser errors (which reject unterminated rings / bad indentation) up to a single `log.Fatalf` naming the file — never `panic`, never emit a silently-truncated seed |
| T-28-05 | Tampering | seed_regions.go `--out` path write | accept | `--out` is operator-supplied on a maintainer-run dev tool writing to a maintainer-chosen path; not an untrusted-input surface (RESEARCH Security Domain V2/V4: no served endpoint) |
| T-28-SC | Tampering | dependency surface | accept | RESEARCH Package Legitimacy Audit: no new packages installed this phase; new logic is stdlib-only, reusing the already-vendored `cobra` |
</threat_model>
