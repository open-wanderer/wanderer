<objective>
Build the pure handoff logic for HANDOFF-01: a `route_planner_handoff_util.dart`
that turns the in-progress route (`plannedGpxProvider`) into a draft `Trail` and
hands it to the existing trail create/edit screen, plus the `categoryForTravelProfile`
reverse-lookup (D-08) that pre-fills the draft's category from the hike/bike choice.

This is the phase's load-bearing composition step — it reuses four already-tested
codebase mechanisms almost unchanged (`pendingImportedTrail` handoff, `ElevationTab`'s
`/valhalla/height` fetch/merge, `Trail.empty().copyWith(...)`, `buildNavShape`) and
adds exactly one small new function (`categoryForTravelProfile`). It creates no UI —
the app-bar Finish button (Plan 04) is the only caller.

Purpose: Give Plan 04 a single `finishPlanning(...)` entry point and give the
create/edit screen a draft Trail shaped identically to a plain GPX-file import
(GPX track only, `waypoints: []`, category pre-filled).
Output: `route_planner_handoff_util.dart` (new), `categoryForTravelProfile` added
to `gpx_util.dart`, and unit tests for the pure pieces.
</objective>
