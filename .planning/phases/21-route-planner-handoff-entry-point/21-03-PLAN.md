## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device GPS → app | A one-shot GPS fix is read at planner entry, only when the user opted in |
| settings store → GPS gate | `Settings.behavior?.allowAutoGeolocate` (local) decides whether GPS is even subscribed |
| entry screen → /route-planner | `travelProfile`/`lat`/`lon` primitives cross the route boundary via `extra` (in-process) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-03-01 | Information Disclosure | GPS fix resolved at planner entry | mitigate | Gated on `settings?.behavior?.allowAutoGeolocate == true` (D-03) — no subscription otherwise; GPS is read only via the shared `foregroundPositionStreamProvider` (its permission-request flow, not a raw `Geolocator.getCurrentPosition`), is used only to set a local map center, and is never transmitted (ASVS V8, RESEARCH Known Threat Patterns) |
| T-21-03-02 | Tampering | `/route-planner` `extra` (travelProfile/lat/lon) | accept | All primitives, passed in-process; the router validates types with null-safe fallbacks (`travelProfile ?? 'pedestrian'`, `lat/lon → Geographic` or a fixed default) so a dropped/garbled `extra` degrades gracefully rather than crashing |
| T-21-03-03 | Denial of Service | GPS resolution hanging the "Plan a route" tap | mitigate | The one-shot `firstWhere((p) => p != null)` is `timeout(Duration(seconds: 4))`-bounded and try/caught; on timeout/error it falls back to a non-GPS center so the entry never dead-locks |
| T-21-03-SC | Tampering | package installs | accept | No installs — reuses `go_router`, `font_awesome_flutter`, `geolocator` (via provider), `maplibre`, `flutter_riverpod`, all already in `pubspec.yaml` (RESEARCH Package Legitimacy Audit: N/A) |
</threat_model>
