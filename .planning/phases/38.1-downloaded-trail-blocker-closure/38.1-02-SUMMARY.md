**Extracted the single owner-scoped live-capture predicate (isLiveCaptureRow/isOwnLiveCapture/ownLiveCaptureProvider), made deleteLocalTrailRow report whether it matched a row, and gated applyServerTrailToLibraryRow's waypoint pruning on a new waypointsAreAuthoritative flag wired through the D-13 save trigger.**

## Accomplishments
- Built the ONE owner-scoped live-capture rule (`isLiveCaptureRow`) that CR-01 and CR-03 both need, with an owner-scoped query wrapper (`isOwnLiveCapture`) that deliberately never calls `toModel()`, and a single Riverpod handle (`ownLiveCaptureProvider`) exposing it to both UI surfaces plans 03/04/05 will wire
- Made `deleteLocalTrailRow` honest: it now returns `bool`, so a caller can distinguish "matched and removed" from "no row owned by this account carried this localId" -- closing the store half of CR-01
- Closed CR-02: `applyServerTrailToLibraryRow` no longer unconditionally prunes waypoints absent from a server response that may itself be known-incomplete (`TrailSaveResult.hadWaypointFailures`); the D-13 save trigger now declares its list non-authoritative on any waypoint failure, and the D-14 fetch trigger is untouched so WR-05 does not regress
- Added real (non-`Store`) unit tests for `isLiveCaptureRow` distinguishing the CR-01/CR-03 overlap row from a plain downloaded row, and a new source-gate test file (`local_trail_scoping_gate_test.dart`) pinning all three store-level invariants this plan introduces
