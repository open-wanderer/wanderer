<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shared `TrailEntity` row → per-account UI model | `TrailEntity.id` is `@Unique(onConflict: replace)`, so the download writer and the capture writer target ONE row. `toModel()` copies `owner`-less fields (`localId`, `syncState`) with no owner filter, so account B can be handed account A's capture bookkeeping. Every predicate in this plan exists at this boundary. |
| partial network response → local persistence | `TrailSaveResult.trail.expand.waypointsViaTrail` omits every waypoint whose save threw. Treating it as a complete set at the persistence boundary destroys local data. |

| T-38.1-01 | Tampering | `_allowDelete` escape hatch reachable by a non-owning account (cross-account destruction of account A's unsynced capture) — severity high | mitigate | Task 1 provides `isOwnLiveCapture`, which consults the ROW's `owner` and `syncState` via an owner-scoped query and never the caller's `Trail` model. Plan 05 wires it into `_allowDelete`. |
