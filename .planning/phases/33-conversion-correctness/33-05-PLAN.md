<objective>
Close VERIFICATION gaps 2 and 3 (CR-01 and CR-03, both BLOCKER), which are two halves of the
same defect in the trail-edit crop panel:

- The guard added by 33-03 checks `!Number.isFinite(rawRouteTotal)`, which is dead code
  (the total is always finite) and misses the condition that actually breaks:
  `rawRouteTotal === 0`, or a merely *coincident* leading point pair. In both cases
  `getCoordinateAtDistance()` divides `0 / 0` and returns `[NaN, NaN, 1]`, which throws
  inside MapLibre's `LngLat.convert` on crop-panel open (`DoubleSlider` fires
  `onupdate([0, 100])` unconditionally on mount).
- That same early `return` exits before `croppedGPX` is reassigned, and nothing anywhere
  resets it, so `confirmCrop()` can silently replace the user's current route with a crop
  of a route they already discarded.

Fix both, and make the fix testable: the interpolation currently lives inside a `.svelte`
component's script block where Vitest cannot reach it, which is why the defect shipped with
no test. Extract it to a pure co-located module, regression-test the two exact fixtures the
verification reproduced, then wire the component to the fixed version.

Purpose: no uncaught exception on a routine GPS artefact, and no silent data loss of a
user's route.
Output: `web/src/lib/models/gpx/crop.ts` + `crop.test.ts`, and a corrected
`updateCropMarkers()` / `confirmCrop()` / `croppedGPX` lifecycle in the trail-edit page.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-supplied / Valhalla-generated route geometry -> `updateCropMarkers()` -> MapLibre `LngLat.convert` | Untrusted-shaped numeric data (coincident points are a routine GPS artefact) crosses into a third-party library that throws on `NaN`. This is the boundary the gap-2 defect sits on. |
| Cached derived state (`croppedGPX`) -> `setRoute()` -> the user's saved trail geometry | A stale cache crossing this boundary destroys user data. This is the gap-3 defect. |

Everything in this plan is browser-side editor logic. It adds **no network call, no new
endpoint, no new persistence path, no new authentication or authorization surface, and no
new dependency** — `crop.ts` is a pure function module with a single type-only import. The
honest reading is that this plan *removes* attack surface (an uncaught exception and a
data-loss path) rather than adding any.
