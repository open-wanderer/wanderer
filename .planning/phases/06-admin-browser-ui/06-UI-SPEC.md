# Phase 6 — UI Design Contract

> Visual and interaction contract for the Federation Admin Browser UI.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Delivery format:** Go-embedded single-file HTML at `db/routes/federation_ui.html`.
> Reactivity via Alpine.js CDN. Styling via Tailwind CSS Play CDN.
> No build step. No shadcn. No React.

---

## Design System

| Property | Value | Source |
|----------|-------|--------|
| Tool | none (Tailwind Play CDN inline) | CONTEXT.md D-07 |
| Preset | not applicable | — |
| Component library | Alpine.js (CDN, no components library) | CONTEXT.md D-06 |
| Icon library | None — use Unicode symbols or inline SVG | default |
| Font | system-ui, -apple-system, sans-serif (no IBMPlexSans — not available at `/federation/` route) | default |

> **Font note:** IBMPlexSans is served from the SvelteKit app at `/fonts/*`. The `/federation/` route
> is a standalone Go handler with no access to those static assets. Use the system font stack instead.
> The PocketBase admin panel itself uses the system stack — this is consistent with the aesthetic goal.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Tailwind Class | Usage |
|-------|-------|---------------|-------|
| xs | 4px | `p-1` / `gap-1` | Icon gaps, badge padding |
| sm | 8px | `p-2` / `gap-2` | Compact element spacing, table cell padding |
| md | 16px | `p-4` / `gap-4` | Default card/form padding, input padding |
| lg | 24px | `p-6` / `gap-6` | Section padding, card gaps |
| xl | 32px | `p-8` / `gap-8` | Page-level horizontal padding |
| 2xl | 48px | `py-12` | Top-of-page vertical breathing room |
| 3xl | 64px | not used | Out of scope for this dense admin UI |

Exceptions:
- Touch targets for action buttons: minimum `h-8 px-3` (32px height) for inline table buttons
- Primary action buttons: `h-10 px-4` (40px height) matching `btn-primary` in Wanderer components.css

## Typography

The page uses system fonts. All sizes are declared in `rem` equivalents via Tailwind classes.

| Role | Tailwind Class | Size | Weight | Line Height | Usage |
|------|---------------|------|--------|-------------|-------|
| Body | `text-sm` | 14px | 400 (normal) | 1.5 | Table cell content, form labels, descriptions |
| Column header | `text-xs uppercase tracking-wide` | 12px | 400 (normal) | 1.5 | Table column headers — visually differentiated by size/case, not weight |
| Heading | `text-xl font-semibold` | 20px | 600 (semibold) | 1.2 | Page title ("Federation Peers") |
| Display | `text-xs` | 12px | 400 (normal) | 1.4 | Status badges, direction tags, metadata counts |

> Two weights in use: **400** (body/display/column headers) and **600** (headings/CTAs).
> Column headers are differentiated visually via `text-xs uppercase tracking-wide` — no weight bump needed.

### Table Row — Action Button Rules

Render ONLY the buttons valid for the row's state:

| Condition | Buttons Rendered |
|-----------|-----------------|
| `status=pending AND direction=inbound` | Approve (accent) + Reject (destructive) |
| `status=accepted` (any direction) | Disconnect (destructive) |
| `status=pending AND direction=outbound` | Pending indicator (text only, no button) |
| `status=rejected` | Row shown greyed out; no action buttons |

Rejected peers ARE shown in the table (not filtered out) so the admin can see historical state.
They render with `opacity-60` on the row.

### Loading State

Alpine `x-show="loading"` controls a spinner span inline with the triggering button.
Spinner: `<span class="inline-block w-4 h-4 border-2 border-white border-t-transparent rounded-full animate-spin"></span>`

Each action button disables during its in-flight request: `:disabled="loading"`.

## Interaction Contracts

### Discovery Flow

1. Admin types or pastes URL into input, clicks "Discover".
2. Button shows inline spinner, becomes disabled.
3. On success: preview card appears below the input with domain/version/counts + Clear + Connect buttons.
4. On error: inline error text appears below the input (`text-red-500 text-sm`). No modal. No toast.
5. Clear: preview card hidden, URL input cleared.
6. Connect click: calls `POST /federation/follow`, resets form, peer list re-fetches.

### Approve / Reject Flow

1. Admin clicks "Approve" or "Reject" on an inbound-pending row.
2. Button disables + spinner.
3. On success: peer list re-fetches (row status updates).
4. On error: inline error text in the Actions column of that row.

### Disconnect Flow

1. Admin clicks "Disconnect".
2. `window.confirm("Disconnect from <domain>? This will send an Undo{Follow} or Reject{Follow} to the remote instance.")` fires.
3. If cancelled: no API call.
4. If confirmed: button disables + spinner, `POST /federation/disconnect/:id` called.
5. On success: peer list re-fetches (row removed or status changes).
6. On error: inline error in Actions column.

### Auth Redirect Flow

1. Page load: JS reads `localStorage.getItem("__pb_superusers__/_")`.
2. If missing or expired: `window.location.replace("/_/")` immediately.
3. If valid: token attached as `Authorization: <token>` on all fetch calls.
4. On any API 401: redirect to `/_/`.

## Accessibility Contract

- All interactive elements reachable by keyboard (Tab order: URL input → Discover → Connect → table rows with action buttons).
- Action buttons have `aria-label` when icon-only. All buttons in this spec use text labels — no icon-only buttons.
- Status badges and direction badges use inline text (not color alone) to convey meaning.
- `window.confirm()` is the destructive confirmation mechanism (specified in CONTEXT.md D-15) — no custom modal needed.
- Form inputs have associated `<label>` elements (even if visually hidden with `sr-only`).
- Spinner `<span>` elements include `aria-hidden="true"` since button text remains visible.
