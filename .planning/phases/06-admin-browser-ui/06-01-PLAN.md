## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Phase 5 federation API | Admin-supplied URLs and actor_ids cross here; every request carries the superuser JWT in the Authorization header |
| PocketBase admin localStorage → page JS | The page reads (never writes) the superuser token written by `/_/`; same-origin only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Information Disclosure | superuser token in localStorage | accept | localStorage is same-origin; the page is served from the same Go binary/origin as the API; the page only reads, never transmits the token off-origin (Authorization header goes to same-origin endpoints) |
| T-06-02 | Tampering (XSS) | peer.domain / api error rendering in `federation_ui.html` | mitigate | Render all server-derived values (peer.domain, status, direction, data.error) with Alpine `x-text` which sets textContent, never `x-html`; do not introduce `x-html` anywhere in the file |
| T-06-03 | Elevation of Privilege | direct API call bypassing the page | accept | The page is not a security boundary; `e.HasSuperuserAuth()` in every Phase 5 handler is the hard gate (verified in federation_admin.go); a non-superuser token receives 401 and the page redirects to /_/ |
| T-06-04 | Spoofing | regular Wanderer user token used at /federation/ | mitigate | Page-side `isTokenExpired` + 401-redirect is UX only; the API's HasSuperuserAuth rejects non-superuser tokens server-side (DASH-02) |
| T-06-SC | Tampering | npm/pip/cargo installs | mitigate | No packages installed this phase; Alpine.js and Tailwind are CDN `<script>` tags only (RESEARCH.md Package Legitimacy Audit — both Approved, no [ASSUMED]/[SUS]); no legitimacy checkpoint required |
</threat_model>
