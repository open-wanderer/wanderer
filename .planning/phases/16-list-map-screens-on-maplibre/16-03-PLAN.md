<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cluster response → `GeoJsonSource` | The FeatureCollection is jsonEncoded and handed to the native source; a malformed body must fail soft, not crash the map. |
| `properties['id']` → trail lookup | The cluster feature's `id` indexes `mapTrailSearchProvider`'s results; treat as untrusted. |
| `apiProvider` (authenticated) → cluster/search/polyline endpoints | Requests must keep going through the existing auth interceptor; no hand-built bypass. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-02 | Denial of Service (client) | `onStyleLoaded` jsonEncode + `GeoJsonSource`/`updateGeoJsonSource` | mitigate | Wrap the encode+source-construct in a `try/catch` that logs and no-ops (Task 1); the provider already surfaces parse failures as `AsyncError` (16-02). Fail soft to an empty source, never crash the map. |
| T-16-01 | Tampering | `properties['id']` → `mapTrailSearchProvider` lookup | mitigate | Use `firstWhereOrNull` (never `firstWhere`) when resolving a tapped trail id to full metadata (Task 2); a missing/unexpected id skips the marker/selection instead of throwing. |
| T-16-03 | Information Disclosure / Access Control (V4) | category/subcategory filter | accept | Preference + `is_large` filtering is server-enforced; the screen keeps sending the authenticated request via `apiProvider` and the correct `filterText` — no client bypass (Task 1). |
