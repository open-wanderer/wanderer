# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** This is a Flutter (Material 3) mobile phase, not a web/React phase. There is no shadcn/Radix/Tailwind layer here. The visual contract is expressed through Flutter's Material widgets and the project's `AppTheme` / `ColorScheme`. shadcn initialization gate is **not applicable** (non-React stack). All values below are derived from existing project conventions (`app/lib/theme/theme.dart`, `app/lib/theme/colors.dart`, `settings_screen.dart`, `settings_appearance_screen.dart`) — this phase must visually match those screens, not introduce new design language.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | n/a this phase |
| sm | 8px | n/a this phase |
| md | 16px | Vertical gap above logout button (`SizedBox(height: 16)`) — existing pattern |
| lg | 24px | n/a this phase |
| xl | 32px | Horizontal padding around logout button (`EdgeInsets.symmetric(horizontal: 32.0)`) — existing pattern |
| 2xl | 48px | n/a this phase |
| 3xl | 64px | n/a this phase |

**Material defaults govern in-row spacing.** `ListTile`, `RadioListTile`, and `SwitchListTile` supply their own internal padding (16px horizontal content insets, 56px min row height for icon rows). Do NOT override these — matching the existing `SettingsScreen` and `SettingsAppearanceScreen` means accepting Material defaults.

Exceptions:
- Leading list icons are fixed at `size: 18` (FaIcon) to match the existing `SettingsScreen` rows (e.g. `FaIcon(FontAwesomeIcons.circleUser, size: 18)`). This is an icon glyph size, not a layout spacing token.
- Units `Text` section label on the Language screen: use `ListTile`-aligned padding (`EdgeInsets.fromLTRB(16, 16, 16, 8)`) so the label aligns with `RadioListTile` titles above it and reads as a group break.

## Typography

Typography is inherited from the Material 3 `TextTheme` (font family IBMPlexSans). Do not hardcode `fontSize` — use `TextTheme` roles so light/dark and accessibility scaling work. The roles below map to the Material 3 defaults this phase relies on.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (list tile title) | 16px (`titleMedium`) | 500 (medium) | 1.5 |
| Label (units section header) | 14px (`titleSmall`, color `onSurfaceVariant`) | 500 (medium) | 1.43 |
| Heading (AppBar title) | 22px (`titleLarge`) | 400 (regular) | 1.27 |
| Display | not used this phase | — | — |

- `ListTile.title` / `RadioListTile.title` / `SwitchListTile.title` → `titleMedium` (Material default). Language native-name labels render at this role.
- `AppBar.title` (`l10n.language`) → `titleLarge` (Material default).
- Only two effective weights appear: regular (400) for the app bar title and medium (500) for list/tile titles — within the 2-weight ceiling.

## Color

Colors come exclusively from `Theme.of(context).colorScheme` (defined in `app/lib/theme/colors.dart`). Light values shown; dark-mode equivalents resolve automatically via `ColorScheme.brightness`. No new colors are introduced this phase.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` light / `#12141C` dark (`colorScheme.surface`) | Scaffold background, list surface |
| Secondary (30%) | `#E5E7EB` light / `#2D3241` dark (`colorScheme.secondary`); divider `#D1D5DB` / `#374151` | Divider rule, secondary button fill |
| Accent (10%) | `#242734` light / `#3E435B` dark (`colorScheme.primary`) | Selected-control tint only |
| Destructive | not used this phase | No destructive actions in Phase 6 |

Accent reserved for: **the selected/active state of interactive controls only** — `RadioListTile.activeColor` (selected language radio) and `SwitchListTile` active thumb/track (imperial-on / metric toggle). Per the existing `SettingsAppearanceScreen` rule, `activeColor` resolves to `colorScheme.onSurface` in dark mode and `colorScheme.primary` in light mode; the Language screen MUST replicate this exact `activeColor` derivation. Accent is NOT applied to list text, chevrons, leading icons, or the app bar.

- Leading FaIcons and `Icons.chevron_right` trailing affordances inherit default `onSurface`/icon theme color — they are not accent-tinted (matches existing `SettingsScreen`).
- Logout button uses the existing `WandererButton(secondary: true)` styling — unchanged, not re-specified here.

## Copywriting Contract

All user-facing strings come from ARB localization keys (already present in `app/lib/i18n/app_en.arb`) — no hardcoded English in widgets, with the single documented exception of native language names. This phase has no empty state, no error UI, and no destructive action.

| Element | Copy |
|---------|------|
| Primary CTA | None — this phase is auto-save on selection (D-12). No Save/Submit button exists. |
| Empty state heading | Not applicable — the language list is a fixed 14-item set; it is never empty |
| Empty state body | Not applicable |
| Error state | Not applicable in-screen — save failures surface through the existing `settingsProvider` / toast mechanism; no new error UI is introduced this phase |
| Destructive confirmation | Not applicable — no destructive actions in Phase 6 |

**Native-name exception is intentional and contract-approved:** a language's own name must read in its own script regardless of the active UI locale, so these are hardcoded rather than localized (per D-09). This is the only permitted hardcoded string set in the phase.

### Interaction contract

- **Settings list row order (D-06):** Account → Privacy → Language → Notifications → Appearance → `Divider` → Logout. Flat list, no section headers.
- **Row anatomy (match existing):** `ListTile` with `leading: FaIcon(size: 18)`, `title: Text`, `trailing: Icon(Icons.chevron_right)`, `onTap: context.push('/settings/<route>')`.
- **New row icons (D-07):** Privacy → `FontAwesomeIcons.lock`; Language → `FontAwesomeIcons.globe`; Notifications → `FontAwesomeIcons.bell`. (Account → `circleUser`, Appearance → `palette` already exist.)
- **Language picker (D-08):** `RadioGroup<String>` wrapping a scrollable `ListView` of 14 `RadioListTile`s — structurally identical to `SettingsAppearanceScreen`. `activeColor` derived exactly as in that screen.
- **Units control (D-10):** A `Text(l10n.units)` section label below the language list, then a single `SwitchListTile` (`value: settings?.unit == 'imperial'`, metric = off-position, imperial = on-position). Switch, not radio.
- **Save behavior (D-12):** Selecting a language or toggling units triggers `settingsProvider.saveToServer()` immediately. No Save button, no confirmation dialog. Selection state reflects optimistically via the watched provider (matches Appearance screen's immediate `ThemeMode` update).
- **Live locale switch (D-01):** A language selection updates `MaterialApp.router`'s `locale:` via `localeProvider`; visible UI strings (app bar title, row labels) re-render in the chosen locale on the same frame. Native language names do not change.
- **Stub screens:** `SettingsPrivacyScreen` and `SettingsNotificationsScreen` render a minimal `Scaffold` + `AppBar` (back button + localized title) only — no body content this phase. They must still look intentional (titled app bar, themed background), not a blank white screen with no chrome.
