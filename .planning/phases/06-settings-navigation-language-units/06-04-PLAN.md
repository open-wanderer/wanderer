    - app/lib/i18n/app_en.arb (the template — 486 keys, snake_case; the authoritative key set to iterate over)
    - app/lib/i18n/app_de.arb (existing translated ARB — structure to mirror: `@@locale` header + flat snake_case keys, NO `@key` metadata blocks in the non-template files)
    - app/lib/l10n.yaml (config: arb-dir `lib/i18n`, template `app_en.arb`, output `app_localizations.dart`)
    - web/src/lib/i18n/locales/fr.json (representative web source — kebab-case keys e.g. `account-delete-confirm`; values are the translation source)
    - .planning/phases/06-settings-navigation-language-units/06-RESEARCH.md (Pitfall 3 + Assumption A1: kebab↔snake mapping, ICU plural syntax is byte-identical, omit unmatched keys for English fallback)
  </read_first>
  <action>
    Create one ARB file per missing locale: `app_cs.arb`, `app_es.arb`, `app_eu.arb`, `app_fr.arb`, `app_hu.arb`, `app_it.arb`, `app_nl.arb`, `app_no.arb`, `app_pl.arb`, `app_pt.arb`, `app_ru.arb`, `app_zh.arb`. Each file (D-02):

    1. Starts with a `"@@locale": "<code>"` header (e.g. `"@@locale": "fr"`).
    2. Is iterated keyed off the **`app_en.arb` key set (the 486 template keys)** — NOT the web JSON key set. For each ARB key, compute its kebab-cased equivalent (replace every `_` with `-`) and look it up in the matching `web/src/lib/i18n/locales/<code>.json`. If the web JSON has that key, copy its translated string value into the ARB under the original snake_case key. If the web JSON does NOT have it, OMIT the key entirely — gen-l10n auto-fills the missing key from the English template at generation time, which satisfies D-02 (untranslated strings fall back to English).
    3. Does NOT include `@key` metadata/description blocks (only the template `app_en.arb` carries those; translation ARBs are flat key→value).
    4. Preserves ICU plural/select syntax verbatim — it is identical between the web JSON and ARB (verified on the `activity` plural key). Where a value contains `{count, plural, ...}` or named placeholders like `{name}`, copy the braces and placeholder names exactly so they match the template's placeholder declarations.

    Chinese (`zh`): port from the single `web/src/lib/i18n/locales/zh.json` (no script subtag — match the web client's single `zh` file per RESEARCH Open Q3).

    After all 12 files exist, run `flutter gen-l10n` (from `app/`) to regenerate `app_localizations.dart` and the per-locale `app_localizations_<code>.dart` files. This is what makes `AppLocalizations.supportedLocales` (wired in Plan 01's `main.dart`) include all 14 locales. Commit the regenerated `.dart` artifacts alongside the ARB files. Do NOT edit `app_en.arb` or `app_de.arb`.

    Note: gen-l10n is permissive about partial translation by default (Assumption A3 — `l10n.yaml` sets no strict untranslated handling). Warnings about untranslated messages are expected and acceptable; build errors (malformed JSON, placeholder mismatch) are not.
  </action>
