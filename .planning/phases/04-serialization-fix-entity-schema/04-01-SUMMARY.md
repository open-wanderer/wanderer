## Accomplishments
- `_$NavigateResponseToJson` now emits `'maneuvers': instance.maneuvers.map((e) => e.toJson()).toList()` instead of the opaque `instance.maneuvers`, so `jsonEncode` no longer throws at runtime.
- Added a `group('NavigateResponse roundtrip')` with 4 cases (full-field, empty maneuvers, empty shape, required-only-with-@Default) — each runs `jsonEncode(toJson()) -> jsonDecode -> fromJson` end to end.
- All 9 tests pass (5 original `fromJson` + 4 new roundtrip); the original group is unmodified — no regression.
- ObjectBox `navCacheJson` caching (Phase 5) is now unblocked.

## Decisions Made
- **Annotation placement corrected to the constructor.** The plan (D-01) specified placing `@JsonSerializable(explicitToJson: true)` above `@freezed` at the class level. In freezed 3.2.5 that makes json_serializable run against the abstract class and fails with "Cannot populate the required constructor argument: maneuvers". The freezed 3.x README (lines 935-947) documents the correct location as the factory constructor. Applied there instead; outcome is identical (explicitToJson honored) with working codegen.
- **No project-wide build.yaml.** Chose the constructor annotation over a global `explicit_to_json: true` in build.yaml to keep the fix scoped to `NavigateResponse` and avoid regenerating every model's `.g.dart`.
