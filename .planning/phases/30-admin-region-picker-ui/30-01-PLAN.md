## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser (localStorage superuser JWT) -> PocketBase collection REST API | The page reads the /_/ dashboard's own `__pb_superusers__/_` token and attaches it as the Authorization header on every collection call; PocketBase validates it server-side |
| Go handler -> admin browser | The handler ships one static HTML blob plus response security headers (CSP, X-Frame-Options); no per-request business logic or secrets |
| seed-derived region `name`/`path` -> rendered tree DOM | CoMaps catalog strings are injected into the page as text nodes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-01 | Spoofing / Elevation of Privilege | superuser auth on /region-catalog/ | mitigate | No new auth mechanism: the page reads the existing PocketBase `_superusers` JWT from same-origin localStorage; the real access boundary is PocketBase validating that JWT on every /api/collections/regions call. Both collections keep their default (nil = superuser-only) API rules from the Phase 28 migration. The route is a bare se.Router.GET NOT wrapped in apis.RequireAuth() (which would admit any authenticated end user); a missing/expired token shows the log-in CTA and no data loads. |
| T-30-02 | Tampering | clickjacking of the admin page | mitigate | Set `X-Frame-Options: DENY` and CSP `frame-ancestors 'none'` on the handler (carried forward from federation_ui.go) so the page cannot be framed into a decoy. |
| T-30-03 | Tampering / Information Disclosure | region `name`/`path` rendered in the tree | mitigate | Render every region name/path with Alpine `x-text` (auto-escaped); never `x-html`. Verified by the `grep -c 'x-html' ... == 0` gate. Names originate from the static maintainer-curated CoMaps seed, defense-in-depth regardless. |
