# Phase 15 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note — Read First

This is a **Flutter (`app/`) native-map port phase**, not a web/React/shadcn phase.

- **shadcn gate: not applicable.** Tech stack is Flutter/Dart + native MapLibre GL (`maplibre` 0.3.5). There is no `components.json`, no Tailwind, no React. The shadcn initialization gate was skipped by design (it only fires for React/Next.js/Vite projects). `Tool: none`.
- **The web brand system (`PRODUCT.md` / `DESIGN.md`, "The Terrain Log", IBM Plex Sans, Polar Night) does NOT govern this phase.** Those documents describe the SvelteKit web app's surface. This phase renders the Flutter app's map layers, whose visual identity is defined by (a) the pre-existing 7,677-line MapLibre Style Spec v8 basemap JSON being ported verbatim, and (b) the existing `flutter_map`-based marker/line widgets being ported to native GL layers with visually-equivalent output.
- **This phase does NOT redesign anything.** The contract below is overwhelmingly "**port these exact pixel/color/spacing specs from the current implementation**," extracted from `app/lib/components/map/trail_layer.dart`, `app/lib/components/base/wanderer_map.dart`, and the `wandererLightTheme`/`wandererDarkTheme` style documents. The one genuinely new visual surface is the attribution/scale-bar control (CORE-04), which uses MapLibre's built-in default control unstyled.
- **No new copywriting, CTAs, forms, or empty states are introduced.** The only user-facing text is (a) MapLibre's default attribution string and (b) an offline tile-load error passthrough that already exists. These are captured in the Copywriting Contract with explicit N/A markings for the template rows that don't apply.

Because every field below is answered by locked CONTEXT.md decisions (D-01..D-10) or is extractable verbatim from source, no design questions were asked.

## Basemap Style Contract (STYLE-01..04)

The basemap is **ported, not designed**. The 7,677-line `wandererLightTheme(tileUrl)` / `wandererDarkTheme(tileUrl)` Dart `Map` literals become plain `.json` assets whose **rendered output must be equivalent to today's** (colors, layer styling, label placement all preserved verbatim).

| Aspect | Contract |
|--------|----------|
| Extraction fidelity (STYLE-01) | Rendered output equivalent to current `wandererLightTheme`/`wandererDarkTheme`. Do not re-color, re-order, or re-style any layer. Extraction mechanism (programmatic dump vs. manual port) is planner's discretion. |
| Tile source injection (STYLE-02) | Operator's `TILE_SERVER_URL` (via `/map/style-sources`) injected into the style's `protomaps` source at runtime. Operator control preserved. |
| Glyphs key (STYLE-03) | Style carries a `glyphs` key; its 14 symbol layers render labels in all 4 fontstacks above, including the data-driven Devanagari-script case. |
| Sprite key (STYLE-04) | Style carries a `sprite` key; the `arrow` icon and route-network shield icons render (both are silently dropped today). Light and dark sprite variants both cached. |
| Theme swap (CORE-02) | Light/dark map style swaps **live** when the app theme changes — no reload, no flash. Two full style docs, one per theme. |

## Offline Rendering Contract (OFFL-01..06, GLYPH-04)

No new visual surface — parity requirement. A downloaded trail in airplane mode must render **identically** to its online counterpart (basemap + labels + icons + track + markers).

| Aspect | Contract |
|--------|----------|
| Glyph/sprite cache scope (GLYPH-04, D-08) | One shared **app-wide** cache (not per-trail). Full set: all 4 fontstacks × complete 256-range set, plus both light & dark sprite themes. |
| Cache-warm trigger (D-09/D-10) | Lazy. Whichever of {first map open, first trail download} happens first performs the fetch; the other is a no-op against the warm cache. |
| Offline style rewrite (OFFL-02) | Rewrite `glyphs` + `sprite` keys to `file://` paths before handing the style to the map. |
| Offline basemap (OFFL-03/05) | Render from `.pmtiles` via native `pmtiles://`, every cell when a trail spans several. |
| Offline label parity gate (OFFL-04) | Labels render from `file://` glyphs with no network — **the milestone's hard gate**, validated on a physical device in airplane mode (see Risk Gate note below). |
| Cache reuse (OFFL-01) | Second trail download reuses cache; no re-fetch. |
| Storage location | Planner's discretion (ObjectBox vs. app-documents plain files); follow the existing `.pmtiles` storage convention rather than inventing a new one. |

> **Risk gate (D-01..D-03):** The first plan of this phase is a throwaway `file://` glyph-resolution spike, validated by the user on a **physical device** (not simulator). No fallback is pre-decided; a failure stops and returns the actual error mode to the user. Nothing visual downstream is contractually safe until this passes.

## Spacing Scale

Native map symbol/line dimensions are **pixel-exact ports**, not an 8-point UI scale — the standard 4/8/16/24/32 web token ladder does **not** govern MapLibre symbol sizing. The load-bearing dimensional tokens for this phase are the map-layer sizes above. Declared for the checker:

| Token | Value | Usage |
|-------|-------|-------|
| Elevation marker | 12 px | Scrub-position dot (TRAIL-05) |
| Arrow marker | 18 px (glyph ~6 px) | Directional arrows (TRAIL-02) |
| Start/finish pin | 28 px | Trailhead/terminus pins (TRAIL-04) |
| Waypoint marker | 32 px | Tappable waypoints (TRAIL-03) |
| Route line | 5 px + 2 px casing | Track line (TRAIL-01) |
| Marker border | 2 px | All circular markers |
| Camera fit padding | 40 px (`EdgeInsets.all(40)`) default | Initial bounds fit (CORE-03) |
| Proximity nudge threshold | 36 px | Start/finish separation trigger (TRAIL-04) |

Exceptions: this entire table **is** the exception — map-native pixel sizes, not the 8-pt UI ladder. App chrome (if any) follows the existing app default spacing.

## Color

Basemap colors are **ported verbatim** from `wandererLightTheme`/`wandererDarkTheme` (the near-monochromatic Polar Night dark theme + its light counterpart). The web 60/30/10 doctrine does not apply to native map rendering. The load-bearing overlay colors for this phase:

| Role | Value | Usage |
|------|-------|-------|
| Basemap surface (dominant) | per ported style JSON (light + dark) | Map background, land, water, roads, labels — NOT redesigned |
| Route line (accent) | `#3549bb` (default, `routeColor`-overridable) | The GPX track line only |
| Casing / marker fill | `#FFFFFF` | Track casing, unselected pin fill, arrow glyph, elevation-marker fill, selected-waypoint fill |
| Waypoint accent | theme `primaryColor` | Waypoint marker fill (unselected) / icon+border (selected) |
| Start-pin semantic | `Colors.greenAccent` | Trailhead pin only |
| Finish-pin semantic | `Colors.redAccent` | Terminus pin only |
| Elevation-marker border | `#000000` | 2px border on the scrub dot only |

Accent reserved for: the route line (`#3549bb`) is reserved for the GPX track; `greenAccent`/`redAccent` are reserved exclusively for start/finish pins respectively. No accent bleeds into basemap or chrome.
