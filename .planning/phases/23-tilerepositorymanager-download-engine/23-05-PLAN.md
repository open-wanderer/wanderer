<objective>
Finish the download engine's query and teardown surface, then wire it into Riverpod. Add `localTilePathsForBounds(bbox)` (TILE-05) so map rendering (Phase 25) can ask "which downloaded region files cover this viewport" via a pure, tested axis-aligned bbox-overlap test — there is no `intersects()` on the app's `LngLatBounds` type, so this is hand-rolled against `RegionEntity`'s four bbox doubles. Add `deleteRegion` that removes both package rows and their on-disk files as one unit (ObjectBox does not cascade). Then add the Riverpod seam: a construction-only `tileRepositoryManagerProvider` (mirroring `regionRepositoryProvider`) and a `keepAlive` `TileRepositoryStatus` notifier exposing per-region download state for Phase 24's UI (mirroring `DownloadingTrailIds`).

Purpose: TILE-05 unblocks Phase 25's viewport pipeline; the delete cascade completes TILE-01's lifecycle; the provider seam is what Phase 24's Settings UI subscribes to. All the new pure logic (`bboxOverlaps`, `RegionDownloadState` equality) is unit-tested; the store/network orchestration is verified on-device in Plan 06.
Output: `localTilePathsForBounds` + `bboxOverlaps` + `deleteRegion` on the manager, `region_download_state.dart`, `tile_repository_provider.dart`, generated code, and unit tests.
</objective>
