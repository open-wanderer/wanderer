<objective>
Fix the two SvelteKit region-archive proxy routes so HTTP Range requests survive end-to-end. Today both routes drop the client's incoming `Range` header and hardcode `status: 200` on the response, so a resumed download silently receives the entire file again — defeating TILE-02 even when the Flutter client is correct. The Go backend (`db/routes/regions_get.go`, PocketBase `e.FileFS`) already serves Range requests; the gap is only in the passthrough layer the app actually talks to.

Purpose: This is the hard, load-bearing prerequisite for the whole phase's resumable-download requirement (TILE-02). Without it, Plan 04's Flutter resume code is unverifiable against a real resumed download.
Output: Both proxy routes forward the incoming `Range` header inbound and forward the upstream `status` (200 or 206) plus `Content-Range`/`Accept-Ranges`/`Content-Length` outbound; two vitest tests prove the behavior.
</objective>
