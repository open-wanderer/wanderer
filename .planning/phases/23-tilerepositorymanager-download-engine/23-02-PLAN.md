<objective>
Lay the Dart foundation the download engine builds on: append the two new persisted status values this phase needs (`paused` for backgrounding/user-pause, `error` for a failed/corrupt download) to `PackageStatus` and `RegionStatus` using the append-only explicit-`.code` contract Phase 22 established, update `RegionEntity.status` so its switch handles the new package states, and create a `region_file_path.dart` path-safety utility that validates a catalog region id against the backend's own `^[a-z0-9][a-z0-9_-]*$` allow-list before turning it into an on-disk directory name.

Purpose: The enum values and the path-safety helper are consumed by every later plan; getting the append-only int contract and the traversal guard right here (both pure, fully unit-testable) avoids a data-corruption class of bug and a path-traversal class of bug before any I/O code depends on them.
Output: Extended `region_status.dart`, updated `RegionEntity.status` getter, new `region_file_path.dart`, and unit tests for all three.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Fetched catalog → on-disk path | Catalog `id` string flows into a filesystem directory name |
| Persisted enum int → in-memory status | An on-device row's stored `.code` is re-decoded across app versions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-01 | Tampering | region `id` → file path | mitigate | `assertValidRegionId` rejects anything not matching `^[a-z0-9][a-z0-9_-]*$` before any `p.join`; mirrors the server allow-list (RESEARCH Pitfall 4) |
| T-23-05 | Tampering | persisted PackageStatus `.code` | mitigate | New members appended with fresh codes (3/4, 4/5) — never renumbered; `firstWhere(orElse: notDownloaded)` degrades an unknown future code safely |
</threat_model>
