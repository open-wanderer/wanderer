<objective>
Introduce the phase's only genuinely new dependency — a disk free-space check — behind a mandatory human legitimacy gate. `disk_space_2` is `[ASSUMED]` in the research's Package Legitimacy Audit (slopcheck does not support the pub.dev ecosystem, so it could not be scanned; it is a community fork of an unmaintained original running filesystem-adjacent native code on both platforms). A human must resolve whether to add it (or an alternative) before it enters `pubspec.yaml`. Then wrap the chosen package in `disk_space_util.dart` whose *decision* logic (`hasEnoughSpace`) is a pure, unit-tested function decoupled from the plugin's exact API.

Purpose: TILE-03 requires a safety-margin disk check before each region file write; this plan delivers that primitive and isolates the unverified plugin behind a fail-closed wrapper with a tested pure core, so Plan 04 can consume `hasEnoughSpace(...)` without re-litigating the plugin choice.
Output: The approved disk-space package added to `pubspec.yaml` (post-gate), `disk_space_util.dart`, and a unit test covering the margin math and the fail-closed (unknown-free-space) path.

Note on mode: this project runs `human_verify_mode: end-of-phase`, which suppresses `checkpoint:human-verify` tasks. The legitimacy gate below is therefore a `checkpoint:decision` (still emitted in end-of-phase mode, since it gates the work itself — whether to add an unaudited dependency — rather than post-hoc verifying completed work). It is a blocking, non-auto-approvable security control per the package-legitimacy gate.
</objective>
