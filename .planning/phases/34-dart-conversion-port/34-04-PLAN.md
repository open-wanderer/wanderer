<objective>
Complete the Dart side of the port: add `trailFromGpx` (the Dart counterpart of `gpx2trail`'s
trail assembly), prove both halves against the shared on-disk corpus, and retire the app's
second, CONV-01-buggy metrics implementation so only one answer exists for a given GPX.

Purpose: PORT-01 is not satisfied by metrics alone - a draft trail also needs name, description,
waypoints, start coordinates and date. PORT-02 is only meaningful once the Dart side reads the
same fixtures the TS side does. And D-17 exists because shipping two metrics implementations
would mean a previewed-but-unsaved trail showing one distance and the saved trail another for the
same GPX - the exact CONV-01 defect this milestone exists to eliminate, surviving in a file the
corpus does not cover.

Output: `trailFromGpx` in `app/lib/util/gpx_conversion_util.dart`,
`app/test/util/gpx_corpus_test.dart`, a `GpxMappingUtils` extension with no `getTotals`, both
preview consumers on the ported function, and `trailDisplayDuration` wired into the app's three
Trail duration surfaces.
</objective>
