## D-02 is a hard constraint on how expected values are produced

For fixtures 01-09 the expected values must be derived **from first principles** and the
derivation written down in `DERIVATION.md` beside the fixture:

- Elevation gain/loss: derive by reasoning over the algorithm's stated rules (threshold 5 m,
  defer-then-publish, discard only on a horizontal-stillness return). Every one of these values
  already appears as a documented, human-reasoned expectation in
  `web/src/lib/models/gpx/gpx-metrics-computation.test.ts`, including the pre-fix value each case
  pins against. Cite that file and the reasoning; do not re-run the implementation to obtain them.
- Distance: evaluate the haversine formula independently - write the formula out fresh in a
  scratch `node -e` or `python3 -c` one-liner using `R = 6371000` - and paste the formula, its
  inputs and its result into `DERIVATION.md`. Do NOT call `GPX.getTotals()`, `gpx2trail()` or
  `GpxMetricsComputation` to obtain a distance.
- Centroid and bounding box: plain arithmetic over the fixture's own coordinates; show the sum
  and the divisor.

Fixture 10 is the only one permitted to be seeded from the corrected TS output
(`derivation: "seeded"`), and its `expected.json` must be read back and sanity-checked against
the fixture's own shape before it is committed.
