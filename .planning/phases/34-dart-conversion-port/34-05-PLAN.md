Switch all three capture paths onto the Dart conversion. Replace `convertGpxToTrail`'s HTTP POST
with a local call into the ported module, reduce `/trail/convert` to a transcode-only helper
reached only for non-GPX extensions, move the reverse-geocode step into the app as an optional

`movingDuration` field (D-09/D-11).

plan 34-07) strictly after this plan, so that when the contract changes nothing in the app still
depends on the old one.

`buildDraftTrail` without a network round trip, `_saveRecordedTrack` passing the session's
elapsed time, and tests pinning the hand-off plus a grep gate proving the single remaining
`/trail/convert` call site.

## Deliberate design note: the transcode response shim

`transcodeToGpx` accepts BOTH response shapes: a raw `application/gpx+xml` body (what plan 34-07
makes the endpoint return) and the legacy JSON body with `expand.gpx_data` (what it returns
today, before 34-07 lands). This is client tolerance, not server versioning - it keeps the app
working against a server that has not yet been upgraded, which is a real scenario for a
self-hosted product and is exactly the compatibility surface D-05's rationale describes
("self-hosters control their own server/app pairing"). It does NOT keep any legacy
trail-computing path alive on the server, so it does not contradict D-05.
