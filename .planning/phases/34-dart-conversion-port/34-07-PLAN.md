<objective>
Reduce `POST /api/v1/trail/convert` to what it is now the only thing anyone needs from it:
transcoding kml/kmz/tcx/fit into GPX. It stops parsing the GPX into a `Trail`, stops
reverse-geocoding the start point, and returns the GPX document itself.

Purpose: PORT-04. The ROADMAP sequences this last within the phase, after PORT-01 and PORT-03
have made the app self-sufficient, so nothing still depends on the old contract when it changes.
D-05 makes the change in place rather than behind a version or a negotiated content type, because
either of those would keep the legacy trail-computing path alive on the server - the exact thing
this phase exists to remove.

Output: a transcode-only `+server.ts`, a handler-level Vitest suite, and a regenerated
`wanderer.openapi.json` whose 200 response for this route is a GPX document.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Unauthenticated HTTP client -> `POST /api/v1/trail/convert` | The endpoint's existing auth posture is unchanged by this plan; the request body is fully untrusted (arbitrary file bytes or XML text). |
| Uploaded bytes -> `fromFile` (`toGeoJSON`, JSZip, `fit-parser`) | Vendored parsers process attacker-controlled input server-side. |
| Endpoint response -> the Flutter app's on-device parser | The response body is now parsed by `parseGpxSafely` on the device instead of being consumed as JSON. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-34 | Denial of Service | A malformed or hostile upload crashing or hanging the transcode step | mitigate | Unchanged and preserved: the whole handler stays inside its existing `try`/`catch` funnelling into `handleError`, and the empty-body 400 guard remains. Removing `gpx2trail` strictly reduces the server-side parsing surface - the XML-to-model parse now happens on the client instead. |
| T-34-35 | Information Disclosure | The response echoing more than the transcoded document | mitigate | The success path returns exactly the `gpxData` string produced by `fromFile` - no trail record, no user data, no geocoded place name. Removing the reverse-geocode block (D-07) also removes a server-side outbound call made on an unauthenticated request's behalf, which is a net reduction in SSRF-adjacent surface. |
| T-34-36 | Tampering (contract drift) | The published OpenAPI JSON continuing to advertise a Trail response after the handler changed | mitigate | Task 2 regenerates `wanderer.openapi.json` and the acceptance criteria assert both the removal of the convert route's `schemas/Trail` `$ref` and the survival of plan 34-02's `moving_duration` additions. |
| T-34-37 | Repudiation / availability | An older app build breaking on kml/kmz/tcx/fit import after the hard break | accept | Explicitly accepted by D-05: the blast radius is narrow (non-GPX import only, old builds only), it fails loudly at import time rather than corrupting data, and self-hosters control their own server/app pairing. Plan 34-05's dual-shape `transcodeToGpx` additionally means a NEW app build works against an OLD server, so only the old-app/new-server direction breaks. |
| T-34-38 | Tampering (response confusion) | A client treating a JSON error body as a GPX document | mitigate | D-06: errors keep the `handleError` JSON shape and a non-200 status, and `transcodeToGpx` only reads a body on success, throwing a `StateError` when neither shape yields a non-empty GPX string. |
| T-34-39 | Denial of Service | An unbounded upload to an unauthenticated endpoint | accept | Unchanged posture: the endpoint's authentication and body-size handling are exactly as they were before this plan, which only alters the success-path response shape. Out of scope per 34-CONTEXT.md. |
| T-34-SC | Tampering (supply chain) | npm/pip/cargo/pub installs | n/a | No package-manager install task exists in this plan. `npm run openapi:generate` runs an already-installed dev dependency. 34-RESEARCH.md § "Package Legitimacy Audit" records "Not applicable". |
</threat_model>
