<objective>
Make `GET /api/v1/regions` hierarchy-aware (EXTRACT-03) and finish retiring the `region_config.json` loader (EXTRACT-02) now that the cron (29-01) no longer needs it.

Purpose: expose each region's `parent`, `path`, and `depth` (plus `kind`) so a client can reconstruct the catalog tree from a flat response (Phase 31's Flutter hierarchy is the downstream consumer). The change must be strictly additive for existing leaf entries so the already-shipped Flutter offline-regions feature (`RegionCatalogEntry.fromJson`) is not regressed. Removing `LoadRegionCatalog`/`Region`/`ValidateRegion` completes EXTRACT-02's "config parsing retired entirely."

Output:
- `db/routes/regions_get.go` — `RegionsList` iterates the `regions` table (group + leaf) and emits hierarchy fields; leaf rows join `region_archives` on `region_id == path` and keep today's build-state shape.
- `db/services/regions/config.go` — `LoadRegionCatalog`, `Region`, and `ValidateRegion` deleted; imports cleaned; `RegionCacheDir`, `RegionArchivePath`, `RegionDemPath`, `IsValidRegionID`, and the relaxed `regionIDPattern` (from 29-01) retained.
- `db/services/regions/config_test.go` — `TestLoadRegionCatalog` removed; id-validation / path-builder tests retained.
</objective>
