<objective>
Retire the admin `region_config.json` catalog loader as the cron's build-target source and replace bbox-based tile extraction with polygon-based extraction driven directly by the Phase 28 `regions` table.

Purpose: EXTRACT-01 (archives clipped to the region's canonical polygon, not its bounding box) and EXTRACT-02 (the cron reads `kind='leaf' AND enabled=true` from `regions`). This makes region archive coverage follow real political/geographic boundaries and removes the hand-authored config file from the cron path.

Output:
- `db/services/regions/config.go` — `regionIDPattern` relaxed to allow the materialized-path characters `.` and `'` while `IsValidRegionID` gains an explicit `..` traversal guard (Pitfall 1). The catalog loader (`LoadRegionCatalog`/`Region`/`ValidateRegion`) is left in place here — it is still referenced by `db/routes/regions_get.go` and is removed in plan 29-02 once that reader is migrated (keeps the `db` package compiling at this plan's boundary).
- `db/services/regions/polygon_extract.go` — new `writePolygonTempFile` helper.
- `db/services/regions/builder.go` — `BuildAll` queries the `regions` table; `buildRegion`/`buildRegionSafely`/`buildVector`/`buildDem`/`findOrCreateRegionRecord` operate on a `*core.Record` and a region-id derived from its `path`; both vector and DEM extraction switch to `--region=`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| seed data (regions.polygon/path) → cron → `pmtiles` subprocess | Committed-seed geometry/id are trusted but treated defensively before reaching `exec.Command` / `filepath.Join` |
| region id (`path`) → `filepath.Join` (RegionArchivePath/RegionDemPath, cache subdir) | The id becomes a filesystem path component |
