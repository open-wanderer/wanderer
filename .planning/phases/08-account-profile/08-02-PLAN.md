<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Flutter client → SvelteKit/Go API | Credential changes (email, password) cross here. The server is authoritative for current-password validation, access control, and token re-issue. |
| User input → form fields | Untrusted text (email, passwords) enters the app at the WandererTextField boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-04 | Spoofing / Elevation | Email change without proving identity | mitigate | The form requires `currentPassword`; the Go `user_email_change.go` route validates it server-side via `e.Auth.ValidatePassword` (RESEARCH V2/Threat Patterns). Client cannot bypass — server is authoritative. |
| T-08-05 | Elevation | Password change without current password | mitigate | Payload includes `oldPassword`; PocketBase's native password-change rule enforces it (Pitfall 2). Required by ASVS V2. |
| T-08-06 | Tampering (IDOR) | Editing another user's account | mitigate | The sheet posts to `/user/$userId` where `userId` is the authenticated user's own id (passed from the screen's `authProvider.value.id`); server enforces `id === authStore.record.id` → 403 otherwise (V4). |
| T-08-07 | Information Disclosure | Error toast leaking server internals | mitigate | Email errors surface the API `message` field only (not stack/internal); password errors use a generic `l10n.error_updating_password` (D-11, V7). No `print()` of passwords/tokens. |
| T-08-08 | Input tampering | Empty/malformed credentials reaching the API | mitigate | `FormBuilderValidators.required()` + `.email()` block invalid input client-side (UX); Zod + Go validate server-side (authoritative, V5). |
</threat_model>
