# Phase 8 — UI Design Contract

> Visual and interaction contract for the Account & Profile settings screen. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Platform: Flutter + Material Design (not web/React — shadcn gate not applicable). This screen fills the stub `SettingsAccountScreen` and follows the canonical `SettingsPrivacyScreen`/`SettingsLanguageScreen` structure plus the `LoginScreen`/`RegisterScreen` form pattern. The contract below codifies those mirrors so the executor produces a consistent, theme-driven result.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Flutter Material Design, not React/Vite — shadcn gate not applicable) |
| Preset | not applicable |
| Component library | Flutter Material (`Scaffold`, `AppBar`, `ListView`, `ListTile`, `CircleAvatar`, `AlertDialog`, `showModalBottomSheet`) + `WandererTextField` (first-party, extends `FormBuilderField<String>`) + `FormBuilder` (flutter_form_builder) |
| Icon library | Material Icons (`Icons.arrow_back`) + Font Awesome Flutter (`FontAwesomeIcons.*` for ListTile leading icons and toast icons) |
| Font | App theme default (IBMPlexSans via `ThemeData.fontFamily`); no per-screen font override |

**Theme inheritance rule:** This screen sets NO explicit colors, font sizes, or paddings beyond what is listed in this contract. Everything else derives from `Theme.of(context)` so light/dark mode and the global type scale apply automatically. The only allowed explicit color is `colorScheme.error` on the Delete account row (decision D-12, D-14). Do not hardcode hex colors or font sizes anywhere in `settings_account_screen.dart`.

**New dependency:** `image_picker` (latest stable) — decision D-01. Gallery source only (D-02). This is the only new package this phase.

## Layout Structure

Top-down widget tree (decision D-14; mirrors `SettingsPrivacyScreen` shell, `LoginScreen` form pattern):

```
ConsumerWidget  (settings_account_screen.dart)
└─ Scaffold
   ├─ AppBar
   │   ├─ leading: IconButton(Icons.arrow_back) → context.pop()
   │   └─ title: Text(l10n.account)                       // "Account"
   └─ body: ListView
       ├─ Avatar row              (CircleAvatar + edit/upload affordance)   [ACCT-01]
       ├─ Bio section             (section header + multiline TextField + Save button)  [ACCT-02]
       ├─ ListTile  l10n.change_email      → opens email modal bottom sheet  [ACCT-03]
       ├─ ListTile  l10n.change_password   → opens password modal bottom sheet  [ACCT-04]
       └─ ListTile  l10n.delete_account    → opens AlertDialog confirm (error color)  [ACCT-05]
```

**Body must be `ListView`** (not `Column`) so the screen scrolls on small viewports and when the keyboard is open — identical to the Privacy/Language screens.

**Section order is fixed:** Avatar → Bio → Change email → Change password → Delete account. The Delete account row is last (destructive actions belong at the bottom).

**Avatar row** is a horizontal layout: a `CircleAvatar` (radius ~40) on the left showing the current avatar, with a tap target (the avatar itself and/or an adjacent edit icon button) that triggers the gallery picker. Auto-upload on pick (D-03) — no staging, no separate Save for the avatar.

**Bio section** is a section header (`l10n.add_bio` — see Copywriting note) followed by a multiline `TextField` (`maxLines` 4–5, not `WandererTextField`, per D-04) and an `ElevatedButton` Save below it, enabled only when the text differs from the persisted `Settings.bio` (D-05).

**Email & password changes** are `showModalBottomSheet` forms (D-06, D-09) — no new go_router routes. Each sheet hosts a `ConsumerStatefulWidget`/`StatefulWidget` with a `FormBuilder` and two `WandererTextField`s.

**Delete account** is an `AlertDialog` confirm (D-12) triggered from the last `ListTile`.

## Spacing Scale

Declared values (Material 4dp grid; all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Field label bottom gap (inside `WandererTextField`), inline icon gaps |
| sm | 8px | Section header bottom padding; gap between bio field and Save button |
| md | 16px | Section header L/R/top padding; avatar row padding; bottom-sheet content padding; gap between the two form fields |
| lg | 24px | Bottom-sheet top padding above the first field (breathing room under the drag handle) |

**Exact spacing rules:**

- **Section header padding:** `EdgeInsets.fromLTRB(16, 16, 16, 8)` — copy verbatim from `SettingsPrivacyScreen._sectionHeader`. Applies to the Bio section header.
- **Avatar row padding:** `EdgeInsets.all(16)` around the row; `SizedBox(width: 16)` between avatar and any adjacent edit affordance.
- **Bio field → Save button gap:** `8px` (`SizedBox(height: 8)`); wrap the bio field + button block in `EdgeInsets.symmetric(horizontal: 16)` so it aligns with the section header.
- **Bottom-sheet content padding:** `EdgeInsets.fromLTRB(16, 24, 16, 16)` plus `MediaQuery.viewInsets.bottom` added to the bottom so the keyboard never covers the submit button. Gap between the two `WandererTextField`s: `16px`.
- **ListTile rows (email / password / delete):** no added padding — use Material default `ListTile` content padding. Do NOT wrap tiles in extra `Padding`.
- **No leading/trailing ListView padding overrides** — default `ListView` padding applies, matching the Privacy screen.

Exceptions: none.

## Color

This screen introduces no new color tokens. All color derives from the active `ColorScheme` (defined in `app/lib/theme/colors.dart` + `theme.dart`).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `colorScheme.surface` (light `#FFFFFF` / dark `#12141C`) | Scaffold background, ListView surface, bottom-sheet background |
| Secondary (30%) | `colorScheme.onSurfaceVariant` / `colorScheme.secondary` (light `#E5E7EB` / dark `#2D3241`) | Section header text, field fills, avatar placeholder background |
| Accent (10%) | `colorScheme.primary` (light `#242734` / dark `#3E435B`) | Primary Save button background, focused field border, avatar edit icon |
| Destructive | `colorScheme.error` (`#FEF2F2`) + Material destructive red for text | Delete account row text + leading icon; Delete button in the confirm `AlertDialog` |

**Accent reserved for:** the bio Save `ElevatedButton` (theme default primary background), the focused input border (already in `WandererTextField`), and the avatar edit/camera affordance icon. Nothing else.

**Destructive color rule (exact — decision D-12, D-14, specifics):**
```dart
final errorColor = Theme.of(context).colorScheme.error;
```
- Delete account `ListTile`: set both the leading `FaIcon`/`Icon` color and the title `Text` color to the destructive color so the row reads as dangerous.
- In the confirm `AlertDialog`, the **Delete** action uses the destructive color; the **Cancel** action uses the default text-button color.

> Note: the theme maps `colorScheme.error` to the light-red background token `#FEF2F2` (an inherited Tailwind mapping). For the destructive *text/icon* on the delete row and dialog action, prefer a saturated red foreground (e.g. `Colors.red.shade400`, matching `WandererTextField`'s existing error foreground) so it is legible — `colorScheme.error` is too light for foreground text. The executor should verify contrast in both light and dark mode.

## Interaction Contract

### Avatar (ACCT-01)
- Tap the avatar (or its edit affordance) → `ImagePicker().pickImage(source: ImageSource.gallery)` (D-02).
- On a non-null pick → immediately `POST /api/v1/user/{id}/file` as `FormData.fromMap({'avatar': await MultipartFile.fromFile(path)})` (D-03, code_context).
- On success → refresh the displayed avatar (re-fetch `UserEntity` or update `authProvider` state) and show a success toast.
- On error → error toast; avatar reverts to the prior image.
- Avatar URL construction: `user.getFileUrl(user.serverUrl, user.avatar)` with the dicebear fallback `https://api.dicebear.com/7.x/initials/png?seed=${user.preferredUsername}&backgroundType=gradientLinear` — copy the pattern verbatim from `wanderer_layout.dart`. Set `onBackgroundImageError` to a graceful fallback (icon or grey background).
- No camera, no cropping, no staging Save.

### Bio (ACCT-02)
- Source of truth: `Settings.bio` via `settingsProvider` (D-15). Plain-text multiline `TextField` (D-04).
- Save button is **disabled** until the field text differs from the persisted `Settings.bio` (D-05). On Save → `settingsProvider.notifier.saveToServer(settings.copyWith(bio: text))`.
- On success → success toast; the button returns to disabled (text now equals persisted value).
- On error → error toast (reuse the Privacy screen's `_save` try/catch + toast pattern).

### Email change (ACCT-03)
- `ListTile` tap → `showModalBottomSheet` with a `FormBuilder` (D-06, D-07).
- Two `WandererTextField`s: (1) new email `name: 'email'` with `isPassword: false`, email-format + non-empty validators; (2) current password `name: 'currentPassword'`, `isPassword: true`, non-empty validator.
- Submit button calls `_formKey.currentState!.saveAndValidate()`; on valid → `POST /api/v1/user/{id}/email` with `{ email, currentPassword }` (D-08).
- On success → `Navigator.of(context).pop()` the sheet, show `l10n.email_updated` success toast, re-fetch `UserEntity` so the displayed email refreshes (code_context).
- On error → surface the API error message in an error toast; the sheet stays open so the user can retry.

### Password change (ACCT-04)
- Same `showModalBottomSheet` + `FormBuilder` pattern (D-09).
- Two `WandererTextField`s, both `isPassword: true`: (1) current password `name: 'currentPassword'`; (2) new password `name: 'password'`. Both non-empty validators (D-10).
- Submit → `POST /api/v1/user/{id}` with `{ password, passwordConfirm }` (server re-auths with current password) (D-11).
- On success → pop sheet, show `l10n.new_password_success` toast.
- On error → show `l10n.error_updating_password` error toast; sheet stays open.

### Account deletion (ACCT-05)
- `ListTile` (destructive color) tap → `AlertDialog` (D-12).
- Title: `l10n.confirm_deletion`. Body: `l10n.account_delete_confirm`. Two actions: **Cancel** (`l10n.cancel`, default color) and **Delete** (`l10n.delete_account`, destructive color).
- Cancel → dismiss dialog, no side effect.
- Delete → `DELETE /api/v1/user/{id}` → on success `authProvider.notifier.logout()`; go_router's redirect guard pushes to `/login` (D-13). No extra route.

### Bottom-sheet conventions
- Sheets dismiss on success via `Navigator.of(context).pop()` AFTER showing the success toast (specifics).
- Sheets respect the keyboard: add `MediaQuery.of(context).viewInsets.bottom` to bottom padding (or use `isScrollControlled: true`).
- Validation always runs via `FormBuilder.saveAndValidate()` before any network call (specifics).

### Feedback model
- All success/error feedback is via the existing toast provider pattern (`toastProvider`), mirroring the Privacy screen — `ToastType.success` / `ToastType.error` with a Font Awesome icon. No inline banners.
- No global blocking spinner required; an inline progress affordance on the submit button during the network call is acceptable but optional.
