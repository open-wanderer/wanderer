<objective>
Re-gate the stored-on-device badge onto library membership (D-10) and give the Library's own
un-download action the same honest vocabulary the detail menu is getting (D-04, DL-01).

Purpose: `trail_panel.dart` currently renders TWO badges on the same axis with contradictory gates —
a grey "Offline" pill at `:214` gated on `trail.isLocal && !isUnsyncedState(...)`, and a green
"Available offline" pill at `:250` gated on `availableOffline && !trail.isLocal`. `Trail.isLocal` is
hardcoded `true` by `TrailEntity.toModel()` for every cached row and `TrailNotifier.build()` falls
back to the cache on any fetch exception, so which of the two a hiker sees flips with network
conditions: the grey pill appears when a fetch fails and the green one when it succeeds, and the
grey one can contradict a menu that offers *Download*. Phase 36's D-09 requires one axis per badge;
this badge's axis is "is it stored on this device", which is library membership and nothing else.

The Library's context menu has the identical vocabulary defect the detail menu has: an item labelled
*Delete* that actually calls `trailLibraryProvider.deleteTrail` (an un-download), confirmed with
`delete_trail_confirm` — the "cannot be undone" copy D-04 rejects for exactly this action.

Output: one badge, membership-derived, plus the Library's remove action renamed and re-confirmed.
</objective>
