# Phase 38 Plan 01: Retire forceOffline Summary

**Reverted the `forceOffline` family-key parameter from `trailProvider` and every one of its nine call sites, regenerated Riverpod codegen, and deleted the two tests written for it -- restoring the online-always-fetches read model (D-22) that D-01/D-02 will build on in later plans.**

## Performance

- **Duration:** ~20 min
- **Started:** 2026-08-04T15:50:00+02:00 (approx)
- **Completed:** 2026-08-04T16:02:38+02:00
- **Tasks:** 3/3
- **Files modified:** 12

## Accomplishments
- `TrailNotifier.build(String id)` no longer takes `forceOffline`; the disk-preferred early return is gone, replaced with a short D-22 comment. The pre-existing `catch (_)` fallback (network fails → disk) is untouched.
- `trail_provider.g.dart` regenerated by `build_runner` (not hand-edited): the family argument collapsed from `(String, {bool forceOffline})` to a bare `String`, matching `local_trail_provider.g.dart`'s shape.
- `route_location.dart`'s `trailDetailLocation`/`trailMapLocation` reverted to unnamed-parameter form; `router_provider.dart`'s `/trail/:id` builders stopped reading `state.uri.queryParameters['offline']`.
- All six consumer call sites (`LikeButton`, `TrailDropdown`, `TrailPanel`, `TrailDetailScreen`, `TrailDetailMapScreen`, `library_screen.dart`) dropped the `forceOffline` constructor param/field/forwarding.
- Deleted the two `forceOffline`-specific tests from `route_location_test.dart`; the remaining six (including the double-slash regression test) pass unchanged.

## Decisions Made
- Reverted the flag entirely rather than adapting it in place, matching D-20's explicit framing as "a deliberate revert, not a regression" -- the flag's only job (making the Library's Delete deterministic) is superseded by D-01/D-02's library-membership + authorship model, planned for a later 38-0x plan.
- `trail_download_state_provider.g.dart`'s hash constant shifted as an unavoidable side effect of running `build_runner build` project-wide (its hash covers the whole dependency graph including `Trail`). No logic in that file changed. Included in the same commit as the other Task 1 codegen output rather than split out, since it originates from the same single build_runner invocation.
- Left the `router_provider.dart` import of `settings_offline_regions_screen.dart` and an unrelated in-file comment containing the substring "offline" untouched -- both predate the `forceOffline` change (verified via `git show 8478ef56^:...`) and are outside this plan's scope; the plan's own automated verify command greps for `forceOffline` specifically, not the bare substring `offline`.
