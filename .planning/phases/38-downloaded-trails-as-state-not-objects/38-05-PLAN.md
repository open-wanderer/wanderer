<objective>
Break the coupling this whole phase exists to remove: make destructive-action availability derive
from **library membership** and **authorship**, and split the single ambiguous *Delete* into two
differently labelled actions (D-01, D-02, D-08).

Purpose: today one menu item labelled *Delete* means two different things and `Trail.isLocal` decides
which. That flag is hardcoded `true` by `TrailEntity.toModel()` for every cached row, and
`TrailNotifier.build()` falls back to the cache on *any* fetch exception — so one timeout while
viewing your own downloaded trail armed the server-delete branch. `_allowDelete`'s
`if (widget.trail.isLocal) return true;` is that coupling in source form and must go.

The replacement is komoot's single-object model: a download is a *state of the trail*, not a
separate object. `availableOffline` already arrives as a constructor bool computed from
`trailLibraryProvider` in `trail_detail_screen.dart` — that is the membership signal, and reusing it
is deliberate: it keeps both menu branches testable through the existing widget harness with zero
ObjectBox `Store` involvement. Do not make this widget read `objectBoxProvider` directly.

D-09 is a negative constraint: the bottom action bar is NOT touched by this plan. It already hides
its Download button once downloaded and Navigate keeps the full width; *Update* is a maintenance
action and must not carry equal visual weight.

Output: a menu whose destructive actions are unambiguous and whose availability no longer moves with
the network.
</objective>

Rewrite `_allowDelete` so it derives from authorship, never from `Trail.isLocal`:

Keep one explicit escape hatch first — when `isUnsyncedState(widget.trail.syncState)` is true, return
true. That is `isUnsyncedState`, not `isLocal`, and it is load-bearing: an unsynced capture is the
only copy on earth and its `author` can be the `Trail.author` placeholder rather than a real actor
id, so an authorship-only gate would silently strip the hiker's ability to delete their own
recording. D-03 guarantees unsynced and downloaded are mutually exclusive by construction, so this
branch can never swallow a downloaded trail.

Otherwise: read `authProvider`, return false when there is no user, and return
`widget.trail.author == user.actorId`. Delete the `if (widget.trail.isLocal) return true;` branch
entirely.

The consequence is D-02, and it is intended: a trail the hiker authored AND downloaded now shows
BOTH *Remove download* (from `availableOffline`, Task 1) and *Delete trail* (from authorship) —
independent axes. Today there is no way to delete your own trail from the server once it is in your
library. Someone else's downloaded trail shows *Remove download* and no *Delete trail*, which is
correct: it was never yours to delete.

`trailLibraryProvider.deleteTrail(trail.id)` plus its long comment. That branch was the un-download

confirm. After the unsynced branch returns, control falls straight through to
`await _deleteOnServer(context, trail);`.

Rewrite the comment above `_deleteTrail` to describe the new two-branch shape (unsynced local delete,

network conditions.

Leave `_confirmDelete` alone — its `trailHasServerId(trail.id)` copy selection (CR-04) is still

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| menu gesture → server DELETE /trail/{id} | The most destructive action in the app, previously reachable by mistake |
| menu gesture → local library membership | Removing a download must stay local and must not affect other accounts |
| network condition → which destructive branch is armed | The defect that produced the original report |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-05-01 | Tampering (destructive-action misrouting) | `_deleteTrail` | mitigate | The `Trail.isLocal` branch is deleted, so a cached model produced by a timed-out fetch can no longer decide between un-download and server delete; the two are separate menu items with separate handlers, asserted by a zero-occurrence grep on `isLocal` |
| T-38-05-02 | Elevation of privilege | `_allowDelete` | mitigate | Server delete is offered only when `trail.author == user.actorId`; the previous unconditional `true` for `isLocal` rows offered it with no ownership check at all whenever the fall-through was reached |
| T-38-05-03 | Denial of service (data loss) | `_confirmRemoveDownload` | mitigate | Calls only `trailLibraryProvider.deleteTrail`, which drops this account's `savedByUserIds` entry and removes files only when the last account gives it up ("scope, don't delete user data"); the acceptance criteria forbid `trailSaveProvider` and `_deleteOnServer` in that handler |
