<objective>
Retire the `forceOffline` flag entirely (D-20, D-21), reverting everything added for it on
`feature/app` on 2026-08-04.

Purpose: `forceOffline` was part of `trailProvider`'s family key, so `trailProvider(id)` and
`trailProvider(id, forceOffline: true)` are different provider instances and every consumer had
to forward the flag or silently mutate an invisible second copy (D-21). Its only job was making
the Library's Delete deterministic — a job D-01/D-02 take over properly in plan 38-05. Keeping it
would also violate D-19 ("a downloaded trail must never be stale while online"). The resulting
read model is D-22: online always fetches; disk is the offline fallback via the pre-existing
`catch` block.

This is a deliberate revert, not a regression. It must land first, because five other files in
this phase are edited by later plans and every one of them currently carries the flag.

Output: 9 lib files with the parameter removed, a regenerated `trail_provider.g.dart`, and two
deleted tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| deep link / restored route → screen | A `/trail/<id>` URL arrives from outside the app and selects which copy of a trail is shown |
| signed-in account → ObjectBox trail rows | Library rows are shared across accounts and filtered by `savedByUserIds` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-01-01 | Tampering | `router_provider.dart` `/trail/:id` builders | mitigate | Removing the `?offline=1` parameter removes the only query input that changed which copy (and therefore which destructive branch) a route selects; builders now read path parameters only |
| T-38-01-02 | Information disclosure | `TrailNotifier._readCached` | mitigate | Left untouched: the fallback query keeps `TrailEntity_.savedByUserIds.containsElement(userId)` with a fresh `currentAccountId(store)`, so one account can never read another's downloaded private trail |
| T-38-01-03 | Denial of service (data loss) | `TrailNotifier.build` fallback | accept | Online failures still fall back to the stored copy via the pre-existing `catch (_)`; this plan changes no failure handling, so a flaky network degrades exactly as it does today |
| T-38-01-SC | Tampering | package installs | accept | No package-manager install occurs in this plan; `pubspec.yaml` is untouched, so no legitimacy audit applies |
</threat_model>
