<objective>
Wire the `navigation_screen` call site off `Trail.pmTiles`/`demPmTiles` and onto `TileRepositoryManager.localTilePathsForBounds` (RENDER-01), and add the viewport-scoped region-swap recompute (RENDER-02). Unlike `TrailMap` (fixed trail bounds), `navigation_screen`'s camera moves freely across a session, so its bounds come from the LIVE viewport (`controller.getVisibleRegion()`), and it is the only screen that gains swap logic (D-06). Panning across a region boundary must swap the newly-relevant region's sources in rather than accumulating every downloaded region unconditionally — recomputed once per settled gesture by listening for `ml.MapEventCameraIdle` in the existing `onEvent` callback (which fires exactly once per settled pan, making it a debounce by construction — NO manual `Timer`, per D-04 and Pitfall 4; this is the same event `map_screen.dart` already uses for camera persistence).

Use the recommended full-style-reload strategy: the camera-idle recompute routes through the existing `_swapStyle()` → `controller.setStyle(json)` path, so the existing `onStyleLoaded` → `_onStyleLoaded()` re-add-track/breadcrumb chain fires automatically (Pitfall 5). Add a third `ref.listen(regionListNotifierProvider)` for mid-session download completion. An uncovered viewport resolves to empty vector paths → blank basemap; navigation continues its live GPS/maneuver tracking regardless (D-01/D-02).

Purpose: Make live navigation render offline from the app-wide region registry anywhere within a downloaded region, swapping sources as the hiker moves between regions.
Output: A rewired `_composeStyle`/`_swapStyle` + a new camera-idle recompute + a third region-list listen; `offline_style_rewriter.dart` untouched (D-06).

NOTE: This plan is written for the full-style-reload composition strategy (RESEARCH.md's recommended default). If 25-01's `checkpoint:decision` selects incremental composition instead, this plan must be revised before execution.
</objective>
