<objective>
Wire the `navigation_screen` call site off `Trail.pmTiles`/`demPmTiles` and onto `TileRepositoryManager.localTilePathsForBounds` (RENDER-01), and add the viewport-scoped region-swap recompute (RENDER-02) using 25-01's settled RENDER-03 decision (incremental composition, option-b) — `StyleController.addSource`/`addLayer`/`removeSource`/`removeLayer`, never a full `setStyle` reload for a region swap.

Unlike `TrailMap` (fixed trail bounds, add-only), `navigation_screen`'s camera moves freely across a session, so its bounds come from the LIVE viewport (`controller.getVisibleRegion()`), and it is the only screen that gains swap logic (D-06). Panning across a region boundary must swap the newly-relevant region's sources IN and the stale region's sources OUT rather than accumulating every downloaded region — reconciled once per settled gesture by listening for `ml.MapEventCameraIdle` in the existing `onEvent` callback (which fires exactly once per settled pan, a debounce by construction — NO manual `Timer`, per D-04 and Pitfall 4; the same event `map_screen.dart` already uses for camera persistence).

Composition-strategy mechanics (resolves 25-01's contingency NOTE, now settled as option-b):
- The map is still MOUNTED with the fully-composed offline style as `initStyle` (via `_composeStyle` → `rewriteStyleForOffline` seeded from the trail's bounds), because `glyphs`/`sprite` are style-level properties settable only at style-load (no incremental API on `StyleController`) and `rewriteStyleForOffline` (unchanged, D-06) throws on empty `cellPaths`. This initial render is flicker-free; the full-reload flicker the user rejected only ever occurred on post-mount `setStyle` swaps.
- Every POST-MOUNT region change is applied incrementally by `_reconcileRegionComposition()`, never via `setStyle`. It recomputes the composed style for the current `controller.getVisibleRegion()`, diffs its source/layer ids against the `_addedSourceIds`/`_addedLayerIds` tracking sets (seeded in `_onStyleLoaded` from the baked style), `addSource`/`addLayer`s the newly-relevant ids, and `removeLayer`/`removeSource`s the stale ones (layers before their source — Pitfall 3: Android has no missing-id guard, each wrapped in try/catch).
- 25-01 finding 1 (repaint-on-remove gap): after the removal loop, if anything was removed, force a native repaint with a 1ms no-op camera nudge — maplibre 0.3.5's `MapController`/`StyleController` expose no invalidate/redraw method, and removed layers otherwise stay visible until the user taps/pans. Read `controller.getCamera()` and issue `controller.animateCamera(center: cam.center, zoom: cam.zoom, bearing: cam.bearing, pitch: cam.pitch, nativeDuration: const Duration(milliseconds: 1))` — identical camera so nothing visibly moves, but the 1ms native transaction forces GL to repaint. Use `Duration(milliseconds: 1)`, NEVER `Duration.zero` (the Android binding passes zero to animateCamera as null, which throws — the codebase's documented native-quirk convention).
- 25-01 finding 2 (hillshade z-order gap): every hillshade/DEM layer is added via `addLayer(hillshadeLayer, belowLayerId: firstVectorLayerId)`, never a bare append — incrementally-added hillshade otherwise renders ON TOP of the vector layers.

Add a third `ref.listen(regionListNotifierProvider)` for mid-session download completion, also routed to `_reconcileRegionComposition()`. An uncovered viewport resolves to empty vector paths → the reconcile removes all region sources → blank basemap; navigation continues its live GPS/maneuver tracking regardless (breadcrumb + location marker are separate GeoJSON/Flutter layers, untouched by the region reconcile) (D-01/D-02). Theme-toggle and glyph-cache-warm swaps keep their existing `_swapStyle()` → `setStyle` path (they change style-level glyphs/sprite that cannot be incrementally patched) — out of scope, unchanged.

Purpose: Make live navigation render offline from the app-wide region registry anywhere within a downloaded region, swapping sources incrementally as the hiker moves between regions without a full-style flash.
Output: A rewired `_composeStyle`/`_swapStyle`, a `_reconcileRegionComposition` incremental add/remove swap + repaint nudge, a camera-idle recompute, a third region-list listen, `_addedSourceIds`/`_addedLayerIds` tracking, and JSON→typed source/layer translation helpers; `offline_style_rewriter.dart` untouched (D-06).
</objective>
