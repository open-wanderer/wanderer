<objective>
Wire the `TrailMap` call site off `Trail.pmTiles`/`demPmTiles` and onto `TileRepositoryManager.localTilePathsForBounds` for its offline style composition (RENDER-01), using the typed vector/DEM split delivered by 25-02, and — per 25-01's settled RENDER-03 decision (incremental composition, option-b) — apply a newly-downloaded region's sources/layers **incrementally** via `StyleController.addSource`/`addLayer` instead of a full `setStyle` reload.

`TrailMap`'s viewport is fixed for the screen's lifetime (`widget.trail.bounds`, D-05/D-06), so this is a one-time-per-compose bounds query — `localTilePathsForBounds(trail.bounds)` naturally returns every overlapping region's paths in one call, preserving the existing multi-cell behavior for a trail spanning several downloaded regions.

Composition-strategy mechanics (resolves 25-01's contingency NOTE, now settled as option-b):
- The map is still MOUNTED with the fully-composed offline style as `initStyle` (via `_composeStyle` → `rewriteStyleForOffline`), because `glyphs`/`sprite` are style-level properties settable only at style-load (no incremental API on `StyleController`), and `rewriteStyleForOffline` (unchanged, D-06) throws on empty `cellPaths` — so the initially-relevant region set is baked once at mount. This initial render is flicker-free (nothing to swap FROM on first paint); the full-reload flicker the user rejected only ever occurred on post-mount `setStyle` swaps.
- Every POST-MOUNT region change is applied incrementally, never via `setStyle`. A region finishing download mid-session fires `ref.listen(regionListNotifierProvider, ...)` → `_addRegionComposition()`, which recomputes the composed style for `widget.trail.bounds`, diffs its source/layer ids against the `_addedSourceIds`/`_addedLayerIds` tracking sets (seeded in `_onStyleLoaded` from the baked style), and calls `addSource`/`addLayer` ONLY for the newly-relevant ids. Per D-06 TrailMap is **add-only** — its bounds never change, so a region only ever ADDS coverage; there is no remove branch and therefore no repaint-on-remove gap (25-01 finding 1 does not apply to this screen).
- Any hillshade/DEM layer is added via `addLayer(hillshadeLayer, belowLayerId: firstVectorLayerId)`, never a bare append — 25-01 finding 2 confirmed incrementally-added hillshade otherwise renders ON TOP of the vector layers; `StyleController.addLayer`'s `belowLayerId` (confirmed in maplibre_platform_interface 0.3.5 `style_controller.dart`) inserts it beneath, matching the z-order `rewriteStyleForOffline`'s baked layer array already produces.

An uncovered viewport resolves to empty vector paths → blank basemap, matching today's empty-`cellPaths` failure mode, with no new banner/indicator (D-01/D-02). Theme-toggle and glyph-cache-warm swaps keep their existing `_swapStyle()` → `setStyle` path (they change style-level glyphs/sprite that cannot be incrementally patched) — out of scope for this plan, unchanged.

Purpose: Decouple trail-map rendering from any specific trail's download history — the app-wide region registry becomes the offline tile source, with mid-session region availability applied incrementally.
Output: A rewired `TrailMap._composeStyle`, a `_addRegionComposition` incremental add-only reconcile + its `regionListNotifierProvider` listen, `_addedSourceIds`/`_addedLayerIds` tracking, and JSON→typed source/layer translation helpers; `offline_style_rewriter.dart` untouched (D-06).
</objective>
