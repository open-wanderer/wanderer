<objective>
Fix the single most important finding in RESEARCH.md — the RENDER-01 blocker. `TileRepositoryManager.localTilePathsForBounds` (built in Phase 23) currently returns ONE flat, untyped `List<String>` with vector and DEM archive paths interleaved and no discriminator. `rewriteStyleForOffline` requires them as TWO separate parameters (`cellPaths` for vector, `demCellPaths` for DEM). Naively feeding the merged list into `cellPaths` would route a DEM `.pmtiles` archive through `_pointSourceAtCell` (the vector cell-duplication path) instead of `_pointDemSourceAtCell` — reproducing the exact bug class already found and fixed once in commit `3f67cf37` (quick-260711-lzb: "hillshadeSource swept into the vector-cell repoint path"). This must be fixed at the `TileRepositoryManager` layer — the seam its own doc comment names for Phase 25 — before either call site is wired in Wave 2.

Split the return type to a typed record `({List<String> vectorPaths, List<String> demPaths})`, extract the per-region split into a `@visibleForTesting` pure helper (mirroring the existing `bboxOverlaps` precedent) so the "which list does a path land in" logic is unit-testable WITHOUT a live ObjectBox store, and update the one existing call site (the 23-06 harness).

Purpose: Give the Wave 2 wiring an explicit, typed, test-proven contract so vector and DEM paths are structurally impossible to conflate.
Output: A split-return `localTilePathsForBounds`, a unit-tested `splitRegionTilePaths` helper, and an updated harness call site.
</objective>
