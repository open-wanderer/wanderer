<objective>
Fix the diagnosed Phase 24 UAT blocker (UAT tests 2 and 3): every first-ever region download — vector OR DEM — is refused on a real device because `freeDiskSpaceBytes(regionStorageDir(root, id))` queries free disk space for a `regions/<id>/` directory that `TileRepositoryManager` only creates AFTER the check. The `disk_space_2` plugin throws "Specified path does not exist", the exception is swallowed to `null`, and `hasEnoughSpace(null, ...)` fails closed per TILE-03 — so the package is marked `error` and no download ever starts.

Root cause (from `.planning/debug/region-download-diskspace.md`): `freeDiskSpaceBytes`'s own doc comment promises a device-wide fallback "when the path-specific query fails," but the catch block never implements it — it unconditionally returns `null`. Implement that promised fallback at the single shared wrapper. This fixes BOTH call sites (`startVectorDownload` ~line 116 and `startDemDownload` ~line 201) through one change, requires NO reordering of the existing create-directory-after-check flow, and fully preserves TILE-03's fail-closed guarantee.

Purpose: Restore SETUI-03 (download/pause/resume/delete a region with visible progress) and SETUI-04 (per-region DEM toggle) — both currently 100% broken on real devices.
Output: A device-wide fallback in `disk_space_util.dart`, extracted behind an injectable orchestrator so the fallback ordering becomes unit-testable (per the debug session's structural recommendation), plus unit tests covering it.
</objective>
