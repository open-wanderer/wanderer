<objective>
Close the two diagnosed UAT re-verification gaps (test 1 and test 3) in the
Offline Maps/Regions screen. Both share one root cause: `_buildActiveRow`
renders its download-progress UI (progress bar, trailing pause/download icon)
from `region.status`, which is derived from an ObjectBox `ToOne` relation that
caches permanently per Dart-object instance (RESEARCH.md Pitfall 2). The
screen holds that instance across the whole download and only refreshes it via
a single terminal `ref.invalidate(regionListNotifierProvider)` in `_save`'s
`finally` — so the row stays frozen at `notDownloaded` for the entire download,
then snaps straight to `downloaded`. No `downloading` frame, no progress bar,
no pause button ever renders.

The fix (per `.planning/debug/region-download-stale-toone.md`): make
`_buildActiveRow` prefer the live ephemeral `downloadState` (from
`tileRepositoryStatusProvider`, a plain in-memory Riverpod map immune to the
ToOne cache) over `region.status` while a VECTOR download/resume is in flight,
falling back to `region.status` only when idle (exactly when the ToOne value is
guaranteed fresh). A DEM-only download must NOT override the row status — that
would regress the currently-passing UAT test 2 (DEM toggle keeps its inline
spinner while the row keeps its vector lifecycle state).

Purpose: Restore SETUI-03's "visible progress while downloading" and unblock
SETUI-05's paused-mid-transfer disk-usage observation, without regressing
SETUI-04's independent DEM toggle.
Output: A pure `resolveRowStatus` util + unit test, and a one-line wiring
change in `settings_offline_regions_screen.dart`.
</objective>

  <files>app/lib/util/region_row_status_util.dart, app/test/util/region_row_status_util_test.dart</files>
  <behavior>
    `resolveRowStatus(RegionStatus persisted, RegionDownloadState? live)` returns:
    - `persisted` when `live == null` (no mutation in flight — ToOne value is fresh).
      e.g. `resolveRowStatus(RegionStatus.downloaded, null) == RegionStatus.downloaded`.
    - `live.status` when a VECTOR download is in flight
      (`vectorProgress != null`, `demProgress == null`):
      `resolveRowStatus(RegionStatus.notDownloaded, RegionDownloadState(status: downloading, vectorProgress: 0)) == RegionStatus.downloading` (fixes UAT test 1).
    - `live.status` when a resume is in flight (both progress fields null, since
      `resume()` sets only `status: downloading` before its first onProgress):
      `resolveRowStatus(RegionStatus.paused, RegionDownloadState(status: downloading)) == RegionStatus.downloading`.
    - `persisted` for a DEM-ONLY download (`demProgress != null` AND
      `vectorProgress == null`), so the row keeps its vector lifecycle state:
      `resolveRowStatus(RegionStatus.downloaded, RegionDownloadState(status: downloading, demProgress: 0)) == RegionStatus.downloaded` (no regression of UAT test 2),
      and `resolveRowStatus(RegionStatus.notDownloaded, RegionDownloadState(status: downloading, demProgress: 0)) == RegionStatus.notDownloaded`.
  </behavior>
  <action>
    Create `app/lib/util/region_row_status_util.dart` as a pure, dependency-free
    util (mirrors the pure/tested shape of `disk_space_util.dart`'s
    `hasEnoughSpace` and `map_cache_path.dart`). Import only
    `package:wanderer/models/region_download_state.dart` and
    `package:wanderer/models/region_status.dart`.

    Define a top-level function
    `RegionStatus resolveRowStatus(RegionStatus persisted, RegionDownloadState? live)`
    with this exact logic and no other branches:
    - If `live == null`, return `persisted`.
    - Compute `final isDemOnly = live.demProgress != null && live.vectorProgress == null;`
    - If `isDemOnly`, return `persisted`.
    - Otherwise return `live.status`.

    Document WHY with a doc comment: `persisted` is `RegionEntity.status`,
    computed from an ObjectBox `ToOne` relation that caches permanently per
    Dart-object instance (RESEARCH.md Pitfall 2 — see
    `~/.pub-cache/.../objectbox/.../to_one.dart`), so it is stale for the whole
    duration of an in-flight download and only becomes fresh again after
    `_save`'s terminal `ref.invalidate(regionListNotifierProvider)`. `live` is
    the ephemeral `RegionDownloadState` from `tileRepositoryStatusProvider`, an
    in-memory Riverpod map that is immune to the ToOne cache and updates on
    every progress callback. A DEM-only download is deliberately excluded from
    the override because `region.status` intentionally tracks only the VECTOR
    package lifecycle (see `RegionEntity.status`'s own doc comment), and the DEM
    download surfaces its own inline spinner — letting it flip the whole row to
    `downloading` would hide a downloaded region's checkmark/delete action and
    regress UAT test 2.

    Create `app/test/util/region_row_status_util_test.dart` following the

    Construct `RegionDownloadState` with the `const` factory exactly as the
    provider does (e.g. `RegionDownloadState(status: RegionStatus.downloading, vectorProgress: 0)`).

    Gap reason (both gaps): the UI reads the ToOne-frozen `region.status`
