## Spacing Scale

Declared values (must be multiples of 4) — matches values already in use across `settings_categories_screen.dart` / `settings_subcategories_screen.dart`, which this screen mirrors structurally:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps inside a compact chip/badge |
| sm | 8px | Compact spacing (e.g. banner-to-button gap, chip run spacing) |
| md | 12px | Icon-to-label gap in a row (`SizedBox(width: 12)`, matches `settings_categories_screen.dart`'s existing row layout) |
| lg | 16px | Default row padding (`EdgeInsets.all(16.0)`) — region row content padding, screen horizontal padding |
| xl | 24px | Section padding — disk-usage summary card padding, space above/below the search box |
| 2xl | 32px | Not used at row level; reserved for the empty-state illustration/copy block padding |
| 3xl | 48/64px | Not expected on this screen (no page-level hero spacing needed for a Settings list) |

Exceptions:
- **44px minimum touch target** on every icon-only action button in a region row (download / pause / resume / delete / retry / update). These sit inside a row that also has a full-row tap target (per `settings_categories_screen.dart`'s `InkWell`-wrapped row pattern) — use `IconButton`'s default Material tap target (48px) or explicit `constraints: BoxConstraints(minWidth: 44, minHeight: 44)`, never a bare `FaIcon` with no tap padding.
- **6px** `Wrap` spacing for any chip-style elements (matches `settings_categories_screen.dart`'s subcategory chip `spacing: 6, runSpacing: 6`) — only relevant if the size-breakdown (vector/DEM) is rendered as two small chips rather than one text line (executor's choice; either satisfies SETUI-02).

## Typography

Uses Flutter's default Material 3 `TextTheme` (this app's `AppTheme` does not override `textTheme`), scoped through `Theme.of(context).textTheme.*` — never a hardcoded `TextStyle` with a raw font size, matching every existing screen's convention.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Label | 12px | 400 (regular) | 1.33 | `textTheme.bodySmall` — size breakdown text ("120 MB vector · 45 MB DEM"), search-box hint, disabled-row caption ("Not yet available" / "Build failed"), update-banner sub-text |
| Body | 16px | 400 (regular) | 1.5 | `textTheme.bodyLarge` — dialog body copy, empty-state body text, general row secondary text |
| Row Title (emphasis) | 16px | 700 (bold) | 1.5 | `textTheme.bodyLarge!.copyWith(fontWeight: FontWeight.bold)` — region name in each row. Reuses `settings_categories_screen.dart`'s exact category-row-name style verbatim (do not introduce a new `titleMedium`/w600 variant). |
| Heading | 22px | 400 (regular) | 1.2 | `textTheme.titleLarge` (Flutter's default `AppBar` title style) — screen title "Offline Maps/Regions" |
| Display | 24px | 700 (bold) | 1.2 | `textTheme.headlineSmall!.copyWith(fontWeight: FontWeight.bold)` — the total-disk-usage headline figure at the top of the screen (SETUI-05), matching `WandererError`'s existing headlineSmall+bold precedent for a prominent standalone figure/statement |

Exactly 4 distinct sizes (12/16/22/24) and exactly 2 weights (400/700) — the "Row Title" row reuses the 16px size at the bold weight rather than introducing a 5th size or 3rd weight.

## Color

Uses the app's existing `ColorScheme` (`AppTheme.createTheme`, `AppColors`) — this phase adds no new palette entries, only new *usages* of existing roles.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `colorScheme.surface` — light `rgb(255,255,255)` / dark `rgb(18,20,28)` (`AppColors.backgroundLight`/`backgroundDark`) | Scaffold background for the whole screen |
| Secondary (30%) | `colorScheme.outline` (row dividers, matches `DividerThemeData`) + `colorScheme.surfaceContainerHighest`/`secondaryContainer` for the disk-usage summary card background | Region-list row separators, the disk-usage summary card/container, search box fill (`inputDecorationTheme.fillColor`) |
| Accent (10%) | `colorScheme.primary` — light `rgb(36,39,52)` / dark `rgb(62,67,91)` (`AppColors.primaryLight`/`primaryDark`) | Reserved for exactly: (1) the DEM `Switch`'s active-thumb color (mirrors `settings_categories_screen.dart`'s `activeColor` convention), (2) the downloading-state progress indicator's active color (`ProgressIndicatorThemeData` already uses this role app-wide), (3) the idle "Download" action's icon/label color |
| Destructive | `Colors.red.shade400` (text/label) + `Colors.redAccent` (icon) | Reserved for exactly: the region row's delete action + its confirm dialog (D-02), and the local per-package download-error badge/icon (D-03, paired with `FontAwesomeIcons.circleExclamation`) — matches `settings_account_screen.dart`'s "Danger zone" convention verbatim |
| Warning (non-destructive) | `Colors.orange` | Reserved for exactly: the `updateAvailable` persistent banner text + its update icon/button (D-05) — matches the existing "attention, not error" orange already used in `location_search_screen.dart`/`global_search_screen.dart`. Deliberately distinct from Destructive red: an available update is never an error state. |

Accent reserved for: DEM toggle active-thumb, downloading progress-indicator active color, idle "Download" CTA — never applied to plain body text, dividers, or disabled-row captions.

## Component & Pattern Inventory (executor reference)

Not part of the template's required tables, but recorded here since this phase's structural precedent is unusually strong and should not be re-derived:

- **Screen shape**: `ConsumerStatefulWidget` list screen, structurally mirroring `settings_categories_screen.dart` (AsyncLoader-wrapped list, per-row toggle with auto-save + error-toast-only failure, confirm-before-destructive-action dialog).
- **Search box**: reuse `WandererSearchBar` (`app/lib/components/base/wanderer_searchbar.dart`) verbatim — debounced 500ms `onChanged`, already themed correctly.
- **Loading/error**: reuse `AsyncLoader<T>` + its built-in `WandererError` fallback (`app/lib/components/async_loader.dart`) — do not build a bespoke spinner or error widget.
- **Toasts**: reuse `toastProvider` (`app/lib/provider/toast_provider.dart`) with `FontAwesomeIcons.circleExclamation` for any operation failure that isn't already covered by an inline row state (D-03 already covers per-row download errors inline; toasts are for catalog-refresh/DEM-delete-call failures per `24-CONTEXT.md`'s code-context notes).
- **Progress**: D-07's combined vector+DEM progress bar should be a `LinearProgressIndicator` (first use of this widget in the app for a download context — precedent elsewhere is `CircularProgressIndicator` for generic loading, but a determinate horizontal bar better fits a byte-progress row per SETUI-03's "visible progress while downloading").
- **Disk-usage formatting**: no byte-formatting utility currently exists in `app/lib/util/`; this phase introduces the first one. Convention to follow: one decimal place, unit steps at KB/MB/GB (e.g. "45 MB", "2.4 GB") — matches the informal precedent already implied by `disk_space_util.dart`'s byte-based API.
