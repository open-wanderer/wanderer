# Phase 19 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** This phase is Flutter mobile (`app/lib/`), not the SvelteKit web app. `shadcn` and the web `DESIGN.md`/"The Terrain Log" palette (Polar Night, flat-by-doctrine elevation) documented in `CLAUDE.md`'s Design Context are a **web-only** artifact set — no `DESIGN.md`/`PRODUCT.md` file exists in this repo for the Flutter app, and none was found during research. This contract instead derives from the Flutter app's own existing, shipped design system (`app/lib/theme/`) and established map-UI patterns (`trail_layer.dart`, `trail_map.dart`, `trail_detail_map_screen.dart`), which already implement the same near-monochromatic, restrained-accent spirit natively (IBM Plex Sans, a single dark-navy primary, flat pill-shaped controls). Do not import web CSS tokens or shadcn primitives into this phase.

## Spacing Scale

Declared values (must be multiples of 4), matching the existing map-control pattern (`trail_detail_map_screen.dart`'s `_buildMapControls`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside pill controls |
| sm | 8px | Padding around the top-right control-button pill (`Padding(all: 8.0)`); gap between stacked control buttons in the `Column` |
| md | 16px | App bar action padding; horizontal screen-edge margins |
| lg | 24px | Control-button pill corner radius (`BorderRadius.circular(24)`, matches existing pattern verbatim) |
| xl | 32px | Route-anchor marker diameter (matches `TrailMarkerLayer`'s existing 32px waypoint marker size) |
| 2xl | 48px | Minimum touch target for app bar undo/redo `IconButton`s (Material default) |
| 3xl | 64px | Not used this phase |

Exceptions:
- **36px marker hit-radius** (not a multiple of 4, but a *reused, load-bearing existing constant*): D-04 explicitly reuses the proximity-nudge/hit-radius threshold already established in `trail_layer.dart`'s `TrailMarkerLayer` (start/finish pin 36px nudge distance) as the route-anchor marker's invisible hit-radius, checked before segment hit-testing. Do not round this to 32/40 — it must match the existing constant so marker-vs-segment disambiguation behaves identically to the proven pattern.
- **18px icon size** inside control-button `IconButton`s and app bar `IconButton`s (matches `FaIcon(..., size: 18)` used throughout `trail_detail_map_screen.dart`) — icon glyph size, not a spacing token.

## Typography

This is a map-dominant screen with minimal on-screen text (an app bar title, control tooltips, and transient toast/snackbar copy for the blocked-segment/retry flow). No large display text is needed.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | Regular (400) | 1.5 |
| Label | 12px | SemiBold (600) | 1.2 |
| Heading | 20px | SemiBold (600) | 1.2 |
| Display | not used | — | — |

- **Body 14px/400/1.5**: SnackBar/toast copy for the blocked-segment retry flow (e.g. "Couldn't find a route here. Tap the segment to retry.").
- **Label 12px/600/1.2**: the route-anchor's number glyph rendered inside its circular marker; control-button tooltips.
- **Heading 20px/600/1.2**: the screen's `AppBar` title ("Plan a Route" or equivalent, exact copy owned by Phase 21's entry point — Phase 19 should not hardcode a different title than what Phase 21 hands off).
- **Display**: not used — do not introduce a display-scale style for this phase.

**Route-line color is a separate, pre-existing app-wide token, not part of the 60/30/10 UI-chrome palette:** `kTrailRouteColor` (`#3549bb`, defined in `trail_layer.dart`) is the fixed hue for any rendered route/track line across the whole app. This phase's three segment states reuse it as follows (see Segment Rendering Contract below) — differentiated by stroke style and casing, never by inventing a new hue for "routed" vs "straight-line."

## Segment Rendering Contract (phase-specific — supplements Color/Typography)

Three mutually-exclusive segment visual states, required to be simultaneously distinguishable per D-08 (a user must be able to tell all three apart at a glance, never by color alone since two share `kTrailRouteColor`):

| State | Stroke | Width | Color | Casing | Tap behavior |
|-------|--------|-------|-------|--------|---------------|
| Valhalla-routed (auto-routing ON, resolved) | solid | 5px | `kTrailRouteColor` `#3549bb` | 9px white casing underneath (identical to `TrailLayer.add`'s existing route/casing pair) | tap-on-segment inserts a new anchor (WAYP-03) |
| Straight-line (auto-routing OFF) | solid | 3px | `kTrailRouteColor` `#3549bb` at reduced opacity (`.withValues(alpha: .55)`) | none | tap-on-segment inserts a new anchor (WAYP-03) |
| Blocked (auto-routing ON, Valhalla failed — ROUTE-05) | dashed (`line-dasharray: [2, 2]`) | 3px | `Colors.red.shade400` | none | tap-on-segment retries auto-routing for that segment (D-09) — mutually exclusive with insert-anchor by segment state, not a competing gesture |

Rationale for the three-way distinction: casing presence (routed) vs. reduced-opacity thin solid (straight-line) vs. dashed red (blocked) means no two states share both color and stroke style, satisfying D-08 without inventing a fourth palette color.

## Route-Anchor Marker Contract (phase-specific)

Reuses `trail_layer.dart`'s `_buildCircularMarker` visual shape, adapted for a numbered anchor instead of a Font Awesome glyph:

- **Size:** 32px diameter circle (matches existing `TrailMarkerLayer` waypoint marker `size: const Size(32, 32)`).
- **Fill (default/unselected):** Accent primary (`#242734` light / `#3E435B` dark), 2px white border, `BoxShadow` black-20%-alpha/blur-4/offset-(0,2) — identical box-shadow spec to the existing `_buildCircularMarker`.
- **Label:** the anchor's 1-based ascending number, Label typography (12px/SemiBold/white), centered.
- **Selected/dragging state:** inverts to white fill with accent-primary 2px border and accent-primary number text — same invert pattern `_buildCircularMarker` already uses for `selected: true`. Scale animates 0.875 → 1.0 via `AnimatedScale` (200ms, `Curves.easeOutBack`) — identical animation spec to the existing marker.
- **Drag behavior (D-05):** no live route preview while dragging. The dragged anchor renders at a straight temporary screen position (reusing `TrailMarkerLayer`'s `onPanStart/Update/End` + `_dragOffset`/`toScreenLocation`/`toLngLat` pattern verbatim); connected segments stay in their pre-drag rendered state until `onPanEnd`, at which point they re-resolve to the current routing mode (Valhalla or straight-line) per D-05.
- **Renumbering (D-02):** inserting a mid-route anchor (WAYP-03) renumbers every anchor after the insertion point — the marker label is a derived display value recomputed from list order, never a stored/independent field.

## Map Control & App Bar Contract (phase-specific)

- **Auto-routing toggle (D-06):** joins the existing top-right `controls` `Column` slot (`TrailMap.controls` pattern) as a pill-shaped `IconButton` identical in container styling to `_buildMapControls`'s pill (`Theme.of(context).canvasColor` background, `BorderRadius.circular(24)`, `Padding(all: 8.0)`, `VisualDensity.compact`). Icon: `FontAwesomeIcons.route`, size 18. **ON** = accent-primary tint; **OFF** = muted/neutral (`colorScheme.onSurface` at ~40% opacity, matching Flutter's standard disabled-icon treatment). Tooltip text: "Auto-routing on"/"Auto-routing off" (state-reflecting, not a static label). This slot is shared with Phase 20's planned waypoint-list/elevation-profile buttons — stack order/spacing must accommodate siblings joining later without redesign.
- **Undo/redo (D-10/D-11):** `AppBar.actions` icon buttons, in that order (undo before redo), using `FontAwesomeIcons.arrowRotateLeft` (undo) and `FontAwesomeIcons.arrowRotateRight` (redo), 18px, matching the existing app bar `IconButton` sizing convention (`trail_create_screen.dart`). Enabled icon tint = accent-primary; disabled (empty history direction, D-11) = Flutter's standard disabled `IconButton` treatment (`onPressed: null`, ~38% opacity) — never a no-op tap.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | None in this phase — there is no persistent "Add anchor" button; adding an anchor is a direct tap-on-empty-map gesture (D-03), not a labeled CTA. (The route hand-off CTA belongs to Phase 21.) |

| Empty state body | "Tap the map to start your route." — shown until the first anchor is placed, then dismissed permanently for the session |

| Destructive confirmation | None in this phase — no delete/discard actions exist in Phase 19's scope (waypoint deletion is WAYP-04, Phase 20's waypoint-list sheet) |
