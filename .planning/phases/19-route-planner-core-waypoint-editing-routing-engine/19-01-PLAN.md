<objective>
Lay the two load-bearing foundations every later plan in this phase consumes: (1) fix the verified polyline-precision bug by adding a `precision` parameter to `PolylineUtil.decode`/`encode` so this phase's first-ever Flutter consumer of a Valhalla `/route`-encoded polyline decodes at precision 6 instead of the app's hardcoded precision 5, and (2) define the in-memory route data model (`RouteAnchor`, `RouteSegment`, `SegmentState`, `RouteAnchorsSnapshot`) that backs the route-planner state provider — deliberately a NEW type set, never reusing the persisted `Waypoint` model (D-01).

Purpose: These are pure, deterministic contracts. Building them first (interface-first) means the state engine (19-02), map overlays (19-03), and screen (19-04) all receive fixed types and a correct codec rather than reverse-engineering them.
Output: A precision-aware `PolylineUtil` with a regression test, and `route_anchor.dart` + its generated `route_anchor.freezed.dart`.
</objective>
