# Phase 31 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** This phase is Flutter/Dart mobile (`app/lib/routes/settings_offline_regions_screen.dart`), not a web/React/Next.js/Vite surface. The shadcn gate in the researcher's standard flow does not apply — there is no `components.json`, no npm-based component registry, and no equivalent tool for Flutter in this codebase. The design system below is the app's existing Material 3 theme (`app/lib/theme/theme.dart`, `app/lib/theme/colors.dart`), already established across Phases 6-30 and left unmodified by this phase.

## Spacing Scale

Declared values (must be multiples of 4) — identical to what the screen already uses today, no new values introduced:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, tight vertical rhythm (existing: disk-usage number → caption) |
| sm | 8px | Row internal gaps, corner radius on cards/summary box |
| md | 16px | Screen horizontal padding, card margin, tree base indent (depth 0), row internal padding |
| lg | 24px | Padding below the disk-usage summary card |
| — | 44px | Minimum touch target for the group-row tap area and chevron icon button (exception below) |

Exceptions:
- **Tree row touch target = 44px minimum height**, even though the visual chevron glyph is 16px — matches WCAG 2.1 AA / Material minimum touch target guidance already implied by the existing `ListTile`/`IconButton` defaults elsewhere on this screen. Do not shrink a group row below this to save vertical space.
- **Depth indentation step = 16px per level, capped at depth 4 (max 64px indent added to the 16px base = 80px total left inset).** CoMaps hierarchy can nest continent → country → region → sub-region; on a 360dp-wide phone, uncapped indentation would eventually leave no room for the row label. Rows at depth > 4 keep indenting from the same capped 80px left edge rather than growing further.

## Typography

Reuses the screen's existing `Theme.of(context).textTheme` roles — no new sizes or weights introduced (2 weights max, already satisfied by the existing screen):

| Role | Textstyle | Weight | Used for |
|------|-----------|--------|----------|
| Region/Group name | `textTheme.bodyLarge` | bold (700) | Leaf region name (existing, unchanged) AND new group row name — same style, so a group reads as a peer-level heading to a leaf, not a demoted label. Differentiation comes from the chevron + indentation + absence of Vector/DEM tiles beneath it, not from a weight change. |
| Subtitle / caption | `textTheme.bodySmall` | regular (400) | Vector/DEM tile subtitles, disabled-row caption, empty-state body (all existing, unchanged) |
| Disk-usage figure | `textTheme.headlineSmall` | bold (700) | Total bytes-used headline in the summary card (existing, unchanged) |
| Filter input | inherited from `WandererSearchBar` | regular (400) | Search/filter text field (existing widget, reused verbatim) |

Line height: inherited from Flutter's default `TextTheme` metrics (Material 3 typography scale) — not overridden anywhere on this screen today; this phase does not introduce an override.

## Color

Reuses the app's existing dual light/dark `ColorScheme` (`AppColors` in `colors.dart`) — no new colors introduced.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `colorScheme.surface` (`AppColors.backgroundLight` `#FFFFFF` / `AppColors.backgroundDark` `#12141C`) | Screen background |
| Secondary (30%) | `colorScheme.outline` border (`AppColors.inputBorderLight` `#D1D5DB` / `AppColors.inputBorderDark` `#323640`) on card containers; row hover/press states use Flutter's default `InkWell` splash over surface | Card borders around the disk-usage summary and each leaf region card (existing pattern, unchanged); tree structure itself (group rows) has **no** card/border — it sits directly on the screen background, visually distinct from the bordered leaf cards below it |
| Accent (10%) | `colorScheme.primary` (light) / `colorScheme.onSurface` (dark) — the screen's existing `accentColor` local variable | Reserved for: the Download/Retry/Update icon buttons on Vector and DEM tiles only (existing, unchanged). The chevron icon on group rows is explicitly **not** accent-colored — it uses a muted `onSurface` at 60% opacity, same tone as the existing muted-subtitle color, so groups read as structural chrome rather than competing calls-to-action against the real download actions |
| Destructive | `Colors.redAccent` | Delete icon buttons (existing, unchanged); no new destructive surface introduced |

Accent reserved for: Vector-tile Download/Update/Retry icon button, DEM-tile Download/Update/Retry icon button. Nothing else on this screen — group chevrons, the disk-usage card, and the search bar all stay neutral, exactly as today.

## Interaction Contract (Tree-Specific)

Not part of the standard template but load-bearing for this phase — the researcher is adding this section because the phase's entire surface area is a new interaction pattern (no prior tree/`ExpansionTile` exists in `app/lib`, per `31-CONTEXT.md`'s Established Patterns).

| Behavior | Spec |
|----------|------|
| Group row tap target | Entire row width is tappable (not just the chevron) to expand/collapse — matches the admin page's `.tree-row-clickable` (`regions_ui.html:1108-1111`), which the app mirrors per D-01. |
| Chevron icon | `FontAwesomeIcons.angleRight` (collapsed) / `FontAwesomeIcons.angleDown` (expanded), 16px, `onSurface` at 60% opacity. No rotation animation required (not specified in CONTEXT.md; keep it simple — instant swap, matching the admin page's instant icon-class swap, not an animated transform). |
| Leaf row | Unchanged — still the existing bordered card with region name header + Vector tile + optional DEM tile (`_buildActiveRow`/`_buildVectorTile`/`_buildDemTile`), now just indented by its depth and preceded by an empty chevron-width spacer (16px) so leaf and group row-name text starts align vertically at the same depth, matching the admin page's `<span class="chevron" aria-hidden>` placeholder for leaves. |
| Default expand state | A group auto-expands only if it contains a leaf with an existing download (Vector and/or DEM present) or a mid-flight download (D-02) — computed once per tree build, mirrors admin's `computeDefaultExpanded`. |
| Filter/search | Typing in the existing `WandererSearchBar` narrows the flattened row list to matching leaves/groups plus their full ancestor chain, all auto-expanded while a filter is active — tree structure stays visible, not flattened-to-matches-only (D-06). No debounce — filtering is pure client-side list computation over the already-fetched tree (same immediacy as today's flat-list `setState` filter, no network call per keystroke). |
| Zero-match filter state | Reuse existing `regions_empty_search_title`/`regions_empty_search_body` copy (already correct for "no regions match your search" — applies unchanged whether matching a flat list or a tree). |
| Offline / no-hierarchy-available state (D-04) | New, scoped empty state — see Copywriting Contract. This is a **deliberate, accepted regression** for the offline-only edge case (previously-downloaded regions become unmanageable while offline) per D-04; do not attempt to reintroduce a flat-list fallback here. |
