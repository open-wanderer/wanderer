<objective>
Replace the single-purpose `/api/v1/map/tileurl` route with one unified `/api/v1/map/config` endpoint that returns the tile URL, glyph URL template, and sprite base URL in one JSON object, and update the Flutter app to fetch and hold all three fields through a typed config provider.

The tile URL logic (env `TILE_SERVER_URL`, Protomaps fallback via `PROTOMAPS_API_KEY`) is carried forward byte-for-byte, just relocated into the merged response. Glyph/sprite logic is new: a single new operator env var `MAP_ASSETS_URL` overrides both; unset, they default to the public `protomaps.github.io/basemaps-assets` URLs the app's theme already hardcodes today. No Go/PocketBase, no asset vendoring, no Docker changes, and no wiring of glyphs/sprite into the rendered style — that is Phase 15 (GLYPH-04). This phase only stands up the config endpoint and makes the app fetch/parse/hold it.

Purpose: Consolidates the app's server-config fetch into one call and adds operator override capability for glyph/sprite origins (GLYPH-03), on the same override model as tiles — the foundation Phase 15 consumes when it wires labels and sprites into MapLibre.
Output: New unified config endpoint, new typed Flutter `MapConfig` model + provider, old `tileurl` route and `tile_url_provider` deleted.
</objective>
