# Phase 12 — UI Design Contract

> Visual and interaction contract for the Settings Categories + Subcategories screens. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Platform: Flutter mobile app** (`app/lib/`), Material 3 + Riverpod — NOT the SvelteKit web app. shadcn gate is not applicable (no React/Next/Vite surface in this phase). All tokens below are read from the existing established Flutter theme; this phase adds no new tokens.

| Property | Value |

## Spacing Scale

Declared values (multiples of 4; Flutter logical pixels):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Section-header bottom inset (the `8→` step in `fromLTRB(16,16,16,8)` uses 8; inline icon gaps use 4) |
| sm | 8px | Section-header bottom padding; drag-handle-to-content gap; compact vertical rhythm |
| md | 16px | Canonical horizontal row/list inset; section-header top/left/right padding |
| lg | 24px | `AlertDialog` internal content spacing (Material default `contentPadding`) |

Row padding convention (locked by D-App-Discretion + `settings_notifications_screen.dart`): **section headers use `EdgeInsets.fromLTRB(16, 16, 16, 8)`**. `SwitchListTile` and `ListTile` use Material default insets (16px horizontal) — do NOT override unless matching an existing settings screen.

**Exceptions:**
- `FaIcon` leading glyphs render at **size 18** (matches every existing settings tile in `settings_screen.dart`) — not a spacing token, an icon-size constant. Reuse `18` for the new "Categories" tile leading icon.
- `Icons.drag_handle` uses Flutter default `IconButton`/icon size (24) as the reorder affordance; touch target remains the Material minimum 48px, satisfying WCAG 2.1 AA target size — do not shrink.

## Typography

All type comes from Material 3 `Theme.of(context).textTheme` on IBMPlexSans. Do NOT hardcode font sizes — reference the theme roles below (mirrors the "single explicit override" discipline in `settings_notifications_screen.dart`).

| Role | textTheme token | Approx Size | Weight | Line Height | Usage |
|------|-----------------|-------------|--------|-------------|-------|
| Screen title | `titleLarge` (AppBar default) | 22px | 400 regular | ~1.27 | `AppBar` title — "Categories" and the parent-category name on the subcategories screen |
| Section header | `titleSmall` + `color: onSurfaceVariant` | 14px | 500 medium | ~1.43 | The single explicit override this codebase permits; only if a header is needed |
| List row title | `bodyLarge` (ListTile/SwitchListTile default) | 16px | 400 regular | 1.5 | Category / subcategory locale-resolved name in each row |
| Dialog title | `titleLarge` (AlertDialog default) | 22px | 400 regular | ~1.27 | Own-trail confirm dialog heading |

Weights in use: **regular (400)** for all body/title text, **medium (500)** for the one section-header override — 2 weights total, within budget. Body line-height 1.5, heading/title line-height ~1.2–1.27 (Material defaults, do not override).

## Color

Read from `AppColors` / `ColorScheme` in `app/lib/theme/`. Near-monochromatic Polar Night palette, dual light/dark, flat-by-doctrine (borders/dividers only, no shadows). Reference `colorScheme.*` — do NOT hardcode hex.

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `#FFFFFF` (`backgroundLight` → `surface`) | `#12141C` (`backgroundDark` → `surface`) | Scaffold background, list surface, row background |
| Secondary (30%) | `#E5E7EB` (`secondaryLight`) | `#2D3241` (`secondaryDark`) | AppBar / elevated affordances, divider `#D1D5DB` light / `#374151` dark |
| Accent (10%) | `#242734` (`primaryLight`) | `#3E435B` (`primaryDark`) | See reserved-for list below |
| Destructive | `error #FEF2F2` bg / `onError #4C1111` fg | same | Destructive-action styling in the own-trail confirm dialog only |

**Accent (`colorScheme.primary`) reserved for — explicit list, nothing else:**
- The **active/ON thumb** of category and subcategory visibility `SwitchListTile`s. Reuse the exact existing rule from `settings_notifications_screen.dart`: `activeThumbColor = brightness == dark ? colorScheme.onSurface : colorScheme.primary`.
- The **primary text button** ("Disable anyway" — see copywriting) affirmative action in the confirm dialog.

Accent is NOT applied to: row backgrounds, drag handles (use `onSurfaceVariant`/default icon color), chevrons, or the "Categories" leading tile icon (default `FaIcon` color, matching sibling tiles).

**Destructive semantic — confirm dialog:** the own-trail disable is a data-hiding action, not deletion, so the confirm dialog's affirmative button is a plain `TextButton` at accent color, NOT a red destructive button. The **"Cancel"** action is the safe default (reverts switch to ON per D-10). No second destructive color is introduced.

## Copywriting Contract

All user-facing strings MUST be added as l10n keys to `app/lib/i18n/` ARB files (en canonical with `@metadata`, then regenerate `AppLocalizations`), mirroring the Phase 11 `subcategories` key process. Placeholders below use `{count}` / `{category}` ICU form. Copy tone: plain, technical, direct — no exclamation marks, no marketing voice ("The Terrain Log" register).

| Element | Copy (en canonical) | l10n key (suggested) |
|---------|---------------------|----------------------|
| Settings tile label | `Categories` | reuse existing `l10n.categories` if present, else `settings_categories` |
| Categories screen title | `Categories` | `settings_categories` |
| Subcategories screen title | *(dynamic)* parent category's `displayName(locale)` — no static string | — |
| Category/subcategory row title | *(dynamic)* `displayName(locale)` via CAT-01 fallback chain | — |
| Empty state heading (subcategories screen, zero subcategories — D-07) | `No subcategories` | `settings_categories_empty_title` |
| Empty state body | `This category has no subcategories to configure.` | `settings_categories_empty_body` |
| Load/error state | Reuse existing settings error toast: `l10n.error_saving_settings` on save/reorder failure; no bespoke inline error copy | `error_saving_settings` (exists) |
| Reorder-failure feedback | Same `error_saving_settings` toast + list reverts to pre-drag order (D-04/D-09) | `error_saving_settings` (exists) |
| Own-trail confirm — title | `Hide this category?` (subcategory variant: `Hide this subcategory?`) | `settings_categories_confirm_disable_title` / `..._subcategory_title` |
| Own-trail confirm — body | `{count} of your trails use this {category ? category : subcategory}. They will stay published but this filter will be hidden.` | `settings_categories_confirm_disable_body` |
| Own-trail confirm — view-trails link | `View trails` | `settings_categories_confirm_view_trails` |
| Own-trail confirm — affirmative | `Disable anyway` | `settings_categories_confirm_disable_confirm` |
| Own-trail confirm — cancel | `Cancel` | `cancel` (reuse existing shared key if present) |

**Primary CTA for this phase:** there is no full-width submit button. The primary interactive commitment is the **visibility toggle (auto-save, no button)**; the primary *labelled* action is the confirm dialog's **"Disable anyway"**.

**Destructive / guarded actions (SETCAT-11 / D-10..D-12):**
- Turning a switch **OFF** when `ownTrailCount > 0` → intercept, fetch count via author-scoped `TrailFilter` query, show `AlertDialog`. Cancel reverts switch to ON (no save). Confirm proceeds to normal auto-save.
- Turning a switch **ON** → never guarded (D-11), saves immediately.
- Plugin-mapping warnings are NOT ported (D-13) — omit that messaging entirely.

## Interaction & State Contract

Enumerated so the executor implements every state (checker Dimension 2):

| Screen / element | State | Contract |
|------------------|-------|----------|
| SettingsCategoriesScreen | Loading | Wrap category + preference load in existing `AsyncLoader` (`app/lib/components/async_loader.dart`) — no bespoke spinner (D-14) |
| SettingsCategoriesScreen | Loaded | `ReorderableListView.builder`; rows sorted by priority asc, alphabetical (locale name) for ties (mirror `sortedCategoriesByPreference()`), each row: `Icons.drag_handle` (drag listener) → category `FaIcon`/icon → `displayName` → `Switch` (SETCAT-06) |
| Category row | Body tap | Navigate to `SettingsSubcategoriesScreen` passing the category (D-05). Tap on switch or drag handle must NOT navigate |
| Category row | Reorder | Drag via handle only (not whole row, D-01); on drop `POST /user-category-preference/reorder` with full ordered ID list (SETCAT-09/D-02) |
| Category row | Reorder failure | Revert list to pre-drag order + `error_saving_settings` toast (D-04) |
| Visibility switch | Toggle ON | Auto-save `PUT /user-category-preference`, optimistic via watched provider, no success toast (D-08) |
| Visibility switch | Toggle OFF (own trails = 0) | Auto-save as above |
| Visibility switch | Toggle OFF (own trails > 0) | Show confirm `AlertDialog`; cancel reverts to ON; confirm saves (D-10) |
| Visibility switch | Save failure | `error_saving_settings` toast; provider reverts optimistic state (D-08) |
| SettingsSubcategoriesScreen | Loading | Same `AsyncLoader` wrapper (D-14) |
| SettingsSubcategoriesScreen | Loaded | `ReorderableListView` of subcategories (drag handle + `Switch`), AppBar title = parent `displayName` (D-06) |
| SettingsSubcategoriesScreen | Empty (zero subcategories) | Render empty state copy above (D-07) — screen is still reachable |
| Subcategory row | Reorder | `POST /user-subcategory-preference/reorder` scoped to parent category (SETCAT-10/D-03); same revert-on-failure (D-04) |
| All screens | Reduced motion | Respect OS reduced-motion for the reorder drag animation (WCAG 2.1 AA + reduced-motion per PRODUCT.md); do not add gratuitous transitions |

**Elevation doctrine:** flat — borders/dividers only, no drop shadows (Material `elevation: 0` on AppBar/surfaces where the theme already sets it). The reorder drag-elevation shadow is Flutter's built-in `proxyDecorator`; leave default (it is the affordance signalling the dragged item) but do not add custom shadows elsewhere.
