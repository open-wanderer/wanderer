<objective>
Close the two major gaps UAT found in Phase 26 (both diagnosed with confirmed root causes), each in a different file:

- **Gap 1 (major, `trail_download_state_provider.dart`):** the unified id-42 aggregate progress bar resets downward once per completed package and finishes below 100%. Root cause: `updateAggregate()` re-reads each selected package's live `vectorProgress`/`demProgress` from `tileRepositoryStatusProvider` with a `?? 0.0` fallback, but `tile_repository_provider.dart` deliberately clears that same field to `null` the instant each package completes (its documented per-region "downloading" signal for the Settings/Regions screen). `updateAggregate()` can't tell "not started" from "just completed" — both read null — so each finished package's contribution snaps 1.0 -> 0.0. Fix: give `download()` its own completion-latching accumulator per package (mirroring how `lastTrailFraction` already latches), and gate the id-42 success on the region futures instead of firing it the instant the trail alone resolves.

- **Gap 2 (major, `tile_repository_manager.dart`):** a DEM package downloaded concurrently with Vector via the sheet shows "not downloaded" in Settings even though its file and package row exist. Root cause: `startVectorDownload` and `startDemDownload` each hold a stale `RegionEntity` snapshot; `startVectorDownload`'s late `box.put(region)` (for `lastDownloadedVersion`) re-serializes the whole row — including a `demPackage.targetId` captured BEFORE the concurrent DEM download linked its package — clobbering `demPackage.target` back to unset. Fix: re-fetch the current row from the box immediately before every region-row `put()` so the write carries only the caller's own change, never a stale full snapshot.

Purpose: Restore GUARD-03's "one combined, advancing progress bar" (D-10) and GUARD-02/03's promise that a selected DEM package actually registers as downloaded — without changing `tile_repository_provider.dart`'s clear-on-completion contract (gap 1) or serializing the two region downloads against each other (gap 2).
Output: Two patched files. No new files.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Ephemeral per-region progress -> aggregate notification integrity | `updateAggregate()` consumes `tileRepositoryStatusProvider`'s ephemeral `vectorProgress`/`demProgress`, which are cleared to null on completion for a DIFFERENT consumer (Settings/Regions).
