## Spacing Scale

Declared values (must be multiples of 4) — matches values already in use across `settings_offline_regions_screen.dart` and `track_save_options_sheet.dart`, both of which this phase's sheet directly mirrors:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps; vertical gap between a region-block's rows |
| sm | 8px | Compact spacing (drag-handle vertical padding, sheet-title vertical padding, gap between region blocks) |
| md | 12px | Icon-to-label gap in a row; internal row padding rhythm |
| lg | 16px | Default row/content padding (`EdgeInsets.all(16.0)`), sheet horizontal padding, gap before the Download button |
| xl | 24px | Bottom padding of the sheet (`24 + MediaQuery.viewInsets.bottom`, matches `track_save_options_sheet.dart` exactly — keeps the Download button clear of the on-screen keyboard/gesture bar) |
| 2xl | 32px | Not used at sheet-row level; reserved if a future empty/edge-case illustration is added (not needed for this phase) |
| 3xl | 48/64px | Not expected — this is a compact bottom sheet, not a full page |

Exceptions:
- **44px minimum touch target** on every `Checkbox`/`IconButton` in a region row — matches Phase 24's identical exception. Use `Checkbox`'s default Material tap target or `CheckboxListTile` (already ≥48px), never a bare `Checkbox` with no surrounding tap padding.
- **Drag handle**: `30×5px`, `BorderRadius.circular(24)`, `colorScheme.secondaryContainer` — copied verbatim from `track_save_options_sheet.dart`'s existing drag handle, not a new pattern.
- **Sheet top corners**: `BorderRadius.vertical(top: Radius.circular(20))` — same as `track_save_options_sheet.dart` and `travel_profile_sheet.dart`, the two existing bottom-sheet precedents in this app. This phase's sheet uses the identical shape, no deviation.

## Typography

Uses Flutter's default Material 3 `TextTheme` (this app's `AppTheme` does not override `textTheme`), scoped through `Theme.of(context).textTheme.*` — never a hardcoded `TextStyle` with a raw font size, matching every existing screen's convention including Phase 24's.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Label | 12px | 400 (regular) | 1.33 | `textTheme.bodySmall` — per-package size text ("120 MB"), combined-size summary line, locked/disabled captions, non-blocking warning sub-text |
| Body | 16px | 400 (regular) | 1.5 | `textTheme.bodyLarge` — dialog/sheet intro copy ("This trail needs offline map data for the following region(s):"), general secondary text |
| Row/Sheet Title (emphasis) | 16px | 700 (bold) | 1.5 | `textTheme.titleMedium!.copyWith(fontWeight: FontWeight.bold)` for the sheet title (matches `track_save_options_sheet.dart`'s exact precedent), `textTheme.bodyLarge!.copyWith(fontWeight: FontWeight.bold)` for each region-block's name (matches `settings_offline_regions_screen.dart`'s exact precedent) — same 16px/700 role reused in two contexts, not two separate styles |
| Heading | 22px | 400 (regular) | 1.2 | `textTheme.titleLarge` (Flutter's default `AlertDialog`/large-heading style) — reserved for the rare case a full-screen/dialog heading is needed (not the sheet itself, which uses the Title role above); kept for contract consistency with Phase 24's identical role table |

Exactly 4 distinct sizes (12/16/16-bold/22) and exactly 2 weights (400/700) — no Display role needed this phase (no large standalone numeric figure, unlike Phase 24's disk-usage headline).

## Color

Uses the app's existing `ColorScheme` (`AppTheme.createTheme`, `AppColors`) — this phase adds no new palette entries, only new *usages* of existing roles, all directly inherited from Phase 24's established conventions per `26-CONTEXT.md`'s explicit instruction to visually echo that screen.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `colorScheme.surface` — light `rgb(255,255,255)` / dark `rgb(18,20,28)` | Bottom sheet background |
| Secondary (30%) | `colorScheme.outline` (borders on each region block, matches `_ToggleCard`'s bordered-`Card` pattern) + `colorScheme.secondaryContainer` (drag handle) | Region-block card borders (flat, `elevation: 0` — "Terrain Log" doctrine: borders only, no shadows, per `track_save_options_sheet.dart`'s own doc comment), drag handle fill |
| Accent (10%) | `colorScheme.primary` (light) / `colorScheme.onSurface` (dark, matching `settings_offline_regions_screen.dart`'s exact `accentColor` derivation) | Reserved for exactly: (1) the checked state of each Vector/DEM `Checkbox`, (2) the primary "Download" button (`FilledButton`), (3) an in-flight package's `LinearProgressIndicator` fill color, if a row is already downloading when the sheet opens |
| Destructive | `Colors.red.shade400` / `Colors.redAccent` | Reserved for exactly: an already-erroring package row's caption/icon (mirrors Phase 24's `regions_download_failed` red convention) — this phase does not introduce any new destructive action of its own (no delete happens from this sheet) |
| Warning (non-destructive) | `Colors.orange` | Reserved for exactly: the D-04 non-blocking "part of this trail isn't covered by any offered region" notice — matches Phase 24's `updateAvailable` orange convention verbatim, deliberately distinct from red since this is never an error and never blocks the download |

Accent reserved for: checked checkboxes, the Download button, and an already-in-flight row's progress fill — never applied to plain body text, region-block borders, or disabled captions.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (sheet, GUARD-02/03/D-08) | "Download" (`FilledButton`, always enabled — works identically whether 0 or N region packages are checked; starts the trail plus every checked package in one tap, per D-08) |
| Sheet title (GUARD-02) | "Missing offline map coverage" |
| Sheet intro body (GUARD-02, Body role) | "{Trail name} isn't fully covered by your downloaded regions yet. Select any regions below to download them together with the trail — or tap Download to get the trail without them." |
| Region-block Vector checkbox label | "Vector" (reuses `regions_vector_tile_title` verbatim — same term as Settings) |
| Region-block DEM checkbox label | "Elevation data" (reuses `regions_dem_tile_title` verbatim) |
| Region-block per-package size (Label role) | "{formatted size}" e.g. "120 MB" — reuses `formatBytes()` from `byte_format_util.dart` verbatim, no new formatting rule |
| Combined-size summary (GUARD-03, Label role, above the Download button) | "{N} region(s) selected · {combined formatted size}" — e.g. "2 regions selected · 245 MB"; when 0 selected: "Downloading trail only" (this is what makes the D-08 "no full-coverage force" escape hatch visible, not just functional) |
| Already-downloading package row (edge case: a checked-elsewhere download already in flight when the sheet opens) | No checkbox — replaced by a `LinearProgressIndicator` + Label-role "Downloading..." caption, matching `settings_offline_regions_screen.dart`'s own in-flight row treatment; this package is implicitly included (it's already running) and is not part of the combined-size sum |
| Already-erroring package row (edge case) | Label-role red caption "Download failed" (reuses `regions_download_failed` verbatim) next to the checkbox — still selectable, checking it retries via the same `downloadVector`/`downloadDem` call |
| Non-blocking warning (D-04, orange, Label role) | Toast/inline notice: "Part of this trail isn't covered by any offered region." — never blocks; the trail download proceeds regardless. Shown via `toastProvider` (`ToastType.info`, orange-tinted per this phase's Warning role) when the guard finds a genuine no-region gap, matching how D-04 says the download must still start unblocked |
| Unified download notification title (D-10) | "Downloading offline content" when 1+ region packages are included alongside the trail; falls back to the existing per-trail-name title ("{trail name}") when the guard added nothing (0 regions selected — trail-only path, unchanged from today's `DownloadingTrailIds.download` behavior, GUARD-01's "starts immediately as before") |
| Unified download notification body (D-10) | "{done}/{total} · {N} item(s)" aggregate percentage text, reusing the existing notification's percentage-string convention (`'Downloading trail... {pct}%'` today) extended to "Downloading... {pct}%" when aggregating multiple sources |
| Full-coverage path (GUARD-01, no dialog) | No sheet, no copy change — the existing toast ("Downloading {trail.name}...") and notification flow run completely unchanged, exactly as today |

## Component & Pattern Inventory (executor reference)

Not part of the template's required tables, but recorded here since this phase's structural precedent is unusually strong and should not be re-derived:

- **Sheet shape**: `showModalBottomSheet` with `isDismissible: true`, `enableDrag: true`, `RoundedRectangleBorder(borderRadius: BorderRadius.vertical(top: Radius.circular(20)))` — copy `track_save_options_sheet.dart`'s `showTrackSaveOptionsSheet` function shape almost exactly (drag handle, title, scrollable body, bottom-padded `FilledButton`). Dismissing the sheet (swipe down / tap outside) closes it with no download started at all — distinct from tapping Download with 0 regions checked, which still starts the trail (D-08).
- **Region block**: a flat, bordered `Card` (`elevation: 0`, `side: BorderSide(color: colorScheme.outline)`, `borderRadius: 16`) per missing region — same "Terrain Log" doctrine as `_ToggleCard` in `track_save_options_sheet.dart` and every region row in `settings_offline_regions_screen.dart`. Inside: region name (Row Title role, bold), then a Vector `CheckboxListTile` and — only if the region has a DEM archive (`region.demUrl != null`, matching Phase 24's own gating precedent) — a DEM `CheckboxListTile`, each `dense: true` with the size in the subtitle.
- **Checkbox default state (D-07)**: Vector pre-checked, DEM unchecked, on sheet open, for every listed region — not just the first.
- **Combined-size summary**: a `Text` (Label role) recomputed on every checkbox toggle via local `setState`, positioned directly above the Download button — this is the only genuinely new small piece of UI in this phase; everything else reuses an existing pattern verbatim.
- **Download button**: `FilledButton`, full-width (`crossAxisAlignment: CrossAxisAlignment.stretch`, matching `track_save_options_sheet.dart`), label "Download", accent-colored per this phase's Accent role — always enabled, never disabled by empty selection (D-08).
- **Trigger point**: `DownloadingTrailIds.download(trail)` is the single shared entry point both call sites already use (per `26-CONTEXT.md`'s discretion note) — the coverage check + conditional sheet insert here, not duplicated at `trail_detail_screen.dart`/`trail_dropdown.dart`. This keeps GUARD-01's "checks before proceeding, starts immediately when fully covered" behavior structurally guaranteed rather than re-implemented per call site.
- **Unified notification (D-10)**: extend `DownloadNotificationService`'s existing single fixed-id (`42`) notification rather than adding new ones — reuse `showProgress`/`showSuccess`/`showError` with the aggregate title/body copy from the table above; do not spawn one notification per region package.
- **Progress aggregation math (D-10, implementation detail for planner/executor)**: sum `done`/`total` byte counts across the trail's `onProgress(done,total)` callback and each selected region package's `RegionDownloadState.vectorProgress`/`demProgress` (0.0–1.0 fractions × that package's known size from the catalog) into one combined done/total pair fed to `showProgress`.
