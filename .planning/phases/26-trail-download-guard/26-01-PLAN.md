<objective>
Create the pure, synchronous, unit-tested coverage logic that decides — from a trail's bbox and the local region catalog snapshot — which overlapping regions are NOT yet usable offline. This is the load-bearing decision the whole guard is built on (GUARD-01), and it is the single place GUARD-04 (`updateAvailable` counts as covered) is enforced.

Purpose: Isolate the one piece of genuine business logic in this phase as a pure function so it is deterministic, test-first, and consumed unchanged by the Plan 03 wiring — no widget, no I/O, no Riverpod.
Output: `app/lib/util/trail_coverage_util.dart` (three top-level functions) + `app/test/util/trail_coverage_util_test.dart` (table-driven tests).
</objective>

    - `overlappingRegions(trail, catalog)` returns every catalog region whose bbox overlaps the trail's bbox, regardless of that region's status.
    - `missingCoverageRegions(trail, catalog)` returns the subset of overlapping regions whose `status` is neither `RegionStatus.downloaded` nor `RegionStatus.updateAvailable` (GUARD-04: `updateAvailable` satisfies coverage; `notDownloaded`/`downloading`/`error` do not).

    - A trail overlapping no catalog region → BOTH lists are empty (no-region-gap case, D-04 — the caller distinguishes it by checking `overlappingRegions.isEmpty`).
    - An empty catalog → both lists empty, no throw.
  </behavior>
