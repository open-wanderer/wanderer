<objective>
Close the one BLOCKING gap and three non-blocking robustness findings that Phase 26 verification/code-review found in the single file `app/lib/provider/trail/trail_download_state_provider.dart`. The guard's `DownloadingTrailIds.download()` already computes coverage, shows the sheet, starts region packages in parallel, and drives a unified notification — but (1) it never re-invalidates `regionListNotifierProvider` after its own region downloads, so a live `RegionListNotifier` keeps reporting a just-downloaded region as missing (CR-02, blocking, undermines GUARD-04's "never re-fires for a region already fixed"), and (2) several statements run outside the state-cleanup `try/finally`, so an exception there permanently strands the trail's download button (CR-01), plus two notification-callback robustness gaps (WR-01, WR-02).

Purpose: Make the guard honor the documented `regionListNotifierProvider` invalidation contract (`region_provider.dart` doc comment: "callers must ref.invalidate(regionListNotifierProvider) after each mutation"), and make `download()` crash-safe and its aggregate notification stable — without changing any of the already-verified GUARD-01/02/03/04 behavior or button-unlock timing.
Output: A patched `DownloadingTrailIds.download()`. No new files.
</objective>
