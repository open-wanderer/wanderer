<objective>
Add the superuser-authenticated geometry endpoint (SLIM-05, per D-10 and D-13) and repoint the one admin-UI flow that needs it. The endpoint returns a leaf's boundary geometry and bbox on demand, converted server-side because CoMaps serves Osmosis-format `.poly` rather than GeoJSON, and it persists to `region_geometry` only when that region is currently enabled. Exactly one of the admin SPA's three geometry flows changes: `onLeafHoverStart`, which must preview leaves that are disabled and have never been built.

Purpose: this closes the loop that made an empty `region_geometry` viable — hover previews work without seeding geometry, and toggling a region on caches it as a side effect of drawing it.
Output: a new route, its registration, the repointed hover flow, and a `fitToEnabled` fix for bbox's relocation.
</objective>

  <action>
Create `db/routes/regions_geometry_get.go` in package `routes` with a single handler `func RegionGeometryGet(e *core.RequestEvent) error`.

Read the path parameter with `e.Request.PathValue("id")`, using the wildcard name `id` to match the sibling `/regions/{id}/download` routes. Reject immediately with `e.BadRequestError("invalid region id", nil)` when `regions.IsValidRegionID(id)` is false — this is the first and most important gate, because the value is client-supplied and eventually reaches both a database filter and, indirectly, outbound URL construction.

Look up the catalog row with `e.App.FindFirstRecordByFilter("regions", "path = {:path}", dbx.Params{"path": id})`. Return `e.NotFoundError("region not found", nil)` when the lookup fails or yields nil. Return `e.BadRequestError("region is not a leaf", nil)` when `GetString("kind")` is not `"leaf"` — group rows have no boundary, and refusing them here keeps a pointless upstream request from ever being issued.

Call `regions.ResolveGeometry(e.App, region)` passing the record itself. Do not read `enabled` in this handler, do not pass any persistence hint, and do not accept any query parameter that could influence whether a write happens: the whole point of D-10's rule is that persistence keys off actual catalog state rather than off which gesture called the endpoint. On error return `e.InternalServerError("could not resolve region geometry", err)`.

Respond with `e.JSON(http.StatusOK, ...)` carrying a map with three keys: `path` set to the validated id, `polygon` set to the resolved geometry, and `bbox` set to the resolved `[4]float64`. Name the geometry key `polygon`, not `geometry`, so the admin SPA's existing `item.polygon` handling stays shape-compatible and the client diff stays to one line.

Document in the handler's doc comment: why the conversion must be server-side (CoMaps serves Osmosis-format `.poly`, and converting it is `ParsePoly` with the multi-ring hole and exclave support Phase 28 deliberately built, so a client-side implementation would mean reimplementing that parser in JavaScript and widening the admin page's CSP to two more hosts); why the route is superuser-gated rather than merely authenticated (it triggers outbound third-party requests, so an authenticated-user gate would leave an open proxy and a way to burn CoMaps' rate limit from outside); and that persistence is decided inside `ResolveGeometry` from the region's own `enabled` field, so hovering a disabled region is a pass-through with no write.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser -> Go route | `{id}` is client-supplied and reaches a database filter, and indirectly the upstream URL builder via the looked-up record |
| unauthenticated internet -> Go route | the route triggers outbound third-party requests, so its auth gate is the difference between an admin tool and an open proxy |
| Go route -> `region_geometry` | request handling can cause a database write |
| admin page -> external hosts | any new fetch target would require a CSP change |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
