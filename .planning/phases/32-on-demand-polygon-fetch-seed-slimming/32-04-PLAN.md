<objective>
Make build-time geometry resolution self-healing (SLIM-03, per D-14, D-01, D-02) and finish moving `bbox` out of the catalog (SLIM-04, per D-12). `buildRegion` reads `region_geometry`; on an **absent or malformed** row it refetches from CoMaps and re-persists, overwriting the bad row; only a failed refetch calls `setError` and continues to the next region. `GET /api/v1/regions` sources leaf bbox from `region_geometry` instead of the `regions` record.

Purpose: geometry is now derived state with an authoritative upstream, so a bad or missing local copy is a cache fault rather than data loss — and today's `builder.go:238-241` dead-ends exactly that case with a bare `log` plus `return`, leaving a region permanently broken.
Output: a shared `ResolveGeometry`, a restructured `buildRegion`, and a bbox-joined region listing.
</objective>

Create `db/services/regions/geometry_store.go` in package `regions` with a single exported entry point shared by `buildRegion` and by plan 32-05's HTTP route:

`func ResolveGeometry(app core.App, region *core.Record) (map[string]any, [4]float64, error)`

The parameter is deliberately the leaf's own `regions` record rather than loose strings. That signature is the structural mitigation for the persistence threat: `persist` is derived **inside** this function as `region.GetBool("enabled")` and can never be supplied by a caller, by a request parameter, or by a query flag. There is no `?persist=` flag anywhere in this phase (D-10), and hover on a disabled region must remain a pass-through with no write (D-11). Both callers already hold this record, so the signature costs nothing.

Derive the four inputs from the record: `path` via `GetString("path")`, `comapsID` via `GetString("comaps_id")`, `commitSHA` via `GetString("catalog_commit")`, and `persist` via `GetBool("enabled")`. Reject up front with a descriptive error if `path` fails `IsValidRegionID`, if `comapsID` is empty, or if `commitSHA` is empty — a missing `catalog_commit` means the catalog predates plan 32-02's migration and geometry can never be fetched deterministically, which is worth failing loudly rather than silently defaulting to a hardcoded SHA.

Resolution order, which must follow D-14 strictly. First, look up the cached row with `app.FindFirstRecordByFilter("region_geometry", "path = {:path}", dbx.Params{"path": path})`, matching the `dbx.Params` idiom already used at `builder.go:231-232`. Then decide cache validity: the row is usable only if the lookup succeeded, `UnmarshalJSONField("polygon", ...)` produced a non-empty `map[string]any`, and `UnmarshalJSONField("bbox", ...)` produced a slice of exactly four elements. Treat an **absent row and a malformed row identically** — both fall through to the refetch. This is the trap the plan exists to close: a literal "fetch on cache miss" implementation silently skips the malformed case because a corrupt row exists, so there is no miss, and the region stays broken forever. If the cached row is usable, return its geometry and bbox with no network call, preserving the property that an unchanged region costs zero network.

On absent-or-malformed, call `FetchGeometry(commitSHA, comapsID)`. If it errors, return the error wrapped with the region's `path` so the caller's message identifies the region as well as the upstreams; the upstream names are already in `FetchGeometry`'s error text per plan 32-03.

Persist only when `persist` is true. Reuse the cached record if the lookup found one — updating it in place is what overwrites a malformed row (D-14 step 2) — and otherwise create a new record against the `region_geometry` collection resolved via `app.FindCollectionByNameOrId`. Set `path`, `polygon` and `bbox`, then `app.Save`. A persist failure must be logged and swallowed, not returned: the caller already has valid geometry in hand, and failing a build because a cache write failed would be strictly worse than proceeding. Return the freshly fetched geometry and bbox either way.

Document at the top of the file that build-path callers always satisfy the persist condition because `BuildAllLocked` only iterates enabled leaves, so the D-14 refetch always writes, while the HTTP route's disabled-region hover path deliberately does not.
