<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local repository -> published remote | a force-push replaces history other clones may already hold |
| historical objects -> fresh clones | any blob reachable from a ref is downloaded by every clone forever |
| rewrite tooling -> working history | an over-broad path filter can silently delete unrelated content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-27 | Denial of Service (irrecoverable history loss) | `git filter-branch` | mitigate | A backup tag is created and verified before the rewrite; the post-rewrite tree is diffed against that tag and must be empty; `--force-with-lease` aborts rather than overwriting a concurrently-updated remote |
| T-32-28 | Tampering (over-broad deletion) | `--index-filter` path pattern | mitigate | The filter targets the literal `.gz` path only. Verified during planning that `regions_seed.json` has zero prior blob history, so the new plain-JSON artifact cannot be caught by a path collision; the acceptance criteria assert the new artifact's blobs survive |
| T-32-29 | Repudiation (coordination failure) | force-push | mitigate | Gated behind a blocking `checkpoint:decision` that states the coordination cost explicitly, with a defer option; the SUMMARY must state that trackers reset rather than merge |
| T-32-30 | Information disclosure | purged blob | accept | The blob contains only public OSM-derived boundary data; the purge is about repository weight, not secrecy, so no credential-rotation follow-up is implied |
| T-32-SC | Tampering (dependency supply chain) | npm/pip/cargo/go installs | accept | No package installs in this plan. No dependency manifest is touched; `git-filter-repo` is only *considered* as an alternative and, if used, is an operator-invoked local tool rather than a project dependency |
</threat_model>
