<objective>
Close the five blocking gaps (CR-01 through CR-05) found by Phase 02 verification. These are code-correctness defects in already-shipped Phase 02 code — the structural wiring (routes, handlers, migrations) is present and builds/tests pass, but four logic defects break the follow lifecycle under realistic conditions and one error-masking defect hides failures from remote callers.

CR-01/CR-02 (double-delivery): the pre-existing user-level `CreateFollowHandler`/`DeleteFollowHandler` (Request-family hooks) have no `isInstanceFollow` guard, so creating/deleting an instance follow via the API fires BOTH the Request hook and the AfterSuccess handler → two Follow/Undo activities to the remote inbox.
CR-03 (wrong-direction fire): `InstanceFollowCreateHandler` uses `isInstanceFollow`, which is true when EITHER follower OR followee is the instance actor. On an inbound follow saved by `ProcessFollowActivity` (remote=follower, instance=followee), it mistakenly tries to sign a Follow as the remote actor (no local private key).
CR-04 (panic): `ProcessAcceptActivity` does an unguarded type assertion on `activity.Object`, panicking on IRI-only Accept objects (common in real ActivityPub implementations).
CR-05 (error masking): `InstanceInboxHandler` returns `e.JSON(http.StatusOK, procErr)` regardless of failure (Go errors serialize to `null` → remote sees 200 null) and has no default case for unrecognized types.

Purpose: make FLCL-01 and FLCL-05 actually correct (single delivery), make INST-03 robust (no panic, honest error status), and ensure the directional intent of FLCL-01 (admin-initiated OUTbound follow) holds. No new features; targeted correctness fixes only.
Output: guards added to two existing hooks + a directional guard in InstanceFollowCreateHandler (db/hooks/follow.go); comma-ok assertion in ProcessAcceptActivity (db/federation/follow.go); per-case error propagation + default case in InstanceInboxHandler (db/federation/instance.go); regression tests for CR-03 directional logic and CR-04 panic-safety.
</objective>
