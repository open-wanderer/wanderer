# Phase 7 — UI Design Contract

> Visual and interaction contract for the Privacy settings screen. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Platform: Flutter + Material Design (not web/React — shadcn gate not applicable). This screen mirrors the canonical `SettingsLanguageScreen` exactly; the contract below codifies that mirror so the executor produces a pixel-faithful copy.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Flutter Material Design, not React/Vite — shadcn gate not applicable) |
| Preset | not applicable |
| Component library | Flutter Material (`RadioGroup`, `RadioListTile`, `Scaffold`, `AppBar`, `ListView`) |
| Icon library | Material Icons (`Icons.arrow_back`) + Font Awesome Flutter (`FontAwesomeIcons.circleExclamation`, toast only) |
| Font | App theme default (IBMPlexSans / Noto Sans via `ThemeData`); no per-screen font override |

**Theme inheritance rule:** This screen sets NO explicit colors, font sizes, or paddings beyond what is listed in this contract. Everything else derives from `Theme.of(context)` so light/dark mode and the global type scale apply automatically. Do not hardcode hex colors or font sizes anywhere in `settings_privacy_screen.dart`.

## Layout Structure

Top-down widget tree (matches `SettingsLanguageScreen` structure, decision D-07):

```
ConsumerWidget
└─ Scaffold
   ├─ AppBar
   │   ├─ leading: IconButton(Icons.arrow_back) → context.pop()
   │   └─ title: Text(l10n.privacy)               // "Privacy"
   └─ body: ListView
       ├─ Section header: Padding + Text(l10n.account_privacy)   // "Account privacy"
       ├─ RadioGroup<String>  (account)  → 2 × RadioListTile<String>
       ├─ Section header: Padding + Text(l10n.trail(n: 2))       // "Trails"
       ├─ RadioGroup<String>  (trails)   → 2 × RadioListTile<String>
       ├─ Section header: Padding + Text(l10n.list(n: 2))        // "Lists"
       └─ RadioGroup<String>  (lists)    → 2 × RadioListTile<String>
```

**Body must be `ListView`** (not `Column`) so the three sections scroll on small viewports — identical to the Language screen.

**Section order is fixed:** Account → Trails → Lists.

**Each `RadioGroup` wraps a `Column` of two `RadioListTile<String>` children** (the account group differs only in its second label; trails and lists are structurally identical). Follow the Language screen's `RadioGroup<String>` units block as the template, not the `Language.values` loop.

## Spacing Scale

Declared values (Material 4dp grid; all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| sm | 8px | Section header bottom padding |
| md | 16px | Section header left/right/top padding; ListView horizontal rhythm |

**Exact spacing rules (copy verbatim from `SettingsLanguageScreen`):**

- **Section header padding:** `EdgeInsets.fromLTRB(16, 16, 16, 8)` — 16 left, 16 top, 16 right, 8 bottom. Applies to all three headers identically.
- **RadioListTile padding:** none added. Use the Material default `RadioListTile` content padding (do NOT wrap tiles in extra `Padding`). Subtitles render inside the tile's own vertical padding.
- **Between a `RadioGroup` and the next section header:** spacing comes entirely from the next header's 16px top padding — do NOT insert `SizedBox` or `Divider` between sections.
- **No leading/trailing ListView padding overrides** — default `ListView` padding applies, matching the Language screen.

Exceptions: none.

## Typography

All roles inherit from the global Material `TextTheme`. The screen declares exactly one explicit type role (the section header); every other text element uses the `RadioListTile` defaults.

| Role | Source | Weight | Color | Notes |
|------|--------|--------|-------|-------|
| AppBar title | `AppBar` default (`titleLarge`) | theme default | theme default | `Text(l10n.privacy)` |
| Section header | `textTheme.titleSmall` | theme default (titleSmall) | `colorScheme.onSurfaceVariant` | the ONE explicit override on this screen |
| Radio option label (`title`) | `RadioListTile` title default (`bodyLarge`/`titleMedium`) | theme default | theme default | `Text(l10n.public)` etc. |
| Radio option description (`subtitle`) | `RadioListTile` subtitle default (`bodyMedium`, `onSurfaceVariant`) | theme default | theme default | full description sentence; wraps to multiple lines |

**Section header style (exact, decision D-02):**
```dart
Theme.of(context).textTheme.titleSmall?.copyWith(
  color: colorScheme.onSurfaceVariant,
)
```

**Subtitle wrapping:** descriptions are full sentences (longest ~210 chars — the account-private string). They MUST wrap and the tile MUST grow vertically. Do not set `maxLines` or `overflow: ellipsis` on the subtitle — the user needs to read the full explanation.

## Color

This screen introduces no new color tokens. All color derives from the active `ColorScheme`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `colorScheme.surface` (theme) | Scaffold background, ListView surface |
| Secondary (30%) | `colorScheme.onSurfaceVariant` (theme) | Section header text, radio subtitle text |
| Accent (10%) | `activeColor` (see below) | Selected radio fill ONLY |
| Destructive | n/a | No destructive actions in this phase |

**Accent reserved for:** the selected `RadioListTile` indicator fill, and nothing else.

**`activeColor` rule (exact, brightness-aware — decision/code_context):**
```dart
final activeColor = Theme.of(context).brightness == Brightness.dark
    ? colorScheme.onSurface
    : colorScheme.primary;
```
Set `activeColor: activeColor` on every one of the six `RadioListTile` widgets. This matches the Language and Appearance screens exactly — in dark mode the selected radio reads as `onSurface`, in light mode as `primary`.

## Interaction Contract

**Selection model (decision D-03, D-04, D-05):**

- Radio `value`s are the plain strings `"public"` and `"private"` (matching the `SettingsPrivacy` model). The "Only me" label maps to value `"private"` — the label differs from the value.
- `groupValue` per section, with null-safe defaults (D-04):
  - account: `settings?.privacy?.account ?? "public"`
  - trails: `settings?.privacy?.trails ?? "private"`
  - lists: `settings?.privacy?.lists ?? "private"`

**Labels per section (decision D-03):**

| Section | Option 1 value | Option 1 label | Option 2 value | Option 2 label |
|---------|----------------|----------------|----------------|----------------|
| Account | `"public"` | `l10n.public` ("Public") | `"private"` | `l10n.private` ("Private") |
| Trails | `"public"` | `l10n.public` ("Public") | `"private"` | `l10n.only_me` ("Only me") |
| Lists | `"public"` | `l10n.public` ("Public") | `"private"` | `l10n.only_me` ("Only me") |

**Auto-save (decision D-05, D-06):** No Save button. On any radio change, build the updated privacy via `copyWith` preserving the other two fields, then call `_save`:
```dart
final updated = (settings.privacy ??
        const SettingsPrivacy(account: 'public', trails: 'private', lists: 'private'))
    .copyWith(account: value); // or trails:/lists:
_save(ref, l10n, settings.copyWith(privacy: updated));
```

**`_save` helper:** copy verbatim from `SettingsLanguageScreen._save` — `try { await ref.read(settingsProvider.notifier).saveToServer(updated); } catch (_) { toast error }`.

**Null-settings guard:** if `settings == null`, do not attempt save; surface the same error toast (mirror the Language screen's `onChanged` guard). `onChanged` also returns early when `value == null`.

**Selection feedback:** the only visible feedback on change is the radio indicator moving to the new option (optimistic — the watched provider updates after `saveToServer` succeeds). No spinner, no snackbar on success.

|---------|---------|------|

| Lists section header | `list(n: 2)` | "Lists" (ICU plural) |
| Account → Public label | `public` | "Public" |
| Account → Private label | `private` | "Private" |
| Trails/Lists → Public label | `public` | "Public" |
| Trails/Lists → Private label | `only_me` | "Only me" |

| Element | Copy |
|---------|------|
| Primary CTA | None — auto-save on selection; no button |
| Empty state heading | n/a — settings always present (defaults applied when `settings.privacy` is null) |
| Empty state body | n/a |
| Error state | Toast: "Error saving settings" (icon `circleExclamation`, type error) on `saveToServer` failure |
| Destructive confirmation | n/a — no destructive actions in this phase |

**i18n rule:** Every user-visible string is an `l10n.*` reference. No hardcoded display strings (unlike the Language screen's native-name map, which was a one-off exception; this screen has zero such exceptions). The string values `"public"` / `"private"` used as radio *values* are model values, not display copy, and are correctly hardcoded.
