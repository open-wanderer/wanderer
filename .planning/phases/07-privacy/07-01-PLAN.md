## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Flutter app → SvelteKit `/settings/{id}` endpoint | Authenticated settings update crosses here via `apiProvider` (dio). Privacy values originate from a fixed two-option radio set, not free text. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | Privacy values sent to `saveToServer` | mitigate | Radio `value`s are hardcoded to the closed set `"public"`/`"private"`; no user free-text reaches the model. The screen never constructs arbitrary privacy strings. |
| T-07-02 | Information Disclosure | Default visibility when `settings.privacy` is null | accept | Defaults match web-client parity (account public, trails/lists private — D-04). Trails/lists defaulting to private is the more conservative choice; account-public default is an intentional product parity decision, not a leak. |
| T-07-03 | Elevation of Privilege | Saving another user's settings | mitigate | `_save` posts to `/settings/${settings.id}` using the id from the authenticated `settingsProvider`; server-side PocketBase collection rules enforce ownership (existing infra, unchanged). The client cannot target a foreign settings id. |
| T-07-04 | Repudiation | Silent optimistic save | accept | On `saveToServer` failure an error toast (`error_saving_settings`) is shown; success is reflected by the watched provider re-rendering the new selection. No audit log needed for a personal preference toggle. |
| T-07-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager installs in this phase — zero new dependencies (`font_awesome_flutter`, `flutter_riverpod`, `go_router`, `objectbox` all already present). No legitimacy checkpoint required. |
</threat_model>
