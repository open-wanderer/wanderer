## Phase Boundary

Fill the stub `SettingsPrivacyScreen` with three `RadioGroup<String>` sections — account, trails, and lists visibility — each with public/private radio options and subtitle descriptions. Changes auto-save to the server via `settingsProvider.saveToServer()` on selection.

Requirements covered: PRIV-01, PRIV-02, PRIV-03

</domain>

<decisions>
## Implementation Decisions

### Radio option descriptions
- **D-01:** Each radio option shows a **subtitle** (the descriptive explanation text) using `RadioListTile.subtitle`. All 6 ARB keys already exist (`settings_privacy_account_public`, `settings_privacy_account_private`, `settings_privacy_trails_public`, `settings_privacy_trails_private`, `settings_privacy_lists_public`, `settings_privacy_lists_private`). This matches the web client exactly.

### Section headers
- **D-02:** Three section headers, styled as `Padding + Text(titleSmall, color: onSurfaceVariant)` — identical to the Language & Units screen pattern:
  - Account section → `l10n.account_privacy` ("Account privacy")
  - Trails section → `l10n.trail(n: 2)` ("Trails")
  - Lists section → `l10n.list(n: 2)` ("Lists")

### Radio values and defaults
- **D-03:** Values are `"public"` and `"private"` (plain strings matching the `SettingsPrivacy` model). Labels: `l10n.public` / `l10n.private` for account; `l10n.public` / `l10n.only_me` for trails and lists — matching the web client's label choices.
- **D-04:** Null privacy defaults match the web client: account defaults to `"public"`, trails defaults to `"private"`, lists defaults to `"private"`. Applied via `settings?.privacy?.account ?? "public"` etc.

### Save pattern
- **D-05:** Auto-save on selection — no Save button. Use `SettingsPrivacy.copyWith()` to update only the changed field, preserving the other two values with null-safe fallbacks. Pattern:
  ```dart
  final updated = (settings.privacy ?? const SettingsPrivacy(account: 'public', trails: 'private', lists: 'private'))
      .copyWith(account: value);
  _save(ref, l10n, settings.copyWith(privacy: updated));
  ```
- **D-06:** `_save` helper follows the Phase 6 pattern exactly: `await ref.read(settingsProvider.notifier).saveToServer(updated)` in a try/catch that surfaces a toast with `l10n.error_saving_settings` on failure.

### Screen structure
- **D-07:** `ConsumerWidget` → `Scaffold` → `AppBar` (back nav via `context.pop()`) → `ListView` body with three `RadioGroup<String>` sections separated by section label `Padding` widgets. Identical structural pattern to `SettingsLanguageScreen`.

</decisions>
