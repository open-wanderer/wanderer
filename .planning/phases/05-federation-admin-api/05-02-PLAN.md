<objective>
Add the three follow-lifecycle write handlers to `db/routes/federation_admin.go`:
`POST /federation/follow` (create outbound follow → hook delivers Follow),
`POST /federation/approve/:id` (inbound pending → accepted → hook delivers Accept),
`POST /federation/reject/:id` (inbound pending → rejected → hook delivers Reject).

Purpose: Satisfy CONN-01 (outbound follow appears as Outbound/Pending), CONN-02 (approve
inbound → Accept), CONN-03 (reject inbound → Reject), and enforce SAFE-07 (handlers only
write DB records; hooks own all ActivityPub delivery). These are thin DB-write wrappers
that depend on the shared helpers from Plan 01.

Output: `FederationFollow`, `FederationApprove`, `FederationReject` added to the existing
`db/routes/federation_admin.go`; tests added to `db/routes/federation_admin_test.go`.
Route registration happens in Plan 03.
</objective>
