<objective>
Complete the federation admin API: add the direction-aware disconnect handler and the peer
list handler to `db/routes/federation_admin.go`, then register all six routes in
`db/main.go`.

`POST /federation/disconnect/:id` is direction-aware (CONN-04): outbound follows are deleted
(the after-delete hook delivers Undo{Follow}); inbound-only follows are set to status
"rejected" (the after-update hook delivers Reject{Follow}) — because
InstanceFollowDeleteHandler fires Undo for ANY instance follow, deleting an inbound-only
record would send a wrong-direction Undo (Pitfall 3, verified at db/hooks/follow.go:172-184).

`GET /federation/peers` returns a lightweight array `[{ follow_id, direction, status,
domain }]` with mutual pairs collapsed (D-04, D-05).

Purpose: Satisfy CONN-04 (direction-aware disconnect), the peer-list slice of DISC-01,
SAFE-07 (DB-only writes), and complete route wiring so all six endpoints are reachable.

Output: `FederationDisconnect`, `FederationPeers`, and the pure helper `buildPeerEntries`
added to `db/routes/federation_admin.go`; six route registrations in `db/main.go`; tests in
`db/routes/federation_admin_test.go`.
</objective>

    6. Return `e.JSON(http.StatusOK, map[string]any{"status": "ok"})`.

    directly (SAFE-07).

    `disconnectAction(followerID, localID string) string` returning "delete" when
    followerID == localID, else "reject". Add unit tests:
    - TestDisconnectActionOutbound: followerID == localID → "delete"
    - TestDisconnectActionInbound: followerID != localID → "reject"
    Optionally add an app-level test that an inbound-only record after disconnect has status
    "rejected" and still exists (was NOT deleted), using the follow_test.go bootstrap.
  </action>

    - Disconnecting an inbound-only follow (local is followee) sets status="rejected" and does NOT delete the record (hook sends Reject)

## Trust Boundaries

|----------|-------------|
| admin client → /federation/disconnect | Untrusted request triggers delete-or-status-update that drives Undo/Reject delivery via hooks |
| admin client → /federation/peers | Read-only enumeration of all peer connections (superuser only) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-10 | Spoofing | wrong Undo direction on inbound-only disconnect | mitigate | disconnectAction routes inbound-only to status=rejected (Reject), never delete (Undo); verified at db/hooks/follow.go:172-184 which fires Undo on ANY instance-follow delete |
| T-05-11 | Elevation of Privilege | disconnect/peers without superuser | mitigate | e.HasSuperuserAuth() guard is first statement in both handlers → 401 (D-10) |
| T-05-12 | Information Disclosure | peer list exposed to non-admin | mitigate | FederationPeers superuser guard restricts enumeration to PocketBase superusers only |
| T-05-13 | Tampering | direct ActivityPub delivery from handlers | mitigate | SAFE-07: disconnect/peers call only app.Delete/app.Save; grep for Create*Activity returns 0 |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | No new packages; existing Go module imports only (RESEARCH.md Package Legitimacy Audit) |
</threat_model>
