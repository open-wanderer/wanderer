Remove the trail-scoped tile-download machinery from every runtime code path: the Phase 26 guard's `onGeneratingChanged`/`showGenerating` wiring (D-03), the now-dead `DownloadNotificationService.showGenerating()` spinner (D-07), the three tile-download methods plus all their generating-state/tile-I/O wiring inside `TrailDownloadService` (D-01, D-02), and the orphaned `map_cell.dart` deserialization model. Purpose: The region-based tile system (Phases 22-26) is now the sole tile path; the trail-scoped tile pipeline that Phase 25 already stopped reading from is dead weight and must be deleted outright — no dual-run, no migration (app is pre-production). Matches ROADMAP Phase 27 success criterion #1.
Output: `downloadTrail()` reduced to photo + waypoint-photo + nav-cache download with real progress reporting (D-04); `map_cell.dart` (+ generated siblings) deleted; `showGenerating()` deleted after a fresh grep confirms zero remaining callers; the project compiles clean and `flutter test` passes with the 26-04/26-05 invariants intact.

Ordering rationale: The provider edit lands FIRST (Task 1) so every boundary stays compilable — the service still accepts the now-unused optional `onGeneratingChanged` param until Task 2 removes it. This lets both tasks run a full-project `flutter analyze` + `flutter test`, unlike a service-first ordering which would break the provider call site mid-phase.

No task addresses CLEAN-02; its absence is intentional, not a gap.
