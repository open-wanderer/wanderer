<objective>
Close UAT gap 1 (minor): "The own trails list shows a spinner every so often."

`trailFilterProvider` rethrows every offline `GET /trail/filter` failure as a plain
`Exception`, which opts it into Riverpod 3's `defaultRetry` (10 attempts, 200ms doubling
to a 6400ms cap). Each retry emits through `ProfileTrailsNotifier.build`'s `ref.watch`,
and `ref.watch` invalidates with `asReload: true`, so the list transitions to a genuine
`AsyncLoading`. `profile_trail_screen.dart:90` uses `.when()` with the default
`skipLoadingOnReload: false`, so every one of those ~20 emissions blanks the list.

This plan fixes all three layers, source-first: the filter no longer errors when the
device is merely offline (so there is nothing to retry), the list no longer rebuilds on
filter-provider churn even if it does error, and the screen no longer discards data it
already holds.

Purpose: REC-06 requires the offline own-trails list to render. It renders, then
flickers to a spinner ~20 times over ~45 seconds, and drives ~20 dead network fetches
plus spurious `drainIfOnline()` kicks while the hiker just sits on the screen.

Output: a filter provider with an offline fallback and a bounded retry policy, a list
provider decoupled from filter churn, and a screen that keeps its rendered list across
reloads.
</objective>

Interface facts the executor needs (already verified, do not re-derive):

- `TrailFilter` and `TrailFilterValues` are both `@freezed` (`app/lib/models/trail.dart:208`
  and `:373`), so they have value equality. That is what makes `.select` effective.
- `TrailFilterValues` fields: `minDistance`, `maxDistance`, `minElevationGain`,
  `maxElevationGain`, `minElevationLoss`, `maxElevationLoss`, `minDuration`, `maxDuration`
  — all `required double`.
- `TrailFilter.toFilterText()` (`app/lib/models/trail.dart:247`) emits an upper-bound
  clause **only** when `distanceMax < distanceLimit` (and the same for elevation gain /
  loss). Today's `build()` sets max == limit for all three, so a fallback that also sets
  max == limit produces byte-identical filter text to a server-sourced default. The
  fallback constants therefore bound slider ranges only; they can never exclude a trail.
- `isConnectionFailure(DioException e)` lives in
  `app/lib/provider/online_status_provider.dart:28` and is the app's single "the request
  never reached a server" predicate. `badResponse` is deliberately excluded from it.
- `TrailFilterNotifier.defaultFilter` is `late` and deliberately **not** `late final` —
  the Notifier survives rebuilds and only `build()` re-runs, so `late final` throws
  `LateInitializationError` on the second build. Do not change this.
- `riverpod_annotation` 4.0.2 supports `@Riverpod(retry: <top-level fn>)`; the generator
  (`riverpod_generator` 4.0.3) emits `retry: <identifier>` into the `.g.dart`.
- `_fetchPage` already handles a null filter (`filter?.toFilterText() ?? ''`), so the
  own-trails list never depended on the filter provider succeeding.
