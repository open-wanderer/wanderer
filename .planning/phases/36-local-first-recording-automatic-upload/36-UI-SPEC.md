# Phase 36 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** this phase is Flutter/Dart mobile (`app/lib/**`), not the SvelteKit web app. The shadcn gate does not apply — there is no `components.json`, no React/Next/Vite stack. The design system is the app's existing Material 3 theme (`app/lib/theme/theme.dart`, `colors.dart`), already established across five shipped milestones. This spec extends that system; it does not introduce a new one.

No `PRODUCT.md`/`DESIGN.md` exist in this repo despite CLAUDE.md's "Design Context" section referencing them (near-monochromatic Polar Night palette, IBM Plex Sans) — that section appears to describe an intended visual language, and the app's actual `AppColors`/`AppTheme` already match it (dark slate-blue primary `rgb(36,39,52)`, `IBMPlexSans` font family). Treated as ground truth below.

## Spacing Scale

This phase adds no new spacing tier. Reuse the increments `trail_card.dart`/`trail_list_item.dart`/`trail_dropdown.dart` already establish:

| Token | Value | Usage |
|-------|-------|-------|
| xxs | 3-4px | Icon-to-label gaps inside a badge/chip |
| xs | 6-8px | Compact row spacing (badge row gaps, chip padding) |
| sm | 10-12px | Element spacing within a card (thumbnail-to-content gap) |
| md | 16px | Card padding, section spacing |
| lg | 24px | Screen-edge horizontal padding (`library_screen.dart`, `EdgeInsets.symmetric(horizontal: 24.0)` on empty states) |

Exceptions: the codebase does not enforce a strict 4px-multiple discipline (3px, 5px, 6px, 10px all appear in `trail_card.dart`/`trail_list_item.dart`). These are documentation of pre-existing code only — they are not licensed for reuse. New elements this phase adds (sync-status chip, dialogs) MUST use only 4/8/12/16 to avoid adding a fifth ad-hoc increment — match the *nearest* existing sibling, don't invent a new one, and never copy a 3/5/6/10px value into new code.

## Typography

No new type scale — reuse the sizes already in play on the cards this phase modifies.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Sync-chip label | 11px | 400 regular (all states, incl. Failed) | 1.3 |
| Card metadata (date/author) | 12px | 400 regular | 1.3 |
| Card title | 15px (list item) / 17px (card) | 700 bold | 1.2 |
| Dialog body | Flutter `AlertDialog` default (`bodyMedium`, ~14px) | 400 regular | 1.4 |

Only two weights in use: 400 regular and 700 bold. The Failed sync-chip label stays 400 regular, same as Pending/Uploading — it does not need its own weight variant because `Colors.red` plus the `triangleExclamation` icon (see Color, New Components & States) already carry the emphasis a heavier weight would otherwise add.

Font family is `IBMPlexSans` everywhere via the app theme — never set a different family in new widgets.

## Color

Reusing `AppColors`/`ColorScheme` from `app/lib/theme/`. No new palette entries.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `backgroundLight` `#FFFFFF` / `backgroundDark` `#12141C` | Screen surfaces, card backgrounds |
| Secondary (30%) | `secondaryLight` `#E5E7EB` / `secondaryDark` `#2D3241` (`colorScheme.surfaceContainer`) | Card containers, badge/chip backgrounds — same tokens `_BadgeWrapper`/`_BadgeIcon`/`_Chip` already use |
| Accent (10%) | `primaryLight` `#242734` / `primaryDark` `#3E435B` | Reserved for: selected-trail card border/checkmark (existing), primary buttons, the **Uploading** spinner tint. Not used for Pending or Failed states — those are not the "do this now" affordance. |
| Destructive | `Colors.red` (Material red, literal — the codebase uses this directly, NOT `colorScheme.error`) | Reserved for: delete confirmations (existing `_confirmDelete` red text), error toasts (existing `ToastType.error`), and — new this phase — the **Failed** sync badge/chip and its retry affordance |

**Do not use `colorScheme.error`/`onError`** (`#FEF2F2`/`#4C1111`) for the Failed sync state — that pairing is reserved for input-field validation backgrounds (`AppTheme.inputDecorationTheme` is its only current consumer) and would look wrong as an icon/chip color against the card surface. Use `Colors.red`, matching every existing destructive/error affordance in `lib/components/trail/`.

Accent reserved for: selected-card border + checkmark badge (existing), `ElevatedButton` fills (existing), the in-flight upload spinner (new, matches the existing download spinner's `CircularProgressIndicator` default tint from `progressIndicatorTheme`).

## New Components & States (this phase)

### Sync-status indicator (REC-03, D-08, D-09, SYNC-02, SYNC-03)

A new `_SyncStatusChip` rendered on `trail_card.dart` and `trail_list_item.dart`, positioned directly below the trail title (above the date/author row) — not merged into the existing top-right public/shared `_BadgeWrapper`/`_BadgeRow` group, because D-09 requires this to read as one clearly separate axis ("is this on the server"), not another flag alongside visibility. A small icon-only badge risks failing REC-03's "visibly distinguishable" bar on its own; a labeled chip does not.

| State | Icon | Color | Label copy | Interaction |
|-------|------|-------|-------------|-------------|
| Synced | — (chip absent entirely) | — | — | none — D-08 locks "synced shows nothing at all" |
| Pending | `FontAwesomeIcons.cloudArrowUp` (upload direction — deliberately distinct from the download badge's `cloudArrowDown`/`circleCheck`) | `onSurface` at 60% alpha (muted, matches existing secondary-text treatment) | "Waiting to upload" | not tappable |
| Uploading | `CircularProgressIndicator` (12-14px, `strokeWidth: 2` — same shape as the existing `isDownloading` spinner in `trail_dropdown.dart:114-118`) | `primaryColor` (theme default via `progressIndicatorTheme`) | "Uploading…" | not tappable |
| Failed | `FontAwesomeIcons.triangleExclamation` | `Colors.red` | "Upload failed · Tap to retry" | tappable → calls the drain provider's manual retry (SYNC-03), same tap target as the label |

Chip shape: same visual language as the existing `_Chip` tag chips (`horizontal: 8, vertical: 4` padding, `BorderRadius.circular(8)`, background `colorScheme.surfaceContainerHighest`) — icon + label in a `Row`, `mainAxisSize: MainAxisSize.min`, 4px gap between icon and text.

### `trail_dropdown.dart` — download action for an unsynced trail (D-17)

**Hide** the Download menu item entirely when the trail is unsynced (`trail.id.isEmpty` / sync state != Synced), rather than showing it disabled. Rationale: a disabled item with no explanatory affordance (this app's `PopupMenuItem` pattern has no tooltip-on-disabled convention) reads as broken, not "not available yet." The existing `_allowDelete`/`downloadEnabled` gating already branches on trail state in this exact file — extend the same `if` structure, don't add a new disabled-visual pattern.

### `trail_dropdown.dart` — delete action for an unsynced trail (D-14)

Reuses the existing `_confirmDelete` → `AlertDialog` pattern verbatim, with **new copy** (see Copywriting Contract) stating the deletion is unrecoverable — the existing `delete_trail_confirm` string ("cannot be undone") already carries that tone but must be read carefully: it currently doubles as the *download-removal* confirm text too (`library_screen.dart`'s `_confirmDelete` reuses `l18n.delete_trail_confirm` for un-downloading, which genuinely IS undoable via re-download). An unsynced trail needs its **own** l10n key so the two flows never share misleading copy. Blocked while draining: the delete menu item/dialog trigger must be disabled (not hidden — the hiker should see delete exists but understand why it's blocked) whenever the drain provider's in-flight set contains this trail's local id, mirroring the `isDownloading`-gated `downloadEnabled` pattern already in this file.

### Sign-out warning dialog (D-12)

New `AlertDialog`, same shape as `_confirmDelete` (title-less `content` + `Cancel`/confirm `TextButton` pair). Fires only when the unsynced-trail count for the current account is > 0. Copy names the count (see Copywriting Contract). Confirm action proceeds with sign-out unchanged — this is a warning, not a hard stop.

### Own-trails list offline banner + empty state (REC-06)

`/profile/<handle>/trails` becomes local-first (merges ObjectBox + network, per RESEARCH.md). When offline, add a persistent, non-dismissable banner above the list — same treatment tier as `library_screen.dart`'s empty-state pattern, not a toast (a toast would disappear before the hiker reads it, and this is a standing condition, not a one-off event). Empty state (offline AND nothing to show) reuses `_LibraryEmptyState.icon` verbatim (it is a private class today — promote to a shared widget or duplicate the pattern exactly; do not invent a third empty-state visual language) with `FontAwesomeIcons.cloudArrowUp` (mirrors the Pending badge's icon choice for visual consistency) instead of `cloudArrowDown`.

### Photo copy failure (D-03)

Toast via the existing `toastProvider`/`ToastMessage` pattern (`ToastType.error`, `FontAwesomeIcons` triangle/circle-exclamation icon — matching the existing `error_saving_trail` toast's icon choice), fired once per save if any photo copy fails. The trail save itself still succeeds — this is an informational, not blocking, toast.

## Copywriting Contract

All new strings are l10n keys in `app/lib/i18n/app_en.arb` per project convention (13 other locales fall back to English automatically).

| Element | Copy | l10n key (suggested) |
|---------|------|----------------------|
| Primary CTA (manual retry, SYNC-03) | "Retry upload" | `retry_upload` |
| Sync chip — Pending | "Waiting to upload" | `sync_pending` |
| Sync chip — Uploading | "Uploading…" | `sync_uploading` |
| Sync chip — Failed | "Upload failed · Tap to retry" | `sync_failed` |
| Empty state heading (offline, nothing saved) | "Nothing saved yet" | `own_trails_empty_title` |
| Empty state body | "Trails you record or save offline appear here, and upload automatically once you're back online." | `own_trails_empty_body` |
| Offline banner (REC-06) | "Showing what's saved on this device — connect to see everything." | `own_trails_offline_banner` |
| Error state (photo copy failure, D-03) | "Trail saved, but {count} photo(s) couldn't be saved." | `photo_copy_failed_toast` |
| Destructive confirmation — delete unsynced trail (D-14) | "Delete this trail? It hasn't been uploaded yet, so this can't be undone." | `delete_unsynced_trail_confirm` |
| Destructive confirmation — sign out with unsynced trails (D-12) | "You have {count} trail(s) not uploaded yet. Signing out won't delete them — they'll be here when you sign back in — but they won't upload until then." | `signout_unsynced_warning` |

Existing strings reused unchanged: `cancel`, `delete`, `download`, `available_offline`, `error_saving_trail`.
