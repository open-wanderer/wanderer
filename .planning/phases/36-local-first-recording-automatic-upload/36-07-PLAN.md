<objective>
Make `/profile/<handle>/trails` local-first for the signed-in hiker's own handle: read owner-scoped
`TrailEntity` rows from ObjectBox, merge them with the existing network search page deduped by server
id, state plainly when the list is showing only what is on the device, and route a tap on an unsynced
trail to the offline-capable edit screen.

Purpose: this screen is 100% network today with no ObjectBox fallback, and its `TrailSearchResult`
model has no concept of "unsynced" — so an unsynced trail can only ever surface through the local
half of a merge. REC-02 and REC-06 both live here, and the roadmap already flagged it as a meaningful
chunk of the phase rather than a detail.

Output: a pure merge function with tests, a hybrid provider, and the screen's offline affordances.
</objective>

Create `app/lib/util/own_trails_merge.dart` as a pure, dependency-light library — no Riverpod, no ObjectBox, no `dart:io`.

- `List<TrailSummary> mergeOwnTrails({required List<Trail> local, required List<TrailSearchResult> network})`. Emits the local rows first in the order given, then every network result whose `id` is not among the non-empty ids of the local rows. Document the two things this ordering buys: a just-saved trail is visible at the top immediately (REC-02), and a trail that has finished uploading appears exactly once rather than twice, because its local row and the server's search hit share an id (SYNC-05). Note that a local row with an empty id can never collide with a network result, which is why the id set is built from non-empty ids only. Produce one flat list — D-11 explicitly rules out sectioning or a special sort mixing unsynced and downloaded-authored-by-me rows.
- `List<Trail> filterOwnTrailsByQuery(List<Trail> local, String q)`. Returns `local` unchanged for an empty or whitespace-only query; otherwise keeps rows whose `name`, or non-null `location`, contains the query case-insensitively. The network half is already filtered server-side by Meilisearch; this is the local half's equivalent so a search does not make locally-held trails vanish from the list.

Create `app/test/util/own_trails_merge_test.dart` covering:
- local rows come first, in the order supplied
- a network result whose id matches a local row's id is dropped
- a network result with a different id is kept
- two local rows with empty ids do not suppress any network result
- an empty local list returns the network list unchanged, and an empty network list returns the local list unchanged
- `filterOwnTrailsByQuery` returns the input unchanged for `''` and for `'   '`
- `filterOwnTrailsByQuery` matches case-insensitively on name and on location, and excludes a non-matching row

Construct fixtures with plain `Trail(...)` and `TrailSearchResult(...)` constructors — no Store, no provider container.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| account A rows → account B's rendered list | Both accounts' captured trails share one ObjectBox store; only the owner predicate separates them |
| another hiker's handle → local read | The same provider serves any profile handle, but only the signed-in hiker's own handle may read local rows |
| network search hits → merged list | Server-supplied summaries are concatenated with device-held models in one rendered list |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-07-01 | Information Disclosure | local half of `build(handle)` | mitigate | The local read runs only when `handle` equals the signed-in user's `'@$preferredUsername'`, and `readOwnLocalTrails` additionally filters on `TrailEntity_.owner.equals(currentAccountId(store))` read fresh — a different account signed in on the same device gets an empty local half (D-13, ASVS V4) |
| T-36-07-02 | Information Disclosure | another hiker's profile page | mitigate | A non-own handle takes an empty local list unconditionally, so no device-held content can leak onto someone else's profile |
| T-36-07-03 | Tampering | duplicate rendering after upload | mitigate | `mergeOwnTrails` drops any network hit whose id matches a local row's non-empty id; unit-tested (SYNC-05) |
| T-36-07-04 | Denial of Service | one corrupt cached row blanking the list | mitigate | `readOwnLocalTrails` already guards `toModel()` per entity (36-03); the provider additionally never rethrows a failed network page for the own handle |
| T-36-07-05 | Repudiation | silently showing a partial list | mitigate | The `offline` flag drives a persistent banner stating the list is device-only, so a missing server trail is explained rather than invisible (REC-06) |
</threat_model>
