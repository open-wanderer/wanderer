<objective>
Close UAT gap 3 (major): "After saving edits on a non synced trail the 'own trail' list
needs a manual reload before edits are shown."

`trail_create_screen.dart` contains zero `invalidate`/`refresh` calls. Its shared
local-first save tail `_finishLocalSave` (714-762) commits to ObjectBox, drains, toasts
and `setState`s its own `trail` field — and notifies nobody else. The app has no ObjectBox
`Query.watch()` streams anywhere, so a row mutation emits no signal at all, and the
own-trails list stays mounted beneath the pushed edit route (`maintainState: true`),
keeping its auto-dispose provider alive with pre-edit state. The three existing
`invalidate(profileTrailsProvider(...))` sites cover successful drain upload,
`deleteUnsynced` and server-side delete — none of which fires on an offline edit.

Purpose: REC-05 promises the hiker can edit an unsynced trail offline. The edit lands in
ObjectBox but is invisible until a manual pull-to-refresh, which reads as data loss.

Output: one canonical family-key function used by every own-trails invalidation and
comparison in `app/lib`, plus both save tails wired to it.
</objective>

        /// The local-first save path commits to ObjectBox and this app has no
        /// ObjectBox `Query.watch()` streams anywhere, so an explicit
        /// invalidate is the ONLY propagation mechanism that exists. Without

        /// route (`maintainState: true`), keeping its auto-dispose provider
        /// alive -- holds its pre-edit snapshot until the hiker
        /// pull-to-refreshes, which reads as the edit having been lost.
        ///
        /// Invalidates the same PAIR `trail_sync_provider` already invalidates
        /// after a successful drain, keyed through `ownTrailsHandle` so the
        /// family key can never drift from the one `profile_trail_screen`
        /// watches. The username is read fresh from `authProvider` at the
        /// moment of use, never cached (D-13).
        ///
        /// Both invalidations use riverpod's default `asReload: false`, i.e. a
        /// seamless refresh -- `AsyncValue.when`'s `skipLoadingOnRefresh`
        /// defaults to true, so the list updates without flashing a spinner.
        void _invalidateOwnTrailsList() {
          ref.invalidate(trailLibraryProvider);
          final preferredUsername =
              ref.read(authProvider).value?.preferredUsername;
          if (preferredUsername != null) {
            ref.invalidate(
              profileTrailsProvider(ownTrailsHandle(preferredUsername)),
            );
          }
        }
