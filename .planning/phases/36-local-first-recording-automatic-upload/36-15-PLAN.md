<objective>
Close CR-02: `TrailSync.deleteUnsynced` currently decides "does the server hold a copy of this
trail?" by calling `readLocalTrail`, which returns `null` on **any** `toModel()` failure —
including `parseGpxSafely` throwing on cached GPX. `deleteLocalTrailRow` then runs
unconditionally, so a row that renders broken (exactly the row a hiker reaches for Delete on)
has its local copy and photos destroyed while a live, possibly-public server trail survives
with no device left pointing at it. That is the CR-04 orphan verbatim, behind a narrower
trigger.

Also closes the four warnings that live on the same code path and were made worse by the
CR-04 fix: WR-08 (an unsynced trail with a null `localId` falls through to a silent
un-download while the confirm dialog promised a server delete), WR-10 (the local delete path
is the one unscoped read/write in an otherwise account-scoped file — and CR-04 added a third),
WR-15 (any DELETE failure now makes a trail permanently undeletable, under a hardcoded English
literal, with the exception bound but never logged), WR-17 (a server-supplied record id
interpolated straight into a Dio path with no validation, in a phase that shipped
`recordIdDirSegment` for exactly this class of value).

Purpose: the delete affordance is the only way a hiker can remove a capture, and every one of
these defects turns it into either silent data loss or a permanent dead end.
Output: an owner-scoped, parse-independent delete decision; a classified failure path; and a
dropdown whose dialog and executor can no longer disagree.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PocketBase response → Dio request path | `TrailEntity.id` originates in a server response body (`trail_sync_provider.dart:218`, `rawBody['id']`) and is interpolated into `/trail/{id}` under an authenticated session |
| Account A's persisted rows → account B's session | `Trail.localId` reaches the delete path from a model that may have been constructed before an account switch, or retained by a backgrounded widget |
| Cached GPX on disk → delete decision | `toModel()` parses attacker-influenceable GPX; a parse failure previously changed the delete's routing |
