<objective>
Close the four warnings that make otherwise-correct machinery fail in narrow but real windows,
none of which the blocker fixes touched:

- **WR-03** — `TrailFilterNotifier.defaultFilter` is `late` and assigned only on the success path
  and the connection-failure fallback. Any other failure (a 500, a malformed payload,
  `TrailFilterValues.fromJson` throwing) rethrows without assigning it, and `resetFilter()` reads
  it unconditionally — an uncaught `LateInitializationError` out of a button callback, on a
  `keepAlive` provider, so the un-initialised instance survives.
- **WR-04** — the `StateError` thrown for a keyless waypoint sits *inside* `_drainOne`'s `try`,
  so it lands in the generic handler and consumes one of `kMaxSyncAttempts`. That is an invariant
  break, not a network condition: no retry will ever mint a `localKey`. Four passes — which a
  lifecycle or connectivity flurry produces within seconds, since `syncBackoffDelay` only starts
  at 30 s after the *first* failure — park a perfectly good trail as `failed`, after which
  `isDrainDue` returns false forever. The identical reasoning was already applied one screen up
  for the missing `UserEntity` and not here.
- **WR-09** — `writeServerWaypointId` clears that waypoint's `localPhotos` the instant its own
  upload succeeds, before the *trail's* upload as a whole completes. If a later waypoint fails and
  the trail parks as `failed`, the earlier waypoint's photos become unreachable through the model
  while the JPEGs still sit on disk.
- **WR-02** — `_invalidateOwnTrailsList` interpolates a nullable username into the family key, so
  during a token refresh or a mid-logout race the key becomes the literal `'@null'`, matching no
  mounted instance. The doc comment two lines above states that the key must match or the
  invalidation is a silent no-op, which is exactly what the interpolation permits.

Purpose: each of these turns a working flow into a crash, a stuck trail, or a silently missing
refresh under conditions a real hiker hits.
Output: an always-initialised filter default, a drain that distinguishes an invariant break from
a network failure, photos that survive until retirement, and an invalidation that cannot no-op.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server response → `TrailFilterValues.fromJson` | A malformed or hostile payload is the trigger for the unassigned-`late` crash path |
| Persisted `WaypointEntity` rows → drain retry accounting | A corrupt row can consume another row's retry budget |
| `authProvider` mid-refresh state → Riverpod family key | A null handle silently addresses a non-existent provider instance |
