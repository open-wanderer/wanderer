<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| account A → account B (same device) | The new `owner` field is the only thing separating one account's captured trails from another's in a shared ObjectBox store |
| local id → filesystem path | `localId` becomes a directory segment in a later plan; an unvalidated value crosses into `dart:io` |
| device-local model field → outbound multipart body | `Trail.toJson()` feeds `form_data_util.dart`; any unannotated new field is sent to the server |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-01-01 | Information Disclosure | `TrailEntity.owner` | mitigate | Field is nullable with no default; a null owner never matches an owner filter, so a pre-existing downloaded row can never be mistaken for another account's captured trail. Documented in the field's doc comment; enforced by the query plans (36-03). |
| T-36-01-02 | Tampering | `localIdDirSegment` | mitigate | Whitelist regex `^local-\d+-\d+$` with `ArgumentError` on failure, unit-tested against `../escape` and `local-/etc`; it is the only sanctioned way a local id becomes a path segment (mirrors `map_cache_path.dart`, STATE.md `[15-03]`) |
| T-36-01-03 | Information Disclosure | `Trail.localId` / `Trail.syncState` serialization | mitigate | Both fields carry `@JsonKey(includeFromJson: false, includeToJson: false)`, so device-local state never reaches the server via `toFormData`. Verified by an acceptance grep. |
| T-36-01-04 | Tampering | `@Unique(onConflict: replace)` on `TrailEntity.id` / `WaypointEntity.id` | mitigate | Local rows carry a minted, collision-free sentinel id rather than `''`, so a second unsynced capture can never silently replace the first. Guarded by the two-different-localKeys entity test. |
| T-36-01-05 | Denial of Service | ObjectBox schema change | accept | Additive nullable/defaulted properties on a pre-production app; Phase 27 established that field changes need no migration here. Risk is a failed `build_runner` run, caught by the task's own verify. |
</threat_model>
