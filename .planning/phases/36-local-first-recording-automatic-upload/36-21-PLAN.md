<objective>
Close the one open gap from round 2 of `36-UAT.md`: an unsynced trail's **detail screen** shows a
generic "Offline" badge instead of its upload state. `SyncStatusChip` — the four-state indicator
this phase built for D-08 (Pending → Uploading → Failed, synced shows nothing) with SYNC-03's
retry tap-through — was wired into the two list surfaces only
(`trail_list_item.dart:114`, `trail_card.dart:176`). `TrailPanel`, which both
`trail_detail_screen.dart:162` and `library_detail_screen.dart:36` render, still carries a
pre-Phase-36 badge keyed on `trail.isLocal` that hardcodes `l18n.offline`
(`trail_panel.dart:192-227`). So the `/trail/local/:localId` route this phase added — the one
surface a hiker reaches by tapping their own not-yet-uploaded recording — says "Offline" and
offers no retry.

**The two badges do not mean the same thing, and this plan must not conflate them.** `isLocal` is
cache provenance: `TrailEntity.toModel()` hardcodes it `true` for every cached row, downloaded
trails included (see its own doc comment on `trail.dart:114-125`, and WR-11's fix at
`trail_panel.dart:65-71` which had to stop gating the server tabs on it for exactly this reason).
`SyncStatusChip` is keyed on `syncState`. Round 2 UAT test 1 confirmed on device that an ordinary
downloaded trail's surfaces are correct today; D-10 states unsynced and downloaded are mutually
exclusive by construction. A downloaded trail must therefore come out of this plan rendering
byte-identically to how it renders now.

Purpose: SYNC-02 requires upload progress and failure to be visible **on the trail itself**, and
SYNC-03 requires a manual retry. Both hold on the list; neither holds on the screen the hiker lands
on after tapping the trail. REC-03's "visibly distinguishable from a synced trail *and* from a
downloaded one" is the requirement the current badge actively defeats — it renders the same
"Offline" pill for both.
Output: one gated `SyncStatusChip` render in `TrailPanel`, one narrowed guard on the existing
Offline badge, and a widget test that mounts the real `TrailPanel` and fails if either the chip
disappears or the downloaded-trail case regresses.

Scope discipline: UI only. No schema change, no sync-logic change, no new l10n key (all four
strings already exist: `sync_pending`, `sync_uploading`, `sync_failed`, `offline`), no dependency
change.
</objective>
