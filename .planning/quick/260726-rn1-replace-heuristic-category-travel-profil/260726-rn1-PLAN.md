<objective>
Replace the English-substring heuristics in `app/lib/util/valhalla_util.dart`
(`categoryForTravelProfile`, `costingForCategory`, `categoryForBikeBucket`) with an explicit,
operator-configurable mapping between Valhalla costing profiles and Wanderer (sub)categories,
keyed on a new `settings.valhalla_profile` field — mirroring the existing `categories.settings`
JSON field and adding the equivalent field to `subcategories` (which has none today).

The stored value is a **Valhalla-native costing string**, not an internal Dart identifier, and
the vocabulary is deliberately **OPEN — not limited to the 5 route-planner buckets**. Grammar:

```
valhalla_profile := <costing>                  e.g. "auto", "pedestrian", "motor_scooter", "truck"
                  | "bicycle_" <bicycle_type>  e.g. "bicycle_mountain"
```

An operator who adds a "Car" category can set `valhalla_profile: "auto"` and the app will route,
navigate, and download that category with Valhalla's `auto` costing — no code change and no
allowlist edit. Only `bicycle_(road|hybrid|cross|mountain)` is special-cased (→ costing
`bicycle` + `bicycle_type` `Road`/`Hybrid`/`Cross`/`Mountain`); **every other value passes
through verbatim as the costing name**. Values are NOT validated against a hardcoded allowlist
(Valhalla adds costing models over time); only a cheap format guard applies, and a value failing
it is treated as unset so a typo degrades to the fallback chain instead of emitting a malformed
routing request. Critically, parsing must not split on `_` generally — `motor_scooter` is one
costing name and must survive whole.

This is modeled as a small open value type `ValhallaProfile { costing, bicycleType? }`, not a
closed enum. `RouteTravelBucket` keeps a `valhallaProfileKey` getter deriving its own canonical
string from its existing `.costing`/`.costingOptions` so the 5 shipped buckets can't drift from
their actual request payload — but that enum is now only the **route planner's picker
vocabulary**, not the limit of what a category may map to.

Resolution order: subcategory-level setting wins; an unavailable (deleted/hidden) subcategory
falls back to the parent category's setting; that falls back to a code-level `bicycle_hybrid`
default for an otherwise-biking category (bicycle-specific, because Valhalla's 4 bike variants
share one `bicycle` costing and need a sane `bicycle_type`); and finally `pedestrian` when
nothing resolves (per CONTEXT.md's locked decisions).

Also fixes the second diagnosed bug this session: `trail_create_screen.dart`'s `_onEditRoute`
currently derives the Route Planner hand-off profile from `trail.expand?.category?.name` — a
relation that's never populated on an unsaved draft — instead of the form's live category
selection, so re-opening the planner after manually fixing the category still reverts to
pedestrian costing. `_onEditRoute` now reads `_formKey.currentState?.fields['category']?.value`
through `CategoryPicker.resolve`.

Purpose: the old heuristic only substring-matched a category's raw English name
(`bike`/`cycling`/`bicycle` etc.) against untranslated `name`/`short_name`, so any translated or
custom category name silently mismatched — landing bike routes on "Hiking" costing/category and
vice versa. This makes the mapping explicit, data-driven, self-documenting to operators reading
raw PocketBase JSON, and correct across locales/custom categories.

Output:
- Go: `subcategories.settings` JSON field (new migration) + seeded `valhalla_profile` on Hiking
  (category, `"pedestrian"`) and Touring/MTB/Gravel/Road (Biking subcategories,
  `"bicycle_hybrid"`/`"bicycle_mountain"`/`"bicycle_cross"`/`"bicycle_road"`), with retroactive
  "only if empty" backfill for both existing categories and existing subcategories.
- Flutter: a new `ValhallaProfile` open value type + parser; a
  `RouteTravelBucket.valhallaProfileKey` getter and a `bucketForState` that returns `null` for a
  costing matching no bucket; `Category`/`Subcategory.settings` + `.valhallaProfile` typed
  accessor (+ObjectBox cache parity); a new
  `resolveValhallaProfile`/`costingForCategory`/`categorySelectionForBucket` API in
  `valhalla_util.dart` replacing the 3 retired heuristic functions; every call site rewired
  (icon resolution, Route Planner handoff, navigation/download costing, the recording-session
  category pre-fill, and the `_onEditRoute` live-selection fix); docs updated with the open
  grammar and a worked "Car" → `auto` example.
</objective>
