<objective>
Add a persisted "Last used" section to the Flutter app's instance picker. It holds the 2 most recent servers the user successfully SIGNED IN to (custom URL or remote-list entry), most recent first, deduplicated by normalized URL, and recorded on login success only.

Purpose: a custom server URL typed into the picker currently exists only in memory until the app closes. A logged-out user has to retype it every time. After this plan they can reselect it with one tap.

Output: pure recording util and tests, a device-level persistence field and a Riverpod provider, auth success hooks, the picker UI section, and a `last_used` l10n key in all 14 locales.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user input → persisted list | Text typed into the picker reaches the persisted list only after normalizeServerUrl succeeds AND a real login against that server succeeds |
| on-device store → app | recentServersJson is read back from ObjectBox on every build; it could be corrupted or edited on a rooted device |
| wanderer.to servers.json → picker | Remote metadata (name, image path) flows into persisted entries and into a https://wanderer.to/{image} URL (existing behavior) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-ijp-01 | Tampering | decodeRecentServers | mitigate | Per-element try/catch; drop non-Map, fromJson-failing and unnormalizable entries; dedupe; cap at 2; never throws (Task 1 tests cover malformed input) |
| T-ijp-02 | Denial of Service | Auth login paths | mitigate | _recordLastUsedServer wraps everything in try/catch so a persistence or provider failure can never fail a successful sign-in |
| T-ijp-03 | Information Disclosure | LocalSettingsEntity.recentServersJson survives logout | accept | Intended feature. Only public instance metadata (url/name/image) is stored, never usernames, tokens or cookies. The account-scoped purge invariant is about account content, not instance addresses |
| T-ijp-04 | Spoofing | Persisting typo or unreachable hosts | mitigate | Recording happens only after `_updateUserEntity` succeeds inside login/loginWithOAuth, so only servers that actually authenticated the user are remembered |
| T-ijp-05 | Tampering | Concurrent writes to the LocalSettingsEntity singleton row | mitigate | record() re-reads the row fresh before put, matching every existing writer, so no other field (theme, tile proxy identity, style sources) is clobbered |
</threat_model>
