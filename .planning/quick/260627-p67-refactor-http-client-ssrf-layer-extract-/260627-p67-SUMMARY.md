# Phase quick-260627-p67 Plan 01: SSRF HTTP Client Layer Extract Summary

**One-liner:** Extracted safeurl client construction into `util.NewSafeURLClient` + `util.HTTPDoer`, eliminated duplicate `newDiscoveryClient` in federation_admin.go, and upgraded `isPrivateOrReservedIP` to also block CGNAT/TEST-NET/special-purpose ranges via the now-exported `IsSpecialPurposeIP`.

## What Changed

### db/util/safe_fetch.go
- Added `HTTPDoer` interface (satisfied by `*safeurl.WrappedClient` and `*http.Client`)
- Added `NewSafeURLClient(timeout, checkRedirect)` factory — single place where safeurl config is built
- `FetchPublicURL` now calls `NewSafeURLClient(60*time.Second, publicMediaRedirectPolicy)` instead of building inline
- Renamed `isSpecialPurposeIP` to `IsSpecialPurposeIP` (exported); updated the one internal call site in `connectorIPAllowed`

### db/util/network.go
- Added `"net/netip"` import
- Extended `isPrivateOrReservedIP` to convert `net.IP` to `netip.Addr` and call `IsSpecialPurposeIP`, blocking CGNAT (100.64.0.0/10), TEST-NET (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24), benchmarking (198.18.0.0/15), and the other ranges in `specialPurposePrefixes`
- Closes the gap where `SafeHTTPClient`/`safeTransport` could previously reach those addresses

### db/routes/federation_admin.go
- Removed `github.com/doyensec/safeurl` import — routes no longer depend on safeurl directly
- Deleted local `httpDoer` interface declaration
- Deleted `newDiscoveryClient()` function (28 lines)
- `fetchNodeInfo21URL` now accepts `util.HTTPDoer` instead of local `httpDoer`
- `FederationDiscover` calls `util.NewSafeURLClient(10*time.Second, nil)` — same SAFE-06 10s timeout, no redirect policy needed for NodeInfo probing
