<objective>
Fix recording data loss: ending a recording currently clears the durable ObjectBox active-navigation row (`active_nav.clear`) and then holds the converted draft only in memory (`pendingImportedTrail` + go_router `extra`) until the user taps Save in the create form. If the OS kills the backgrounded app in that window, the recording is gone.

After this plan: the draft is written as a local `TrailEntity` row with a new `TrailSyncState.draft` BEFORE the session row is cleared. The upload drain never picks up drafts. Saving the form promotes the same row from draft to pending, and the existing drain uploads it. A "Draft" chip marks these rows.

Purpose: An ended recording must survive process death between Stop and Save.
Output: New enum value, store-layer draft handling, rewired `_saveRecordedTrack`, Draft chip and l10n key, unit tests plus source-level gate tests.

Out of scope (do NOT implement): a detail-screen "continue editing" CTA, an "Upload as is" action, a default name/visibility helper, and Discard deleting the draft row.
</objective>
