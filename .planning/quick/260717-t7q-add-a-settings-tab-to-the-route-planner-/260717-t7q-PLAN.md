<objective>
Add a Settings tab to the Flutter Route Planner sheet that consolidates the web planner's activity + bike-type pickers into ONE 5-option travel-profile picker (Hiking, Biking/Hybrid, Biking/Mountain, Biking/Cross, Biking/Road), relocates the auto-routing toggle into it, and makes profile selection a real routing-behavior change by sending Valhalla `costing_options`. The same 5-option picker also replaces the entry-point sheet's 2-card Hike/Bike chooser.

This requires the locked Rec B architecture refactor: convert `RouteAnchors` from an autoDispose family keyed by `travelProfile` into a single `@Riverpod(keepAlive: true)` provider with `travelProfile` + `costingOptions` living inside state, so a within-`bicycle` sub-type switch (Hybrid to Road) is expressible and no cross-family anchor migration is needed.

Purpose: Give the planner user real control over how routes are computed (road vs mountain vs hiking costing), matching the web client, without exposing manual override sliders.
Output: A 3-tab planner sheet, a working 5-bucket picker in both surfaces, `costing_options` on every Valhalla route call, and a full re-resolve of all segments on any bucket switch.
</objective>
