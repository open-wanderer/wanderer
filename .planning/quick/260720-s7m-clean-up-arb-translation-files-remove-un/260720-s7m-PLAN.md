<objective>
Clean up the Flutter app's ARB translation files (`app/lib/i18n/app_*.arb`, 14 locales) that
were bootstrapped by bulk-copying web's i18n JSON. After this plan:

1. Every ARB key unreferenced in `app/lib/**/*.dart` (verified with a dynamic/indirect-usage
   safety scan FIRST) is removed from all 14 files.
2. All 14 files end up with an **identical** key set; surviving keys missing from stale
   locales are backfilled (reuse web translation where it exists, else English fallback).
3. Hard-coded user-facing string literals in Dart widgets become real l10n keys, added to all
   14 files and wired at their call sites.
4. Every surviving ICU-placeholder/plural key gets a full `@key` metadata block in the
   template (`app_en.arb`) so `gen-l10n` stops warning and Crowdin translators get context.
5. `crowdin.yml` gains a second file entry covering the app ARB files.

Purpose: Stop shipping ~360 dead strings per locale, silence gen-l10n metadata warnings, and
put the app on the same Crowdin pipeline as web so future translation is automatic.
Output: 14 cleaned/equalized ARB files, updated call sites in Dart, extended `crowdin.yml`.

All decisions are LOCKED in CONTEXT.md — do not revisit them. This is a straightforward
mechanical cleanup: prefer script-driven set operations over hand-editing 14 JSON files.
</objective>
