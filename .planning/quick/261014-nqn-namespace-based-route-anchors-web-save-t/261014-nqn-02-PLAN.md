<objective>
Make the Flutter app on branch feature/app read and write the stored-route format that the web adopted in Plan 01 (PR #1377). On the read side, parseGpxSafely splits a single marked trkseg back into the planner's per-leg layout. On the write side, a planner-built route is stored as ONE trkseg per trk, with `<wanderer:anchor>` at each interior leg boundary and `xmlns:wanderer` on the root.

Purpose: a route drawn on either client is stored in one format that every reader understands, and leg boundaries survive a save/reload on both clients. Today the app stores one trkseg per leg, which the web exports as the broken multi-segment form from #1354 (legacy path), and it collapses web-saved drawn routes to a start/end pair when they are re-opened in its planner.

Shared contract (identical to the web): one trkseg per trk. Each interior leg boundary appears ONCE, as a point carrying `<extensions><wanderer:anchor/></extensions>`. The root declares `xmlns:wanderer="https://wanderer.to/xmlns/gpx/1"`. Readers ignore marks on a segment's first or last point. Web readers rebuild legs with the anchor duplicated at the end of leg i and the start of leg i+1. App readers rebuild the app's own layout, where the anchor opens leg i+1 only.
