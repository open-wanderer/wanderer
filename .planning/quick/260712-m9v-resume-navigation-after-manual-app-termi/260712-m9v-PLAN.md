<objective>
Persist the in-progress turn-by-turn navigation session (route progress + trip stats + traveled breadcrumb) to ObjectBox so that when the user manually terminates (swipes away) the Wanderer Flutter app during navigation, relaunching offers a resume dialog that reopens the navigation screen with everything continuing rather than restarting.

Purpose: Today `NavigationState` and `NavigationStats` live only in memory and GoRouter's `extra` does not survive a process restart, so a killed navigation is unrecoverable (`router_provider.dart` already falls back to the trail detail screen).

Output: A new persisted `ActiveNavigationEntity`, a best-effort store helper, resume-seedable navigation providers (progress, stats, AND breadcrumb), persistence writes wired into the navigation screen, and a launch-time detection + resume dialog in `main.dart`.

Why the app-level session can't just "stay alive" instead: when the user manually force-kills the app, the OS tears down the entire Dart/Flutter process — this is true on both Android and iOS and apps cannot opt out of it. `TraceletPositionSource`'s `stopOnTerminate: false` (already configured, untouched by this plan) only keeps the *native* GPS-collection service alive; it does not keep the Riverpod provider tree, widget state, or navigation screen resident. Persisting a snapshot and rehydrating it on relaunch is therefore the only viable mechanism — there is no way to avoid it by "keeping navigation alive in the background."

Forward-compat design constraint: a later app version will add a "record my own track" mode (GPS breadcrumb recording with no predetermined trail/route, uploaded afterwards). This plan does NOT build that mode, but `ActiveNavigationEntity` and `active_navigation_store.dart` are shaped so a future free-recording session can reuse the same single-row table without a migration:
- `sessionType` is an `ActiveSessionType` enum (`nav` | `rec`), persisted via the same `@Transient()` enum + backing `int` getter/setter pattern `TrailEntity` already uses for `TrailDifficulty` (ObjectBox has no native enum column type) — not a raw string.
- `trailId`, `isOffline`, `currentManeuverIndex` are nullable (present only for `sessionType == nav`).
- `breadcrumbPolyline` (the traveled points, encoded via the existing `PolylineUtil`) is a shared/session-agnostic field — it is NOT treated as a disposable rendering nicety in this plan, because for a future `rec` session the breadcrumb **is** the entire recorded output. It is persisted and restored here for the `nav` case too.
- The store helpers (`save`/`read`/`clear`) already operate on "the one active row" generically and take no trailId-shaped parameters.

Scope guardrails (do NOT add): any change to `tracelet_position_source.dart` or platform manifests; auto-resume without a dialog; arrival/auto-exit handling; the free-recording feature itself (only the entity/store schema needs to anticipate it).
</objective>
