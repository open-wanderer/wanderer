## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| web/app client -> PocketBase route | `cursor` and `page` query params are untrusted client input |
| PocketBase -> remote AP server | the server fetches the cursor URL with the signed-in user's HTTP signature |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-s3w-01 | Spoofing / SSRF | FetchCollectionCursor | mitigate | Parse the cursor, require it to be absolute, non-opaque and without userinfo, and require the same scheme, the exact Host (incl. port) and the same EscapedPath as the actor's stored collection URL. Otherwise return ErrInvalidCursor before any request (D-02). Tested with zero-request assertions for host, path, scheme, port, relative, userinfo and escaped-path cursors. |
| T-s3w-02 | Tampering | cursor request target | mitigate | Fetch the validated parsed URL's String(), not the raw input. EscapedPath comparison blocks %2F path smuggling on the same host. |
| T-s3w-03 | Elevation of privilege | route fallback | mitigate | An invalid cursor returns 400 in both routes with no fallback to the walk or to collectionLink (D-02). collectionLink stays reserved for server-provided links. |
| T-s3w-04 | Denial of service | remote host / per-host rate limiter | mitigate | One remote request per cursor page instead of k(k+3)/2 in total. The rate limiter is unchanged (D-07) and still counts every dial. |
| T-s3w-05 | Information disclosure | `next` in responses | accept | `next` is the remote collection's own public paging URL, resolved via collectionLink. It is already visible to anyone fetching that collection. |
</threat_model>
