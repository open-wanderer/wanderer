# Quick Task 260711-d37: Shrink Navigation-Screen Location Puck Summary

**Custom ~22px heading-aware Flutter marker (`_LocationMarkerLayer`/`_HeadingPuck`) replaces the native MapLibre location puck on the navigation screen; camera-follow, recenter, and heading-up toggle now drive off manual `animateCamera` instead of native `trackLocation`.**

## Accomplishments
- Native MapLibre location puck (`enableLocation`/`trackLocation`) fully removed from `navigation_screen.dart` — no supported size control existed for it on either platform.
- New `_LocationMarkerLayer` (22px `ml.WidgetLayer`/`ml.Marker`) + `_HeadingPuck` (14px blue dot, mirroring `trail_map.dart`'s styling) with a subordinate heading wedge that rotates via `Transform.rotate`.
- Camera-follow, pan-breaks-follow, recenter, and the heading-up compass toggle all now drive the camera manually via `controller.animateCamera`, sourced from the screen's existing position stream.

## Files Created/Modified
- `app/lib/routes/navigation_screen.dart` - Added `_currentPosition` ValueNotifier, `_LocationMarkerLayer`/`_HeadingPuck`/`_HeadingWedgePainter` widgets; removed native `enableLocation`/`trackLocation` calls; `_onPanStart`, `_onRecenter`, and the `MapCompass.onPressed` handler now drive the camera via `animateCamera` off the last known GPS fix.

## Decisions Made
- Kept the wedge and bearing logic conservative: any negative `heading`/`headingAccuracy` (geolocator's "not trustworthy" signal) suppresses both the wedge render and any bearing argument passed to `animateCamera`, so a stationary device never shows a stale or jittery heading indicator.
- Reused the exact blue-dot styling (`Colors.blue` fill, 3px white border, subtle shadow) from `trail_map.dart._buildLocationLayer` for visual consistency across the app's location markers, at a smaller (14px vs 18px) footprint appropriate for turn-by-turn use.
