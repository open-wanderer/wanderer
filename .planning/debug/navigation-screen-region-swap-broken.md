## Resolution

root_cause: "_reconcileRegionComposition() (app/lib/routes/navigation_screen.dart:1076-1218) has no reentrancy guard (WR-03, confirmed unfixed) and is triggered by ml.MapEventCameraIdle, which — contrary to the D-04 assumption it was built on ('fires exactly once per settled gesture') — also fires for every one of navigation_screen's own continuous programmatic controller.moveCamera() calls (_pushCamera, invoked from the 200ms per-fix position tween at ~60fps and from the heading-up bearing-follow ticker every frame, whenever _followEnabled is true, the default during active navigation). This means _reconcileRegionComposition is invoked far more often, and with much higher overlap probability, than the design assumed — during ordinary GPS-driven navigation, not only user pans. Overlapping invocations mutate the shared _addedSourceIds/_addedLayerIds tracking sets with asymmetric error handling (the removal loop advances tracking state unconditionally even on failure; the add loop only advances tracking state on success) and operate against a StyleController reference captured per-call, so interleaved async native calls (addSource/addLayer/removeSource/removeLayer, plus a concurrent full setStyle() from _swapStyle wiping and re-adding all layers including trail/breadcrumb) desync the Dart-side tracking sets from the real native map style. This produces two failure modes depending on exact timing: (1) a needed region source/layer silently fails to (re)apply and is never retried because tracking now falsely claims it's present — 'map does not load at all'; (2) a concurrent setStyle wipes and is racing its own re-add of the trail/breadcrumb layers against a stale in-flight reconcile — 'trail layer disappears'. Region source/layer id collision with the trail/breadcrumb layers was investigated and definitively ruled out."
