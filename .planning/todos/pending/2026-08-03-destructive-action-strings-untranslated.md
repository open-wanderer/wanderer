## Problem

`app/lib/i18n/untranslated_messages.json` lists strings that are English-only in 13 of the
app's 14 supported locales. Two of these are the copy shown on irreversible actions — a
non-English hiker sees English text on the one dialog that destroys data.

This is deliberately **not fixed** by this plan (36-19). `36-REVIEW.md` §WR-06 raised it, and
the reasoning stands: closing this gap needs real human translation into 13 languages, and no
autonomous agent can supply correct destructive-action copy in 13 languages. Machine
translation is explicitly out of scope — a machine translation that reads slightly wrong on an
irreversible action ("this cannot be undone") is worse than English a hiker can recognise as
untranslated, because English is at least honestly foreign rather than confidently wrong. The
app's existing fallback-to-English behaviour for a missing key means shipping is not blocked by
leaving this untranslated; it is blocked only from being silently forgotten, which is what this
todo prevents.

Note: the correctness half of the original WR-06 finding is already resolved (`b9ee66ca`) —
`_confirmDelete` now keys its dialog text on `trailHasServerId(trail.id)`, so a trail with a
server id no longer claims its deletion is device-only and irreversible. What remains is
coverage only: the (now-correct) English copy has no translation in 13 locales.

## Locales affected

cs, de, es, eu, fr, hu, it, nl, no, pl, pt, ru, zh (all supported locales except en).

`de` already carries translations for the `trail_source_*`/`library_empty_*` group below from
an earlier batch; it is missing the same 15 keys every other locale is missing. All 12 other
locales are missing all 22 keys.

## Fix

Ship real human translations for `signout_unsynced_warning` and
`delete_unsynced_trail_confirm` to every locale before release, then work down the priority
list. `app/lib/i18n/untranslated_messages.json` is the live, committed work list — it is
regenerated by `flutter gen-l10n` and shows up in a diff when it grows, which is exactly how
this backlog was caught growing unnoticed in the first place. Do not hand-edit it; run
`flutter gen-l10n` after adding real translations to the locale ARBs and let it shrink on its
own.
