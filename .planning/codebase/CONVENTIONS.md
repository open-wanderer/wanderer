# Coding Conventions

**Analysis Date:** 2026-09-06

## Naming Patterns

### Files

**TypeScript/JavaScript/Svelte:**
- Utility files: `snake_case` suffixed with purpose
  - Examples: `array_util.ts`, `date_util.ts`, `api_util.ts`, `authorization_util.ts`, `format_util.ts`
  - Location: `web/src/lib/util/`
- Store files: `snake_case` with `_store` suffix
  - Examples: `user_store.ts`, `theme_store.ts`, `search_store.ts`, `plugin_store.ts`, `trail_store.ts`
  - Location: `web/src/lib/stores/`
- Model/type files: `snake_case`
  - Examples: `settings.ts`, `trail.ts`, `tag.ts`, `base_schema.ts`
  - Location: `web/src/lib/models/`
- Route components: SvelteKit conventions (`+page.svelte`, `+layout.svelte`, `+server.ts`, `+error.svelte`)
  - Location: `web/src/routes/`
- Svelte components: `PascalCase`
  - Examples: `TrailCard.svelte`, `FeedCard.svelte`, `Scene.svelte`, `Toast.svelte`
  - Location: `web/src/lib/components/`

**Go:**
- Files: `snake_case` matching package and purpose
  - Examples: `auth_token.go`, `plugin_system.go`, `plugin_system_test.go`
  - Test files: `*_test.go` suffix
  - Location: `db/routes/`, `db/services/`, `db/util/`

**Dart/Flutter:**
- Files: `snake_case`
  - Examples: `format_test.dart`, `auth_provider.dart`, `local_trail_store.dart`
  - Test files: `*_test.dart` suffix
  - Location: `app/lib/`, `app/test/`
- Generated files: `*.g.dart` suffix (auto-generated by build_runner)
  - Examples: `auth_provider.g.dart`, `glyph_sprite_cache_provider.g.dart`

### Functions

**TypeScript/JavaScript:**
- camelCase for all function names
  - Prefix naming convention for store functions: `{entity}_{operation}`
    - Examples: `users_create()`, `users_update()`, `users_auth_methods()`, `users_delete()`
  - Utility functions: verb-first naming
    - Examples: `range()`, `isToday()`, `dateExistsInList()`, `isSameDay()`, `isRouteProtected()`
  - Handler functions in routes: HTTP method names
    - Examples: `GET()`, `PUT()`, `POST()`, `DELETE()`, `PATCH()`
    - Location: `web/src/routes/api/v1/*/+server.ts`

**Go:**
- PascalCase for exported functions (public API)
  - Examples: `AuthToken()`, `NormalizeCategoryName()`, `ParseCategoryTranslations()`
- camelCase for unexported (private) functions
  - Examples: `preparePluginInfoResponse()`, `pluginIssueRecordID()`

**Dart/Flutter:**
- camelCase for functions and methods
  - Async functions return `Future<T>` or `FutureOr<T>`
  - Riverpod async providers use `@Riverpod()` annotation
    - Examples: `build()`, `auth()` (in `Auth` class), `onlineStatus()` (in `OnlineStatus` class)

### Variables

**TypeScript/JavaScript:**
- camelCase for all variable names
  - Boolean variables: prefix with `is`
    - Examples: `isToday`, `isRouteProtected`, `isValid`, `hideDemoHint`
  - Constants (module-level): UPPERCASE (implicitly)
    - Examples: `const privateRoutes = [...]`, `const publicRoutes = [...]`, `const defaultPocketBaseEncryptionKey = "..."`
  - Readonly arrays: explicitly typed as `ReadonlyArray<T>`
    - Example: `export function range(to: number, from: number = 0): ReadonlyArray<number>`

**Go:**
- camelCase for local variables and function parameters
- PascalCase for struct field names (exported) and struct names
  - Examples: `type LocalPluginIssue struct { ID, Dir string; SetupErrorCode string }`

**Dart/Flutter:**
- camelCase for local variables, parameters, and fields
- Underscore prefix for private class members (Dart convention)
  - Examples: `_box`, `_yMMMMdCache`, `_oauthCallbackScheme`
- CONSTANT_CASE for constants marked with `const`

### Types/Interfaces

**TypeScript:**
- PascalCase for all types and interfaces
  - Examples: `User`, `Trail`, `Comment`, `Tag`, `TrailTag`, `Settings`, `APIError`
  - Location: `web/src/lib/models/`
- Zod schemas: PascalCase suffixed with `Schema`
  - Examples: `TrailCreateSchema`, `RecordListOptionsSchema`, `RecordIdSchema`
  - Location: `web/src/lib/models/api/`

**Go:**
- PascalCase for struct names (exported)
  - Examples: `PluginInfo`, `LocalPluginIssue`, `CategoryTranslation`

**Dart/Flutter:**
- PascalCase for classes, models, and generated types
  - Freezed immutable classes use `@freezed` annotation
    - Examples: `Trail`, `User`, `Comment`
  - Entity classes with ObjectBox: `@Entity` annotation
    - Examples: `UserEntity`, `TrailEntity`, `ActiveNavigationEntity`

### Enums

**TypeScript:**
- Enum values: lowercase snake_case
  - Examples: `Collection.users`, `Language.en`, `status: 'available'`
  - Location: `web/src/lib/models/`, `web/src/lib/util/api_util.ts`

**Go:**
- Enum (const) values: camelCase or snake_case (following package convention)
  - Examples: `SetupErrorCodeManifestInvalid`, `SetupErrorCodeRuntimeEntrypointMissing`

**Dart/Flutter:**
- Enum values: camelCase
  - Examples: `unit: 'metric'`, `unit: 'imperial'`

## Error Handling

### TypeScript/SvelteKit

**Pattern: Class-based errors with status codes**
- Use `APIError` class for API errors
  - Location: `web/src/lib/util/api_util.ts`
  - Fields: `status: number`, `message: string`, `detail: any`
  - Used by: Store functions and API routes

**Example from `web/src/lib/stores/plugin_store.ts`:**
```typescript
export class APIError extends Error {
    status: number;
    message: string;
    detail: any;

    constructor(status: number, message: string, detail?: any) {
        super();
        this.status = status;
        this.message = message;
        this.detail = detail
    }
}

export async function plugins_index(
    f: (url: RequestInfo | URL, config?: RequestInit) => Promise<Response> = fetch,
) {
    const r = await f("/api/v1/plugin-system/plugins", { method: "GET" });

    if (!r.ok) {
        const response = await r.json();
        throw new APIError(r.status, response.message, response.detail);
    }
    // ...
}
```

**Route handlers: Try/catch with handleError()**
- Location: `web/src/routes/api/v1/*/+server.ts`
- Wraps requests in try/catch
- Calls `handleError(e)` for uniform error responses

**Example from `web/src/routes/api/v1/trail/+server.ts`:**
```typescript
export async function GET(event: RequestEvent) {
    try {
        const searchParams = Object.fromEntries(event.url.searchParams);
        const safeSearchParams = RecordListOptionsSchema.parse(searchParams);
        // ... processing ...
        return json(r)
    } catch (e: any) {
        return handleError(e);
    }
}
```

**Store functions: Error returns, not throws**
- Catch errors and return defaults (empty arrays, null, etc.)
- Log errors to console but don't propagate exceptions
- Allows UI to gracefully degrade

### Go

**Pattern: Error return as second value**
- Go idiomatic: functions return `(result, error)` tuple
- Always check error before using result

**Example from `db/routes/auth_token.go`:**

- Use PocketBase's error constructors: `apis.NewBadRequestError()`, `apis.NewNotFoundError()`
- Suppress fields from error messages for sensitive data

## Function Design

### TypeScript

**Typed parameters (strict mode required)**
- All parameters must have explicit types
- Generics common in utility functions
  - Examples: `list<T>()`, `create<T>()`, `show<T>()`
  - Location: `web/src/lib/util/api_util.ts`

**Explicit return type annotations**
- All functions declare return type
- Examples: `Promise<Trail>`, `ReadonlyArray<number>`, `ListResult<T>`

**Function overloads: Rare**
- Prefer union types and runtime checks

**Example from `web/src/lib/util/api_util.ts`:**
```typescript
export async function list<T>(event: RequestEvent, collection: Collection): Promise<ListResult<T>> {
    const searchParams = Object.fromEntries(event.url.searchParams);
    const safeSearchParams = RecordListOptionsSchema.parse(searchParams);
    const { perPage, page, ...opts } = safeSearchParams;
    
    let r: ListResult<T>;
    if ((safeSearchParams.perPage ?? 0) < 0) {
        const activities: T[] = await event.locals.pb.collection(Collection[collection])
            .getFullList<T>({...opts})
        r = { items: activities, perPage: -1, page: 1, totalItems: activities.length, totalPages: 1 }
    } else {
        r = await event.locals.pb.collection(Collection[collection])
            .getList<T>(page, perPage, opts)
    }
    return r
}
```

  if (meters == null) {
    return "-";
  }
  
  if (unit == "metric") {
    if (meters >= 1000) {
      return "${(meters / 1000).toStringAsFixed(2)} km";
    } else {

## Store Patterns (Svelte)

**Store creation:**
- Use `writable<T>()` for mutable stores
- Type-annotated on creation: `export const currentUser: Writable<User | null> = writable<User | null>()`
- Some stores initialized with default values: `export const theme: Writable<Theme> = writable(getDefaultTheme())`

**Store updates:**
- Use `.set()` to replace entire value
- Use `.update()` for mutation-based updates

**Store reads:**
- Use `get()` function to extract value: `const currentTheme = get(theme)`
- In components: use `$store` syntax for reactive subscriptions

**Derived stores:**
- Use `derived()` for computed/derived state
- Automatically subscribe to source stores

**Example from `web/src/lib/stores/plugin_store.ts`:**
```typescript
export const pluginProviders: Writable<PluginProvider[]> = writable([]);

export const hasSendCapablePlugin: Readable<boolean> = derived(
    [pluginProviders, pluginInstances],
    ([$plugins, $instances]) => {
        const enabledProviders = new Set(
            $instances.filter((a) => a.enabled).map((a) => a.plugin_id),
        );
        return $plugins.some(
            (p) =>
                p.status === "available" &&
                (p.capabilities ?? []).includes("prepare_trail_send.v1") &&
                enabledProviders.has(p.id),
        );
    },
);
```

**Stores typically co-located with operations:**
- `user_store.ts` contains `currentUser` store and user operations
- `trail_store.ts` contains trail data store and fetch functions

## API Conventions

### TypeScript/SvelteKit Routes

**Location:** `web/src/routes/api/v1/*/+server.ts`
